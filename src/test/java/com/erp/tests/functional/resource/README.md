# Functional Tests: Resource (Ресурси)

## Огляд
Цей набір тестів забезпечує повне покриття життєвого циклу та верифікацію цілісності даних для модуля **Resource** у розділі Master Data. 
Основна мета — гарантувати стабільність словника ресурсів, що є фундаментом для виробництва та обліку запасів.

---

## Тестові сценарії

| ID | Назва сценарію | Опис перевірки | Severity |
|:---|:---|:---|:---|
| **TC-RES-001** | Happy Path: Створення | Успішне створення ADMIN-користувачем, валідація JSON-схеми та перевірка персистентності в БД. | **Critical** |
| **TC-RES-002** | Оновлення назви | PUT `/resources/{id}` змінює name → 200; нова назва в response і GET by id. | **Critical** |
| **TC-RES-003** | Контроль унікальності | Заборона створення дублікатів (Name) та перевірка атомарності операцій. | **Critical** |
| **TC-RES-004** | Trim при створенні | POST з leading/trailing whitespace → збережена trim()'нута назва. | **Critical** |
| **TC-RES-005** | Trim при оновленні | PUT з whitespace у name → trim у response і GET by id. | **Critical** |
| **TC-RES-006** | Валідація name | Data-driven: null/empty/blank і довжина > 256 → 400; словник без змін. | **Normal** |

Деактивація / unarchive / guards — у `ResourceDeactivationTest` (**TC-RES-010…016**). Не плутати з TC-RES-001 (створення).

---

## Деталізація функціоналу

### 1. Позитивний сценарій (Happy Path)
* **Contract Validation:** Використання JSON Schema для перевірки відповідності типів даних та обов'язкових атрибутів.
* **Database Sync:** Перевірка того, що об'єкт реально доступний через `GET` запит, а його поля ідентичні даним із `Request`.

### 2. Оновлення назви
* **PUT name:** Адмін змінює назву існуючого ресурсу; нова назва персиститься і видима через GET by id.

### 3. Валідація вхідних даних (Data Quality)
* **Mandatory name:** Система відхиляє запити з null / empty / blank `name`.
* **Boundary Testing:** Обмеження довжини після trim — більше 256 символів → 400.
* **Integrity Check:** При помилці `400` кількість записів у словнику не змінюється.

### 4. Бізнес-правила та цілісність (Business Rules)
* **Uniqueness:** Перевірка унікальних індексів для полів `name`.
* **Integrity Check:** Унікальна перевірка «незмінності бази» для дублікатів і валідації.

## Технічні особливості
* **Паралелізація:** Використання `DataUtils.getUniqueSuffix()` (Timestamp + Thread ID) для повної ізоляції тестів.
* **Звітність:** Allure-кроки розбиті на фази Arrange / Act / Assert.
* **Докази:** До звітів автоматично прикріплюються фактичні JSON-відповіді та очікувані схеми контракту.
