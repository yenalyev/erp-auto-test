# Підказки редагування техкарт за правом global plan update

Фіча обмежує повідомлення про вплив редагування техкарти на глобальні плани користувачами з дозволом `global-plan::update`. Дозвіл є визначальним; назва ролі «адміністратор» сама по собі не є умовою показу.

У каталозі доступів канонічний grant `global-plan.manage` розгортається у дозволи create/update/delete. Саме його надання та відкликання використовує сценарій із non-admin; окремий grant `global-plan.update` у каталозі відсутній.

## Поведінка

Техкарта, використана в розподілі поточного або майбутнього глобального плану, може мати нову версію після зміни ресурсів, норм або альтернативних груп. Збережений розподіл продовжує посилатися на попередню версію, доки користувач не призначить ресурс знову та не перегенерує плани локацій.

Підказка у формі редагування та модалка підтвердження доступні лише з `global-plan::update`. Користувач без цього дозволу, який має окреме право редагувати техкарту, зберігає зміни без цієї модалки. Скасування модалки не створює нової версії.

Коли чинний розподіл став недійсним, у «Виробничі плани» для користувача з дозволом показується помаранчевий warning-бейдж `!` замість цифр. На сторінці «Глобальні плани» він бачить жовту підказку з трьох частин:

1. Заголовок: «Розподіл у глобальних планах ${liveGlobalPlans.map(planLabel).join(', ')} став недійсним для техкарт:».
2. Маркований список назв змінених техкарт. Довгий список можна розгорнути кнопкою «+N ще» та згорнути кнопкою «Згорнути».
3. Окрема інструкція: «Відкрийте кожен план, призначте ресурс знову й повторно згенеруйте плани на локації.»

Шаблонні вставки замінюються реальними значеннями. У цій підказці `planLabel` — опис плану; для порожнього опису використовується місяць/рік. Місяць/рік у дужках до непорожнього опису не додаються. Назви планів є посиланнями й розділені комами. Перелік карт містить змінені техкарти; незмінені карти та плани не додаються. Тести перевіряють заголовок, посилання, маркований список та точний текст окремої інструкції.

15 жовтня 2026 року користувач погодив приведення вимог до фактичної реалізації: помаранчевий індикатор, описи планів без додаткового періоду та підказку зі списком. Попередній звіт зберігає результати перевірки первісної редакції вимог.

## Критерії приймання

- **AC-01.** Жовту підказку та модалку структурного редагування техкарти з актуальним глобальним планом бачить лише користувач із global-plan::update. Назва ролі не замінює перевірку дозволу.
- **AC-02.** Після зміни техкарти, що робить чинний розподіл недійсним, користувач із global-plan::update бачить помаранчевий warning-бейдж ! замість числового лічильника у «Виробничі плани». Користувач без дозволу цього бейджа не бачить.
- **AC-03.** На сторінці «Глобальні плани» користувач із global-plan::update бачить жовту підказку: заголовок «Розподіл у глобальних планах … став недійсним для техкарт:» із посиланнями-описами планів без доданого періоду, маркований список змінених техкарт та окрему точну інструкцію повторного призначення й генерації.
- **AC-04.** Перейменування та редагування невикористаної техкарти не роблять розподіл недійсним. Повторне призначення нової версії та generate прибирають повідомлення лише для виправленого плану.

## Межі перевірки

Зміна лише назви не створює нову версію та не робить розподіл недійсним. Карта без live snapshot не потребує попередження про вплив на глобальні плани. Виправлення одного плану не прибирає повідомлення про інший невиправлений план. Чужі плани та ресурси не змінюються.

Автоматизація використовує справжні сесії ADMIN, OWNER_1 та окремого non-admin із прямим дозволом global-plan update. Права перевіряються через /users/me. Для окремого користувача перевіряється також відкликання update та новий вхід. Автоматичне оновлення прав без нового входу, суто історичні плани та великий перелік карт не входять до десяти нових сценаріїв. Історичні snapshots мають окрему регресію GlobalPlanHistoricalTechMapUiTest. Ці межі не означають перевірку всіх комбінацій прав.

## Запуск

```powershell
$env:PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD='1'
mvn -o test '-Denv=dev' '-Dsuite=global-plan-tech-map-hints' '-Dframework.browser.channel=chrome' '-Dtcm.enabled=false' '-Dgoogle.sheets.enabled=false'
```

Клас також входить у `global-plans`, `ui` і `regression`. Сценарії створюють ізольовані ресурси, техкарти й плани у вільних майбутніх місяцях. Cleanup видаляє лише власні GP і location plans, архівує активні версії власних карт та ресурси, відновлює початковий режим техкарт локації.

Команда використовує встановлений Chrome і вимикає зовнішню публікацію результатів під час прогону. Пакет для TCM dev і prod міститься в `docs/audits/2026-10-15/global-plan-tech-map-hints-tcm-payload.json`: фіча `REQ-GP-HINT` під `REQ-GLOBAL-PLAN`, чотири критерії та десять автоматизованих UI-кейсів. Опубліковані результати описують перевірку ERP dev; вони не є прогоном ERP production.
