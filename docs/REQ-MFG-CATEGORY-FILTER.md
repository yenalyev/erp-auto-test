# Техкарти — фільтр «Категорія виробу»

Дата: 21.10.2026. TCM: `REQ-MFG-001-03`, `AC-05`, `AC-06`.

## Вимоги

Поточний підпис елемента — «Категорії продукту». Фільтр використовує категорію вихідного виробу техкарти, а не категорію сировини. Без вибору категорій список не обмежується за категорією. Кілька категорій дають об’єднання результатів без повторення техкарти з кількома виходами; пошук за назвою карти, продуктом і сировиною додає умови AND. Категорія та пошук продукту повинні збігатися на одному вихідному ресурсі.

Вибір батьківської категорії позначає все піддерево. UI передає явний набір categoryIds; API не розгортає батька самостійно. Дочірню категорію можна зняти окремо. «Скинути вибір» очищує лише категорії та залишає текстові фільтри. За відсутності результатів показується «Немає даних».

Вибір зберігається у URL (category), переживає reload та повернення з історії версій. Зміна категорії скидає номер сторінки. Пагінація та статистика тегів враховують категорії; обмеження типу, архівності та доступного робочого простору продовжують діяти.

## Тестові дані та ізоляція

`TechMapCategoryFilterFixture` створює власні категорії parent → A, B та empty; чотири активні карти виготовлення (a, b, parent, multi), архівну карту та карту розбирання. Карта b має вхід категорії A і вихід B; multi має виходи A+B. Унікальний префікс обмежує список власними картами. Передумови не залежать від наповнення чужих техкарт.

Після класу власні карти й ресурси архівуються, ресурси переводяться до наявної категорії, створені категорії видаляються від дітей до батьків. Початковий режим редагування локації відновлюється; помилка cleanup робить прогін невдалим. БД не потрібна.

## Автоматизовані кейси

### TC-TM-CAT-API-001 — Одна категорія відбирає вихідні вироби для ADMIN та OWNER

- Критерій: AC-05.
- Дія: Вибрати A, потім B через categoryIds.
- Очікування: Для A лише a та multi, для B лише b та multi; сировина категорії A не включає b.

### TC-TM-CAT-API-002 — Кілька категорій дають об’єднання без дублів

- Критерій: AC-05.
- Дія: Передати categoryIds=A,B.
- Очікування: Рівно a,b,multi; multi один раз.

### TC-TM-CAT-API-003 — Явне піддерево категорій включає батька й нащадків

- Критерій: AC-06.
- Дія: Порівняти categoryIds=parent та categoryIds=parent,A.
- Очікування: Лише parentMap у першому запиті; parentMap,a,multi у другому.

### TC-TM-CAT-API-004 — Категорія та текстові фільтри перетинаються за тим самим виходом

- Критерій: AC-05.
- Дія: Поєднати A, назву продукту A та сировину; змінити продукт на B.
- Очікування: a,multi; після зміни продукту порожньо, навіть для multi.

### TC-TM-CAT-API-005 — Порожній результат, очищення та ізоляція типу й архіву

- Критерій: AC-05.
- Дія: Вибрати порожню категорію, очистити; окремо змінити isActive/type для A.
- Очікування: Порожній список; після очищення чотири активні PRODUCTION; архівний та DISASSEMBLE запити повертають відповідні контрольні карти.

### TC-TM-CAT-API-006 — Пагінація рахує лише відфільтровані техкарти

- Критерій: AC-05.
- Дія: Для категорії B запитати дві сторінки size=1.
- Очікування: totalElements=2,totalPages=2; b та multi рівно по одному разу.

### TC-TM-CAT-API-007 — Статистика тегів враховує категорію виробу

- Критерій: AC-05.
- Дія: Запитати tag-statistics з категорією A та спільним префіксом карт.
- Очікування: Лише теги a,multi з count=1; тег b відсутній.

### TC-TM-CAT-UI-001 — Фільтр категорії виробу доступний ADMIN та OWNER

- Критерій: AC-05.
- Дія: Відкрити список; перевірити початковий стан; вибрати A.
- Очікування: Початково всі чотири активні PRODUCTION; після вибору лише a,multi; category=A у URL.

### TC-TM-CAT-UI-002 — Мультивибір, зняття категорії та очищення

- Критерій: AC-06.
- Дія: Вибрати A+B; зняти A; натиснути Скинути вибір.
- Очікування: a,b,multi; потім b,multi; після очищення всі чотири карти, category відсутня в URL.

### TC-TM-CAT-UI-003 — Вибір батьківської категорії та зняття нащадка

- Критерій: AC-06.
- Дія: Вибрати parent; зняти дочірню A.
- Очікування: parentMap,a,multi та URL з parent,A; після зняття A лише parentMap.

### TC-TM-CAT-UI-004 — Поєднання пошуку з категорією та порожній стан

- Критерій: AC-06.
- Дія: Ввести продукт B і сировину; вибрати A; очистити категорії.
- Очікування: Немає даних для несумісного виходу; після очищення b,multi, текстові фільтри збережено.

### TC-TM-CAT-UI-005 — Вибір зберігається після reload і повернення, сторінка скидається

- Критерій: AC-06.
- Дія: Вибрати A; reload; відкрити історію версій і повернутися; перейти на page=1 та додати B.
- Очікування: A та a,multi відновлюються; зміна вибору прибирає page з URL і показує a,b,multi.

## Перевірка 21.10.2026 та відомий дефект

На ERP dev: **13 PASS, 1 FAIL** із 14 виконань. Усі шість UI-виконань пройшли після уточнення локатора автотесту: назва шукається всередині конкретного рядка карти. Framework — **100 PASS**, помилок setup/cleanup немає. [Звіт і скріншоти](audits/2026-10-21/tech-map-category-dev-report.md).

Відомий дефект — **статистика тегів у техкартах не враховує фільтр «Категорія виробу»**. Запит `GET /api/v1/technological-maps/tag-statistics` отримує `categoryIds`, але повертає також тег карти, вихід якої належить іншій категорії. Сам список техкарт на dev відфільтрований правильно. Регресійний тест `TC-TM-CAT-API-007` залишається FAIL до виправлення продукту; очікування не послаблено.

Відтворення: на одній локації створити активні карти A (вихід категорії A, тег `#категоріяА`), B (вихід категорії B, тег `#категоріяБ`) і AB (виходи A+B, тег `#спільний`). У списку виробничих техкарт вибрати категорію A та перевірити статистику тегів.

Очікування: лише `#категоріяА` й `#спільний`, кожен із кількістю 1; `#категоріяБ` відсутній. Фактично API повертає всі три теги. Список містить лише карти A та AB.

На ERP staging цього ж дня основний прогін мав **14 FAIL**: UI-фільтр відсутній, список API ігнорує `categoryIds`; тестовий OWNER додатково отримує 403. Окремий повтор статистики від ADMIN також відтворив зайвий тег. Це стан перевіреної версії стейджу, а не результат тестування ERP production. [Звіт стейджу](audits/2026-10-21/tech-map-category-staging-report.md).

Зміни документації в dev і production TCM не є запуском тестів на ERP production. Результати прогонів зберігаються окремо від вимог.
