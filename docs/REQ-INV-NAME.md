# Інвентаризація — фільтр по назві ресурсу

Вимоги та автоматизовані сценарії, 21.10.2026. TCM: `REQ-WMS-003` → `REQ-INV-NAME`.

## Поведінка

На сторінці **Інвентаризація → Закриті** (`/inventory-processes`) є поле **Назва ресурсу**.
Пошук працює за повною назвою або її частиною без урахування регістру, зокрема для українських назв.
UI обрізає пробіли на початку та в кінці й застосовує значення після debounce 500 мс.
Порожній або пробільний UI-пошук прибирає фільтр.

Таблиця показує лише інвентаризації з відповідними ресурсами. У колонці **Розбіжності**
залишаються тільки ресурси, назви яких відповідають пошуку: якщо одне проведення містить
«Акумулятор А», «Акумулятор Б» і «Кабель», пошук «АКУМУЛЯТОР» показує лише перші два.
Процес із самим кабелем, відхилення й ручне закриття без розбіжностей у цьому результаті відсутні.
Після очищення відновлюються повні розбіжності та процеси без них. Пошук не змінює історію або залишки.

**Експорт в Excel** використовує поточний фільтр: у книзі **Інвентаризації** є тільки відповідні
процеси й ресурси. Зміна пошуку створює нову вибірку. Для відсутніх збігів завантажується
валідний XLSX лише із заголовками. Після очищення книга знову містить усі рядки вибраної локації.
Дробові додатні й від’ємні розбіжності зберігаються числами.

API таблиці: `GET /api/v1/storages/inventory/processes`.
API Excel: `GET /api/v1/storages/inventory/processes/export`.
Параметр `resourceName`; також `parentStorageId`, `states`, `requestedBy`, `categoryIds`, `fromDate`, `toDate`.
Фільтри працюють як AND. `page.totalElements` рахує процеси, а не ресурси всередині `diff`.
Вкладка «Закриті» використовує `states=CLOSED,REJECTED`.

Це покриття історії інвентаризацій. Фільтр залишків `/inventory` та локальний пошук форми
`/inventory/:id` мають окремі наявні регресії.

## Критерії приймання

- **AC-01:** На вкладці «Закриті» доступне поле «Назва ресурсу»; повна назва або підрядок, Unicode, різний регістр та пробіли навколо UI-запиту обробляються коректно.
- **AC-02:** Таблиця та вкладені розбіжності містять тільки відповідні процеси й ресурси; без збігів результат порожній, очищення відновлює повні дані; інші фільтри перетинаються, пагінація рахує процеси, історія та залишки незмінні.
- **AC-03:** Excel враховує поточний пошук, зміну й очищення фільтра; містить точні process/resource/delta без зайвих ресурсів, числові дробові розбіжності та валідну порожню книгу без збігів.

## Передумови й дані

ADMIN на ERP dev. Кожен клас створює власну локацію та три унікальні ресурси:
Акумулятор А, Акумулятор Б і Кабель, по 10 одиниць через справжні надходження.
Далі реальний lifecycle request → approve → conduct створює:

- mixed: А +2.25, Б −3.5, Кабель +4;
- cableOnly: Кабель +1;
- manual: ручне закриття без проведення;
- rejected: відхилений запит без проведення.

Після кожного тесту звіряються всі незмінені записи історії та точні залишки 12.25/6.5/15.
Cleanup прибирає власні залишки, архівує три ресурси й локацію. Історичні процеси зберігаються
як аудит архівованої тестової локації. Наявні користувачі, їхні права та робочі залишки не редагуються.

## Тест-кейси

### TC-INV-NAME-API-001 — Повна й часткова назва, Unicode та регістр [AC-01]
Автотест: `InventoryNameFilterApiTest#fullPartialAndCaseInsensitiveNamesFilterNestedDifferences`.
1. Передати повну назву А, потім її варіант у верхньому регістрі.
2. Передати підрядок «АКУМУЛЯТОР».
Очікування: перші запити повертають тільки mixed із diff А:+2.25; підрядок — тільки mixed із А:+2.25 і Б:-3.5. Кабелю й інших процесів немає, назви ресурсів точні.

### TC-INV-NAME-API-002 — Немає збігів та очищення [AC-02]
Автотест: `InventoryNameFilterApiTest#noMatchAndResetRestoreAllClosedAndRejectedProcesses`.
1. Задати унікальну назву без збігів.
2. Повторити запит без resourceName.
Очікування: content порожній, totalElements=0; після очищення повертаються чотири точні process ID, а mixed знову містить усі три ресурси.

### TC-INV-NAME-API-003 — Пагінація й перетин фільтрів [AC-02]
Автотест: `InventoryNameFilterApiTest#paginationCountsProcessesAndFiltersIntersect`.
1. Шукати спільний маркер трьох ресурсів зі size=1 на сторінках 0 і 1.
2. Перетнути назву А з відсутнім автором або states=REJECTED.
3. Перетнути назву А з фактичним автором та категорією.
Очікування: totalElements=2 на обох сторінках, точні ID mixed і cableOnly; конфліктні фільтри дають порожній список, сумісні — тільки mixed із А:+2.25.

### TC-INV-NAME-API-004 — Excel за поточною назвою [AC-03]
Автотест: `InventoryNameFilterApiTest#excelContainsOnlyCurrentMatchingResources`.
1. Експортувати повну назву А, потім підрядок «АКУМУЛЯТОР».
2. Змінити назву на Кабель та повторити експорт.
Очікування: книги містять відповідно 1, 2 і 2 точні рядки process/resource/delta; +2.25/-3.5/+4/+1 є числовими, зайвих ресурсів та процесів немає.

### TC-INV-NAME-API-005 — Порожня книга, очищення й AND [AC-03]
Автотест: `InventoryNameFilterApiTest#emptyExcelResetAndCombinedFiltersUseFreshSelection`.
1. Експортувати назву без збігів, потім прибрати фільтр.
2. Експортувати назву А з відсутнім автором.
Очікування: порожня книга тільки з заголовками; після очищення рівно 6 рядків, включно з двома процесами без diff; AND з відсутнім автором знову дає порожню книгу.

### TC-INV-NAME-UI-001 — Видиме поле та точні розбіжності [AC-01]
Автотест: `InventoryNameFilterUiTest#fullAndPartialUnicodeNameShowOnlyMatchingDifferences`.
1. У браузері відкрити «Закриті» власної локації й задати повну назву А.
2. Замінити значення на «  АКУМУЛЯТОР  ».
Очікування: видиме поле працює; у таблиці тільки mixed, спочатку один ресурс А, потім рівно А й Б; запит містить обрізану назву, Кабелю немає.

### TC-INV-NAME-UI-002 — Зміна, відсутність збігів та скидання [AC-02]
Автотест: `InventoryNameFilterUiTest#changedEmptyAndClearedNameRestoreTheCompleteTable`.
1. Змінити пошук А на Кабель.
2. Задати назву без збігів, потім лише пробіли.
Очікування: Кабель видно тільки у mixed і cableOnly; без збігів жодного процесу; пробіли скидають фільтр і повертають усі чотири процеси та три ресурси mixed.

### TC-INV-NAME-UI-003 — Кнопка Excel після зміни назви [AC-03]
Автотест: `InventoryNameFilterUiTest#excelButtonUsesTheCurrentNameAfterChangingTheFilter`.
1. Задати назву А, перевірити таблицю та натиснути Excel.
2. Змінити назву на Кабель, перевірити таблицю та натиснути Excel.
Очікування: завантажено два реальні XLSX; resourceName у запиті актуальний; перша книга містить тільки mixed/А/+2.25, друга — mixed/Кабель/+4 і cableOnly/Кабель/+1.

### TC-INV-NAME-UI-004 — Excel без збігів та після очищення [AC-03]
Автотест: `InventoryNameFilterUiTest#emptyExcelAndResetMatchTheVisibleSelection`.
1. Задати назву без збігів і натиснути Excel.
2. Очистити поле, перевірити всі чотири процеси й завантажити Excel.
Очікування: перший XLSX має тільки заголовки; після очищення resourceName відсутній у запиті й книга містить рівно 6 очікуваних рядків, без попереднього фільтра.

## Автоматизація й запуск

Окремий suite `inventory-name-filter`: 5 API + 4 UI, послідовно, без JDBC/SSH.
Класи також включені до `inventory`, `inventory-process`, `regression`; UI — до `ui`, API — до `functional`.
UI очікує відповідь саме з актуальним resourceName після debounce та перевіряє точні ID процесів.
XLSX звіряється через Apache POI за кожним process/resource/delta, включно з об’єднаними комірками ID.
Скриншоти та отримані XLSX додаються до Allure.

```powershell
mvn test -Denv=dev -Dsuite=inventory-name-filter -Duse.database=false -Dssh.enabled=false -Dsuite.artifact.sweep=false -Dtcm.enabled=false -Dgoogle.sheets.enabled=false -Dframework.browser.channel=chrome
```

Вимоги не є підтвердженням PASS. Фактичний результат зберігається окремо після запуску.
Джерела контракту, лише читання: tk-ui `InventoryProcessesPage.tsx`, `DiffList.tsx`, `api/inventoryProcess.ts`;
tk `InventoryRepository`, `InventoryProcessController`, `InventoryExportService`.
Не перевіряються цим suite: межа експорту 500 процесів, фільтри дат, вибір категорій у UI та RBAC.
