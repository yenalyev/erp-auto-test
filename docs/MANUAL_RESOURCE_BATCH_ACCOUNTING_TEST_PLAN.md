# Тест-план: попартійний облік витрат ресурсу

Дата: 14.10.2026. Середовище перевірки: `dev`. Автоматизований набір: `manual-input-batches`.

## Вимога й правило обліку

Керівник локації може увімкнути «Обліковувати попартійно» для пари **ресурс + локація** у списку ресурсів. Фільтр списку показує всі ресурси, ресурси з ручним вибором або ресурси з FIFO. Для нової пари типовий режим — FIFO. Режим іншої локації від перемикання не змінюється.

У режимі ручного вибору (`MANUAL`) кожна фактична витрата ресурсу має посилатися на наявну партію цієї локації та не може перевищувати її залишок. Це стосується серійного, несерійного й проєктного виробництва, відправлення на іншу локацію та браку на складі. Запланована, але ще не витрачена кількість у проєкті не потребує партії. Для FIFO явний UUID партії у виробничому запиті не допускається. Відхилена операція не змінює жодного залишку. При скасуванні або редагуванні витрата повертається у правильну партію.

Технічне трактування `MANUAL`/`FIFO`: це спосіб **вибору партії при витраті**, а не властивість самої партії. У продуктових записах витрат значення `selection` має бути `MANUAL` для явного вибору і `FIFO` для автоматичного списання. Публічні відповіді не для кожного виду операції відкривають це поле, тому автоматизований оракул переважно перевіряє UUID партії та дельту її залишку.

## Передумови та дані

- Доступні `dev` API, UI, ролі адміністратора і керівника локації, постачальник для зовнішнього отримання, виробнича техкарта, категорія обладнання, дві локації.
- Тести створюють окремі ресурси й локації, поповнюють партії унікальними назвами та фіксують UUID і кількості **до** операції.
- Позитивні сценарії вибирають молодшу з двох партій, щоб відрізнити ручне списання від FIFO. Перевіряють і вибрану, і невибрану партію.
- Перемикач після сценарію повертається у FIFO; тимчасові сутності очищаються через наявні fixture. Якщо очищення блокує продукт, артефакти перевіряються за журналом прогону.

## Обсяг і підхід

| Ділянка | Перевірка | Рівень |
| --- | --- | --- |
| Налаштування | Типовий FIFO, роль, персистентність, ізоляція між локаціями, фільтр | API + UI |
| Серійне виробництво | Обов'язковий UUID, конкретна партія, змішані MANUAL/FIFO ресурси, атомарність | API + UI |
| Несерійне виробництво | Створення і редагування витрати, повернення старого списання | API + UI |
| Проєктне виробництво | План без партії, фактичне споживання й редагування | API + UI |
| Передача | Відправлення з вибраної партії, приймання, кілька партій, редагування, повернення | API + UI |
| Брак на складі | Створення, редагування, видалення, невідома партія | API + UI |
| Межі даних | Чужий, неіснуючий, вичерпаний UUID; нестача; дробова кількість; перемикання режиму | API |

Негативні перевірки виконуються без зміни чужих локацій та продуктивних даних. Повна відповідність вимозі означає, що проходять критичні сценарії налаштування й усіх п'яти видів операцій, а негативні сценарії не змінюють залишки.

## Запуск і результати

PowerShell:

```powershell
mvn test '-Denv=dev' '-Dsuite=manual-input-batches' '-Dframework.browser.channel=chrome' '-Dtcm.enabled=false' '-Dgoogle.sheets.enabled=false'
```

`framework.browser.channel=chrome` використовує встановлений Chrome; без нього Playwright намагатиметься завантажити Chromium. Прапорці вимикають публікацію в TCM та Google Sheets під час локальної перевірки; результати доступні в `target/surefire-reports` і `target/allure-results`. Для окремого методу: `mvn test '-Denv=dev' '-Dtest=ManualInputBatchAccountingApiTest#batchSelectionIsScopedToLocationAndFiltersResources' '-Dframework.browser.channel=chrome' '-Dtcm.enabled=false' '-Dgoogle.sheets.enabled=false'`.

Останній фактичний прогін та дефекти фіксуються в [звіті dev](MANUAL_RESOURCE_BATCH_ACCOUNTING_DEV_REPORT.md). Повний перелік кроків та очікувань — у [тест-кейсах](MANUAL_RESOURCE_BATCH_ACCOUNTING_TEST_CASES.md).

## Уточнення вимоги

Фраза «в партіях вказувати MANUAL» може означати видиме поле у журналі/картці партії. Поточний контракт зберігає спосіб вибору в записі **витрати**, а UI показує відповідний бейдж там, де відображає інгредієнти виробництва. Для окремого приймання партії або залишку значення `MANUAL` некоректне без витрати. Якщо потрібна інша видима колонка чи експорт, це окрема вимога до продукту й окремі кейси.
