# Несерійне виробництво — фільтр за використаною сировиною

Вимога: `REQ-NSP-RESOURCE-FILTER`, дочірня до `REQ-NON-SER-MAN`.

## Поведінка

У журналі «Несерійне виробництво» поле **«Пошук за матеріалами»**
(`Назва матеріалу...`) знаходить вироби за назвою фактично використаної
сировини. Можна ввести повну назву або її частину; регістр не впливає на
результат. Достатньо збігу одного матеріалу. Назва виробу чи його опис самі
по собі не є збігом сировини.

Кожен виріб показується один раз, навіть якщо кілька його матеріалів
відповідають запиту. У рядку залишається повний перелік використаної
сировини. «Загальний об'єм» підсумовує кількість виготовленої продукції всіх
відфільтрованих записів, включно з іншими сторінками, без повторного
врахування виробу через кілька збігів матеріалів.

Пошук за матеріалами поєднується через AND з назвою виробу, статусом,
періодом і вибраною локацією. За відсутності збігів видно «Записів не
знайдено», об'єм дорівнює нулю. Очищення поля матеріалу прибирає тільки
цей фільтр. Кнопка «Очистити» скидає пошук виробу й матеріалу, статус,
період та сторінку. Зміна матеріалу повертає на першу сторінку.
Excel-експорт використовує поточні фільтри й зберігає всю сировину
знайдених виробів.

## Критерії приймання

- **AC-01.** Повна назва, підрядок та інший регістр знаходять записи за
  `resourceUsageList.resource.name`; назва виробу/опис не дають хибних збігів.
- **AC-02.** Кілька збігів не дублюють виріб, пагінацію або об'єм;
  список сировини виробу не обрізається.
- **AC-03.** Матеріал AND виріб AND статус AND включний період AND локація
  застосовуються однаково до списку й підсумку. Читання не змінює залишки.
- **AC-04.** Порожній, відсутній або пробільний матеріал не обмежує
  результати; без збігів список порожній, підсумок нульовий. Очищення
  окремого поля зберігає інші фільтри; загальне очищення скидає їх.
- **AC-05.** Пагінація містить унікальні вироби, підсумок охоплює всі
  сторінки; зміна матеріалу в UI повертає на першу сторінку.
- **AC-06.** Excel містить лише відповідні вироби, кожен об'єм один раз
  і всі матеріали виробу; порожня вибірка дає файл лише із заголовками.

## API та джерела контракту

- `GET /api/v1/non-series-production` — `resourceSearch`, `productSearch`,
  `statuses`, `startDate`, `endDate`, `storageIds`, `page`, `size`, `sort`.
- `GET /api/v1/non-series-production/total` — ті самі бізнес-фільтри,
  відповідь `totalAmount`.
- `GET /api/v1/non-series-production/export` — ті самі бізнес-фільтри,
  XLSX, аркуш «Несерійне виробництво».

Контракт звірено з `tk-ui/src/api/nonSeriesProduction.ts`,
`tk-ui/src/pages/non-series-production/NonSeriesProductionListPage.tsx`,
`tk/src/main/java/org/pm/tk/dao/NonSeriesProductionSpecifications.java`
та `NonSeriesProductionExportFacade.java`. Пошук реалізовано через EXISTS;
журнал, підсумок і експорт використовують одну специфікацію.

## Автоматизовані сценарії

Фікстура `NonSeriesResourceFilterFixture` створює дві сусідні локації,
три власні ресурси та шість виробів. На основній локації: Альфа — 2 од.
із мідним дротом; Бета — 3 од. із дротом, мідним листом та сталлю;
виріб із назвою матеріалу — 5 од., але витрачає лише сталь;
виріб без сировини — 7 од.; старіший виріб — 11 од. із дротом.
На іншій локації — 13 од. із тим самим дротом. Пошук «Мідь + унікальний
маркер» дає рівно 3 записи й об'єм 16; без матеріалу — 5 записів і 28.
Поточний день обмежує відповідні записи до 2 і об'єму 5.

### API — NonSeriesResourceFilterApiTest

1. **TC-NSP-RF-API-001 / AC-01, AC-02.** Повна назва й підрядок у двох
   регістрах; точні ID та об'єм 16; у Бети всі три матеріали.
2. **TC-NSP-RF-API-002 / AC-04.** Без збігів — 0; відсутній, порожній
   та пробільний параметри — усі 5 записів і 28. Виріб лише з назвою
   матеріалу та виріб без ресурсів виключені при активному пошуку.
3. **TC-NSP-RF-API-003 / AC-03.** Перетини з виробом, статусом та
   включними датами, позитивні й порожні результати; перевірка списку й total.
4. **TC-NSP-RF-API-004 / AC-02, AC-05.** Три сторінки `size=1`,
   `totalElements=3`, унікальні ID, total=16; наступна сторінка порожня.
5. **TC-NSP-RF-API-005 / AC-03.** Основна локація — 16, сусідня — 13;
   знімки залишків обох локацій після читання незмінні.
6. **TC-NSP-RF-API-006 / AC-06.** Експорт поєднаних фільтрів — лише Бета,
   один об'єм 3 та всі три матеріали; без збігів лише заголовки.

### UI — NonSeriesResourceFilterUiTest

1. **TC-NSP-RF-UI-001 / AC-01, AC-02.** Поле матеріалу, повна назва,
   підрядок у верхньому регістрі, точні рядки й об'єм 16.
2. **TC-NSP-RF-UI-002 / AC-04.** Порожній результат, нульовий об'єм,
   очищення окремого поля зі збереженням назви виробу та загальне очищення.
3. **TC-NSP-RF-UI-003 / AC-03, AC-06.** Матеріал + статус + виріб;
   один рядок, об'єм 3; перевірка фактично завантаженого Excel.
4. **TC-NSP-RF-UI-004 / AC-05.** 21 додатковий власний запис створює
   другу сторінку при розмірі 25; застосування матеріалу повертає на сторінку 1 з 1.

UI очікує фактичні успішні відповіді списку та підсумку з відповідним
`resourceSearch`, перевіряє точний набір рядків і додає скріншоти Allure.
Після класу фікстура видаляє власні виробництва й отримання, перевіряє
нульові залишки та архівує власні локації, включно з частково виконаною
підготовкою. Ресурси деактивуються, коли це дозволяє API. Поточний
`ResourceValidator` блокує деактивацію навіть через нульові `storage_item`
на архівних локаціях; такі власні ресурси залишаються в каталозі з
попередженням у журналі cleanup. Інші помилки cleanup провалюють конфігурацію.

## Запуск

Обидва класи включені в `non-series-production.xml` та `regression.xml`.
Для адресного прогону без звітних listeners:

```powershell
mvn test -Denv=dev '-Dtest=NonSeriesResourceFilterApiTest,NonSeriesResourceFilterUiTest' -Duse.database=false -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
mvn test -Dsuite=framework -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
```
