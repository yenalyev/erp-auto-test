# Тест-кейси: текстовий пошук точки вильоту

Пов'язаний план: [FLY_POINT_TEXT_SEARCH_TEST_PLAN.md](FLY_POINT_TEXT_SEARCH_TEST_PLAN.md).

## TC-UI-CREW-029 — пошук у формі «Видача на екіпаж»

**Передумови:** користувач відкрив `/relocation/create-output-crew`; відповідь списку точок містить цільову точку `ui-crew-label-fp-*` і відмінну від неї `ui-crew-search-other`.

| Крок | Очікуваний результат |
|---|---|
| Відкрити селектор точки вильоту. | Обидві точки видимі; є поле пошуку. |
| Ввести `ui-crew-label-fp-`. | Цільова точка видима; контрольна точка прихована. |
| Ввести рядок, якого немає в назвах. | Обидві точки приховані; показано `Нічого не знайдено`. |
| Очистити поле пошуку. | Обидві точки знову видимі. |
| Повторити пошук і вибрати цільову точку. | Селектор показує її назву. |

**Автоматизація:** `CrewIssuanceUITest.testFlyPointTextSearchInCrewIssuance`.

## Додаткові сценарії для розширення

- Ввести ту саму назву в іншому регістрі: результат має лишитися тим самим.
- Знайти дочірню точку за назвою: її батьківський підрозділ має залишитися у дереві.
- Шукати за назвою підрозділу: його дочірні точки мають залишитися доступними.
- Закрити та повторно відкрити селектор: попередній пошуковий рядок має бути очищений.

Ці додаткові сценарії описують поведінку компонента, але наразі не входять до двох автоматизованих тестів вище.
