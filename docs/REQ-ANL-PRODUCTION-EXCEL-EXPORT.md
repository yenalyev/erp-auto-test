# REQ-ANL-PRODUCTION-EXCEL — експорт статистики виробництва в Excel

Статус: **функціональний acceptance contract автоматизовано; на DEV виявлено дефекти**
Дата: **2026-09-26**
Сторінка: `/analytics/production` → «Статистика»
Батьківська вимога: `REQ-ANL-PRODUCTION`

## 1. Мета

На сторінці «Аналітика → Виробництво → Статистика» користувач може одним натисканням
завантажити один Excel-файл з усіма передбаченими зрізами виробничої статистики.
Експорт використовує поточні верхні фільтри сторінки та не залежить від того, який
внутрішній таб статистики відкритий у момент натискання.

## 2. Нормалізована вимога

- На вкладці «Статистика» відображається кнопка **«Експорт в Excel»**.
- Натискання завантажує один непорожній файл формату `.xlsx`.
- Workbook містить рівно п'ять аркушів у такому порядку та з точними назвами:
  1. `Виготовлення - За виробами`;
  2. `Виготовлення - Витрати`;
  3. `Розбір - За виробами`;
  4. `Розбір - Витрати`;
  5. `Несерійне виробництво - Витрати`.
- Короткі формулювання з початкового опису (`Виробництво`,
  `Виробництво Витрати`, `Розбір`, `Розбір Витрати`, `Несерійне Витрати`)
  є бізнес-ярликами зрізів і не визначають точні назви Excel-аркушів.
- Acceptance contract точних назв аркушів свідомо узгоджено з реалізацією DEV;
  джерелом істини є наведений вище список із п'яти назв.
- До всіх релевантних аркушів застосовуються встановлені на момент експорту верхні
  фільтри: «Період», «Локації», «Категорії» та «Вироби».
- Комбінація фільтрів має семантику перетину (`AND`), а кілька значень усередині
  одного multiselect — семантику об'єднання (`OR`).
- Аркуші містять повний відфільтрований набір, а не лише видиму сторінку UI.
- Поточний відкритий тип або представлення статистики не змінює склад workbook.
- Дані кожного аркуша відповідають тому самому зрізу, який показує відповідне
  представлення «Статистики» для тих самих верхніх фільтрів.

### 2.1. Відповідність аркушів

- `Виготовлення - За виробами` — результати серійного виготовлення.
- `Виготовлення - Витрати` — витрати ресурсів серійного виготовлення.
- `Розбір - За виробами` — результати операцій розбору.
- `Розбір - Витрати` — витрати ресурсів операцій розбору.
- `Несерійне виробництво - Витрати` — витрати ресурсів несерійного виробництва.

Окремий аркуш результатів несерійного виробництва цією вимогою не передбачений.

### 2.2. Межі вимоги

У поточний scope не входять:

- зміна формул розрахунку статистики;
- імпорт або редагування даних через Excel;
- експорт графіків, стилів UI чи стану пагінації;
- CSV/XLS/PDF;
- локальний «Пошук за назвою…», оскільки він фільтрує лише поточну таблицю;
- зміна наявної backward-compatible поведінки «Лише матеріали»: активний чекбокс
  продовжує передавати `rawResources=true` до export endpoint.

## 3. Acceptance criteria

### AC-EXCEL-01 — доступність дії

- Кнопка видима на вкладці «Статистика» для ролі, що має доступ до аналітики
  виробництва.
- Кнопка не з'являється користувачу без відповідного доступу або запит завершується
  контрольованою відмовою `403` без витоку даних.
- Під час формування файлу повторне натискання не запускає неконтрольовані дублікати.

### AC-EXCEL-02 — валідний файл

- Успішна відповідь має HTTP status `200`.
- `Content-Type` відповідає XLSX/OOXML, а ім'я файлу має розширення `.xlsx`.
- Файл непорожній, має ZIP/XLSX-сигнатуру та відкривається стандартним XLSX-парсером
  без recovery warning.

### AC-EXCEL-03 — склад workbook

- Workbook містить рівно п'ять аркушів.
- Назви та порядок аркушів точно такі:
  1. `Виготовлення - За виробами`;
  2. `Виготовлення - Витрати`;
  3. `Розбір - За виробами`;
  4. `Розбір - Витрати`;
  5. `Несерійне виробництво - Витрати`.
- Заголовки `Виготовлення - За виробами` та `Розбір - За виробами`:
  `Ресурс`, `Категорія`, `Теги`, `Кількість записів`, `Обсяг`, `Од. вимір`.
- Заголовки трьох аркушів витрат: `Ресурс`, `Категорія`, `Теги`, `Обсяг`,
  `Од. вимір`.
- Немає зайвих технічних, прихованих або порожніх службових аркушів.
- Склад workbook однаковий незалежно від активного внутрішнього таба статистики.

### AC-EXCEL-04 — застосування верхніх фільтрів

- Період застосовується за погодженими включними межами `from` і `to`.
- «Локації» обмежують дані дозволеними вибраними локаціями.
- «Категорії» обмежують дані ресурсами вибраних категорій.
- «Вироби» обмежують дані вибраними виробами та пов'язаними з ними витратами.
- Одночасно вибрані фільтри працюють як перетин і однаково передаються до джерел
  усіх п'яти аркушів.
- Скидання фільтрів повертає повний доступний користувачу набір у межах default-періоду.

### AC-EXCEL-05 — правильність даних

- Кожен контрольний запис присутній лише на відповідному аркуші.
- Записи поза періодом, локацією, категорією або вибраним виробом відсутні.
- Кількість, суми витрат, одиниці вимірювання та підсумки збігаються з API/UI для
  того самого набору фільтрів.
- Дублікати не виникають через pagination, join або належність до кількох вибраних
  значень фільтра.
- Дробові значення не втрачають точність і не перетворюються на дати або текст.

### AC-EXCEL-06 — порожній результат

- Якщо фільтри не повертають даних, файл все одно є валідним і містить усі п'ять
  аркушів із заголовками та без фіктивних рядків.
- Порожній результат не спричиняє `500`, пошкоджений файл або нескінченний loader.

### AC-EXCEL-07 — повнота та ізоляція

- Експорт не обрізається розміром сторінки UI.
- Користувач отримує лише дані локацій у власному access scope, навіть якщо підмінити
  query-параметри запиту.
- Дані іншої доступної, але не вибраної локації не потрапляють у workbook.

### AC-EXCEL-08 — помилки та повторний запуск

- При `4xx/5xx`, timeout або розриві мережі UI завершує loading state і показує
  зрозуміле повідомлення; пошкоджений або порожній файл не зберігається як успішний.
- Після помилки користувач може повторити експорт без reload сторінки.
- Послідовні експорти з різними фільтрами не змішують дані попереднього запиту.

## 4. Тестові дані

Потрібен ізольований набір із двома доступними користувачу локаціями `L1`, `L2` та
однією недоступною `L3`.

Створити унікальні ресурси й операції:

- категорії `C1` і `C2`;
- вироби `P1` у `C1` та `P2` у `C2`;
- матеріали `M1`, `M2` з різними одиницями вимірювання;
- серійне виготовлення `P1` у `L1` всередині періоду з витратою `M1`;
- серійне виготовлення `P2` у `L2` всередині періоду з витратою `M2`;
- ще одне виготовлення поза періодом;
- розбір `P1` у `L1` всередині періоду з контрольними output/input;
- розбір `P2` у `L2` та розбір поза періодом;
- несерійне виробництво у `L1` з витратою `M1`;
- несерійне виробництво у `L2` з витратою `M2`;
- еквівалентні записи у недоступній `L3` для перевірки ізоляції;
- щонайменше один дробовий amount, наприклад `2.75`, і значення витрати, яке
  потребує агрегації кількох операцій.

Усі назви мають унікальний run suffix. Дані видаляються або деактивуються після
набору тестів без використання shared-користувачів чи shared-локацій.

## 5. Тест-кейси

### TC-ANL-UI-013 — кнопка та базове завантаження

Пріоритет: **blocker**.

1. Увійти користувачем із доступом до аналітики виробництва.
2. Відкрити `/analytics/production` → «Статистика».
3. Перевірити видимість і доступність «Експорт в Excel».
4. Натиснути кнопку й дочекатися завершення download.

Очікувано: завантажено один непорожній `.xlsx`; відповідь `200`; файл проходить
перевірку XLSX-сигнатури та відкривається парсером.

### TC-ANL-UI-014 — точні назви та порядок аркушів

Пріоритет: **blocker**.

1. Експортувати файл із контрольними даними.
2. Прочитати workbook через Apache POI.
3. Отримати всі аркуші, включно з hidden sheets.

Очікувано: рівно п'ять видимих аркушів у порядку
`Виготовлення - За виробами`, `Виготовлення - Витрати`, `Розбір - За виробами`,
`Розбір - Витрати`, `Несерійне виробництво - Витрати`; зайвих аркушів немає.

### TC-ANL-UI-015 — незалежність від активного таба

Пріоритет: **high**.

1. Експортувати workbook з таба «Виготовлення → За категоріями».
2. Не змінюючи верхніх фільтрів, експортувати з «Розбір → Витрати».
3. Повторити з «Несерійне виробництво → Витрати».
4. Порівняти склад аркушів і контрольні рядки.

Очікувано: усі три workbook мають однакові п'ять аркушів і однаковий набір даних;
активний внутрішній таб не звужує експорт.

### TC-ANL-UI-016 — аркуш «Виготовлення - За виробами»

Пріоритет: **critical**.

1. Встановити період, що включає контрольне виготовлення `P1`.
2. Експортувати workbook.
3. Звірити рядок `P1`, кількість, одиницю та підсумок з API/UI.
4. Перевірити відсутність операцій розбору й несерійного виробництва.

Очікувано: аркуш містить лише результати серійного виготовлення у вибраному scope.

### TC-ANL-UI-017 — аркуш «Виготовлення - Витрати»

Пріоритет: **critical**.

1. Експортувати період із двома операціями виготовлення, що витрачають `M1`.
2. Звірити матеріал, агреговану витрату й одиницю з endpoint статистики витрат.
3. Перевірити відсутність витрат розбору та несерійного виробництва.

Очікувано: значення дорівнює сумі витрат усіх релевантних операцій виготовлення.

### TC-ANL-UI-018 — аркуш «Розбір - За виробами»

Пріоритет: **critical**.

1. Експортувати період із контрольним розбором `P1`.
2. Звірити ресурс, кількість, одиницю та підсумок з API/UI розбору.
3. Перевірити відсутність серійного й несерійного виробництва.

Очікувано: аркуш містить тільки результати операцій розбору.

### TC-ANL-UI-019 — аркуш «Розбір - Витрати»

Пріоритет: **critical**.

1. Експортувати період із контрольними витратами розбору.
2. Звірити назви, кількості, одиниці та агрегацію з відповідним API/UI.
3. Перевірити відсутність витрат інших типів виробництва.

Очікувано: аркуш містить тільки витрати операцій розбору в поточному scope.

### TC-ANL-UI-020 — аркуш «Несерійне виробництво - Витрати»

Пріоритет: **critical**.

1. Створити дві несерійні операції з витратою того самого `M1`.
2. Експортувати workbook.
3. Звірити агреговану витрату з `/production/analytic/non-serial/input`.
4. Перевірити відсутність витрат серійного виготовлення та розбору.

Очікувано: аркуш містить суму витрат несерійного виробництва без змішування типів.

### TC-ANL-UI-021 — фільтр «Період» і граничні дати

Пріоритет: **blocker**.

1. Підготувати записи на `from`, між межами, на `to`, за день до `from` і за день
   після `to`.
2. Встановити довільний період і виконати експорт.
3. Перевірити кожен із п'яти аркушів.

Очікувано: записи на `from` і `to` включені; записи поза межами відсутні; календарні
дати не зсуваються через timezone браузера або backend.

### TC-ANL-UI-022 — фільтри «Локації», «Категорії» та «Вироби»

Пріоритет: **blocker**.

1. Окремо вибрати `L1`, `C1` та `P1`, після кожного вибору виконати експорт.
2. Для кожного файлу перевірити всі п'ять аркушів.
3. Для multiselect вибрати `L1 + L2`, потім `P1 + P2`.

Очікувано: один вибір виключає контрольні дані іншого значення; кілька значень
усередині одного фільтра об'єднуються без дублікатів; витрати слідують фільтру
відповідного виробу, а не фільтруються помилково за назвою матеріалу.

### TC-ANL-UI-023 — комбінація верхніх фільтрів

Пріоритет: **blocker**.

1. Встановити період + `L1` + `C1` + `P1`.
2. Експортувати workbook і звірити всі аркуші.
3. Замінити один фільтр на несумісне значення, наприклад `L2` для запису `P1` у `L1`.
4. Експортувати повторно.

Очікувано: перший файл містить лише перетин чотирьох фільтрів; другий не містить
контрольний запис. Жоден аркуш не використовує застарілий стан попередніх фільтрів.

### TC-ANL-UI-024 — порожня вибірка

Пріоритет: **high**.

1. Вибрати період або комбінацію фільтрів без даних.
2. Виконати експорт.
3. Відкрити всі аркуші парсером.

Очікувано: валідний workbook містить усі п'ять аркушів і заголовки, але не містить
data rows, нульових заглушок або даних із попереднього експорту.

### TC-ANL-UI-025 — повний набір поза пагінацією

Пріоритет: **high**.

1. Створити більше записів, ніж page size таблиці статистики.
2. Переконатися, що UI показує лише першу сторінку.
3. Виконати експорт і порахувати унікальні контрольні рядки workbook.

Очікувано: файл містить увесь відфільтрований набір без пропусків і дублікатів.

### TC-ANL-UI-026 — типи й точність Excel-комірок

Пріоритет: **high**.

1. Експортувати цілі, дробові та агреговані значення в різних одиницях вимірювання.
2. Перевірити типи комірок через Apache POI, не лише відформатований текст.
3. Відкрити файл у Excel або LibreOffice як exploratory check.

Очікувано: числа збережено numeric cells; одиниці — окремими текстовими значеннями;
точність відповідає доменному rounding; значення придатні для сортування та формул.

### TC-ANL-UI-027 — авторизація та підміна scope

Пріоритет: **blocker**.

1. Експортувати користувачем, який має доступ до `L1/L2`, але не до `L3`.
2. Перевірити відсутність даних `L3`.
3. Повторити export request із вручну доданим `L3`.
4. Виконати запит користувачем без дозволу на аналітику.

Очікувано: `L3` не розкривається; неавторизований запит повертає `401/403`; файл із
чужими даними не формується.

### TC-ANL-UI-028 — помилка, retry та послідовні експорти

Пріоритет: **normal**.

1. Імітувати `500` або timeout export endpoint.
2. Перевірити завершення loader і повідомлення про помилку.
3. Відновити endpoint і повторити export без reload.
4. Послідовно експортувати `L1`, потім `L2`.

Очікувано: retry успішний; перший успішний файл містить лише `L1`, другий — лише
`L2`; помилковий response не маскується під успішний download.

## 6. Нефункціональні та exploratory перевірки

- Файл із репрезентативним великим обсягом формується в межах погодженого SLA та не
  спричиняє out-of-memory на backend.
- Українські назви, апостроф, дефіс і довгі назви не пошкоджуються.
- Назви, що починаються з `=`, `+`, `-` або `@`, не повинні створювати небезпечну
  spreadsheet formula, якщо походять із користувацьких даних.
- Кнопка доступна з клавіатури, має зрозумілу accessible name і стан loading/disabled.
- Перевірити актуальні підтримувані браузери; основний automation run достатньо
  виконувати в Chromium, а download smoke — у решті браузерної матриці продукту.

## 7. План автоматизації

### 7.1. Рівні

- API/contract: статус, headers, XLSX signature, точні аркуші, authorization і
  передавання всіх верхніх фільтрів.
- UI/E2E: видимість кнопки, фактичний download, зв'язок стану фільтрів із export
  request та один наскрізний контроль даних усіх п'яти аркушів.
- Parser assertions: назви/порядок sheets, headers, унікальні контрольні маркери,
  numeric cell types і відсутність out-of-scope маркерів.

### 7.2. Рекомендований мінімум для CI

- Blocker: `TC-ANL-UI-013`, `014`, `021`, `022`, `023`, `027`.
- Critical: `TC-ANL-UI-016…020` можна об'єднати в один data-driven workbook test,
  але звітність повинна окремо показувати результат для кожного аркуша.
- High: `TC-ANL-UI-015`, `024`, `025`, `026`.
- Error-path `TC-ANL-UI-028` доцільніше стабільно покрити frontend integration test
  з контрольованою відповіддю endpoint.

### 7.3. Зміни в automation framework

- Розширити `ProductionAnalyticsUiTest` новими кейсами `TC-ANL-UI-013…028` або
  винести експорт у `ProductionAnalyticsExcelExportUiTest` для ізольованого fixture.
- `ProductionAnalyticsPage.exportStatisticsToExcel()` має й надалі повертати шлях,
  розмір і request URL.
- Розширити `XlsxWorkbookReader`, щоб він умів перевіряти visibility sheet,
  physical row count і native cell type, а не лише `DataFormatter`-текст.
- Дані для п'яти аркушів створювати через API fixtures до відкриття UI.
- Не порівнювати весь binary-файл із golden fixture: перевіряти семантичний контракт.

## 8. Ризики та уточнення перед розробкою

1. Заголовки та їхній порядок зафіксовано в `AC-EXCEL-03`; стилі й ширина колонок
   не є частиною автоматизованого контракту.
2. Межі періоду в цьому контракті включні; календарна дата береться зі стану UI
   без додаткового timezone-зсуву під час експорту.
3. Потрібно визначити ім'я файлу; рекомендовано стабільний префікс і дату експорту
   без символів, несумісних із Windows.
4. Локальний «Пошук за назвою…» не впливає на workbook. Наявний чекбокс
   «Лише матеріали» зберігає backward-compatible `rawResources=true`; його повне
   вилучення з контракту потребуватиме окремого продуктового рішення.
5. Потрібно визначити погоджений SLA/максимальний обсяг для великого workbook.
6. Поточні `AC-05` і `AC-08` у `REQ-ANL-PRODUCTION` описують експорт активного
   представлення. Після реалізації багатолистового workbook цей документ має бути
   джерелом істини для складу файлу, а старі кейси слід актуалізувати, не дублювати.

## 9. Критерії завершення

- Реалізовані `AC-EXCEL-01…08`.
- Пройдені всі blocker і critical кейси.
- Workbook має точні п'ять аркушів і однаково застосовує верхні фільтри.
- Немає витоку даних поза location scope.
- Погоджені колонки, timezone, filename і SLA внесені до цього документа.
- Automation додана до постійних suite `ui.xml`, `production.xml` і `regression.xml`.
- Результат DEV-прогону та відомі обмеження зафіксовані в документації.

## 10. Результат виконання на DEV

Дата останньої перевірки: **2026-09-26**.

Автоматизовано весь функціональний набір `TC-ANL-UI-013…028` у
`ProductionAnalyticsUiTest`, включно з `TC-ANL-UI-025` для повної вибірки поза
пагінацією. Детальний актуальний результат наведено у
[DEV test report](audits/2026-09-26/production-analytics-excel-export-dev-test-report.md).

Підтверджено проходження сценаріїв валідного XLSX, точного складу workbook,
включних меж періоду, повної вибірки понад UI page size, authorization scope,
порожньої вибірки, numeric cell types, контрольованої помилки та retry. Перевірка
workbook тепер включає точні заголовки, кількості/суми, одиниці вимірювання,
унікальність рядків, `AND`/`OR` семантику фільтрів та скидання фільтра «Вироби».

Поточна DEV-реалізація не відповідає контракту в таких місцях:

- `TC-ANL-UI-017`, `019`, `020`: в колонці `Обсяг` аркушів витрат експортується
  кількість записів (`1`, `1`, `2`) замість фактичних агрегованих витрат
  (`16.5`, `2`, `14` для контрольного набору);
- `TC-ANL-UI-022`, `023`: фільтр «Вироби» залишає рядок готового виробу, але
  помилково вилучає пов'язані з ним витрати з expense-аркушів.

Отже, тестове покриття функціонального acceptance contract є повним, але feature
ще не може вважатися прийнятою: наведені regression-тести залишаються червоними до
виправлення DEV.
