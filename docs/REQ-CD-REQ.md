# Обов'язкові поля нового комерційного документа

У модулі **Документообіг переміщень → Облік надходжень → Комерційні документи**
форма «Новий комерційний документ» позначає обов'язкові поля та дозволяє збереження
лише після їх заповнення. TCM: `REQ-DOCFLOW` → `REQ-CD-REQ`, project `1`.

Покриття містить **8 автоматизованих кейсів: 4 API та 4 UI**.
API-параметризація дає **21 виконання**, UI — **4**, разом **25**.

## Контракт форми та API

Видимі `*` мають номер, дата документа, дія «Додати файли», заголовки
«Сума за все, грн» і «Назва ресурсу за документом». Заголовки ресурсів з'являються
після вибору надходження. Коментар, код номенклатури й категорія (сорт) необов'язкові
та не мають позначки `*`. Вибір хоча б одного надходження є умовою збереження.

`POST /api/v1/virtual-storage/{storageId}/commercial-documents` приймає multipart:

- `request`, `application/json`: `number`, `documentDate`, `receiptIds`, `lines`;
- `files`: щонайменше один непорожній файл;
- кожен рядок `lines`: `resourceId`, `total`, `documentResourceName`;
- необов'язкові значення: `comment`, `nomenclatureCode`, `grade`.

Номер і назва ресурсу не можуть бути порожніми або складатися лише з пробілів.
Сума `0` допустима й відрізняється від незаповненої суми. UI обрізає крайні пробіли
текстових значень і не передає порожні необов'язкові поля. Дата в UI початково
заповнена; її відсутність перевіряється API-тестом, оскільки чинний DatePicker не має очищення.

Відхилений запит повертає HTTP `400` і не створює документ, не прив'язує надходження
та не змінює облік. Успішне створення повертає HTTP `200`; окремий GET підтверджує
збереження документа у стані `NEW`.

## Критерії приймання

- **AC-01.** На новій формі видимі позначки `*` для номера, дати, файлів, суми й назви ресурсу за документом. Необов'язкові коментар, код номенклатури та сорт не позначені.
- **AC-02.** API відхиляє відсутні обов'язкові номер, дату та надходження. Порожній номер і номер із пробілів також відхиляються. UI блокує збереження без номера або вибраного надходження.
- **AC-03.** Кожен вибраний ресурс потребує окремих суми та непорожньої назви за документом. Помилка другого ресурсу не дозволяє зберегти частковий документ. Нульова сума допустима.
- **AC-04.** Для створення потрібен хоча б один непорожній файл. API відхиляє відсутній та порожній файловий part; UI блокує збереження після видалення останнього вибраного файлу.
- **AC-05.** Документ з лише обов'язковими значеннями та total=0 успішно створюється. GET і повторне відкриття форми підтверджують збережені значення; сусіднє надходження й його облік незмінні.
- **AC-06.** Скасування не створює документ і не змінює надходження. Нова форма після скасування має порожній номер, жодного файлу й жодного вибраного надходження; збереження заблоковане.

## Дані та ізоляція

`CommercialDocumentFixture` створює власну внутрішню локацію обліку, окрему зовнішню
локацію постачальника, два ресурси A/B, два записи обліку й надходження на 2/3 одиниці.
Локації є сусідами під наявною батьківською локацією. Дата надходжень — учора;
API-документа — учора, UI-документа — значення DatePicker у момент збереження.
Файл — невеликий валідний PDF `commercial-document.pdf`.

Перед кожною негативною API-дією зчитуються документи, вільні надходження та облік;
після дії перевіряється рівність усіх трьох знімків. Позитивні кейси контролюють
сусідній ресурс B. Після методу видаляються створені документи, після класу —
власні надходження, архівуються записи обліку, ресурси та локації. Архівні сутності
залишаються відповідно до lifecycle ERP. Спільні надходження й документи не змінюються.

## API тест-кейси

### TC-CD-REQ-API-001 — Номер дата та надходження обов'язкові (AC-02)

Автотест: `CommercialDocumentRequiredFieldsApiTest#rejectMissingHeader`. **9 виконань.**

1. Зберегти знімки документів, вільних надходжень та обліку власної локації.
2. Побудувати валідний multipart `request + files` для A й змінити тільки одне поле: `number` відсутній/null/порожній/пробіли; `documentDate` відсутня/null; `receiptIds` відсутній/null/порожній масив.
3. Надіслати запит та повторно зчитати три знімки.

Очікується: HTTP 400, відповідь називає невалідне поле; всі три знімки незмінні.

### TC-CD-REQ-API-002 — Сума та назва обов'язкові для кожного ресурсу (AC-03)

Автотест: `CommercialDocumentRequiredFieldsApiTest#rejectMissingLineFields`. **9 виконань.**

1. Вибрати надходження A та B, підготувати валідні рядки для обох ресурсів і зберегти три знімки.
2. Перевірити `lines` відсутній/null/порожній масив; окремо, з валідним першим рядком, прибрати total другого рядка або передати null; прибрати documentResourceName другого рядка або передати null/порожній рядок/пробіли.
3. Надіслати multipart із непорожнім PDF та повторно зчитати три знімки.

Очікується: HTTP 400, частковий документ не створений; документи, надходження та облік незмінні. Для відсутнього/null lines та невалідних полів рядка відповідь містить lines; для порожнього масиву перевіряються статус та ізоляція.

### TC-CD-REQ-API-003 — Файл обов'язковий і не може бути порожнім (AC-04)

Автотест: `CommercialDocumentRequiredFieldsApiTest#rejectAbsentOrEmptyFile`. **2 виконання.**

1. Підготувати валідний request і зберегти три знімки.
2. Надіслати multipart без files; окремим виконанням передати files із нульовою довжиною.
3. Перевірити помилку та повторно зчитати документи, надходження й облік.

Очікується: HTTP 400, відповідь містить files; всі три знімки незмінні.

### TC-CD-REQ-API-004 — Створення з лише обов'язковими полями та нульовою сумою (AC-05)

Автотест: `CommercialDocumentRequiredFieldsApiTest#createWithOnlyRequiredFields`. **1 виконання.**

1. Зберегти облік і вільне надходження B. Підготувати документ для A з total=0 та назвою за документом, без comment, nomenclatureCode й grade.
2. Надіслати multipart із непорожнім PDF і прочитати збережений документ окремим GET списку документів.
3. Перевірити номер, дату, NEW, один файл, один рядок total=0 і його назву, null необов'язкових полів та зв'язок з надходженням A.
4. Перевірити, що додано лише один документ, B залишилося вільним, його облік незмінний і receivedAmount ресурсів збережені.

Очікується: HTTP 200, значення збережені; з двох надходжень документ покриває тільки A, сусід B незмінний.

## UI тест-кейси

### TC-CD-REQ-UI-001 — Видимі позначки обов'язкових полів (AC-01)

Автотест: `CommercialDocumentRequiredFieldsUiTest#requiredMarkersAppearOnLabelsAndResourceColumns`. **1 виконання.**

1. Під ADMIN вибрати власну локацію та відкрити Облік надходжень → Комерційні документи → Додати комерційний документ.
2. Перевірити видимі * біля Номер, Дата документа й Додати файли; перевірити відсутність * у Коментар.
3. Вибрати надходження A; перевірити видимі * у Сума за все, грн і Назва ресурсу за документом, відсутність * у Код номенклатури та Категорія (сорт).
4. Перевірити недоступність Зберегти й додати скріншоти початкової форми та рядка ресурсу.

Очікується: усі п'ять обов'язкових полів мають видимі позначки, три необов'язкові — без них; неповна форма не зберігається.

### TC-CD-REQ-UI-002 — Блокування збереження та скидання скасованої форми (AC-06)

Автотест: `CommercialDocumentRequiredFieldsUiTest#saveRequiresNumberFileAndReceiptAndCancelResetsForm`. Також AC-02, AC-04. **1 виконання.**

1. Заповнити валідну форму: номер, PDF, надходження A, total=0, назва ресурсу; необов'язкові поля лишити порожніми.
2. Окремо очистити номер, ввести пробіли, видалити файл і зняти вибір надходження. Після кожної невалідної зміни перевірити disabled Зберегти, після відновлення — enabled.
3. Натиснути Скасувати, відкрити нову форму й перевірити порожній номер, відсутність файлів та вибраних checkbox і disabled Зберегти.
4. Перевірити лічильник POST створення документа, список документів і знімок вільних надходжень.

Очікується: збереження залежить від кожного обов'язкового значення; після скасування форма скинута, POST=0, документів немає, надходження незмінні.

### TC-CD-REQ-UI-003 — Сума й непорожня назва для кожного вибраного ресурсу (AC-03)

Автотест: `CommercialDocumentRequiredFieldsUiTest#eachResourceRequiresTotalAndNonblankDocumentName`. **1 виконання.**

1. Підготувати валідну форму для A й додати B. Перевірити disabled Зберегти, поки поля B порожні.
2. Ввести B.total=0 та назву з пробілів: Зберегти лишається disabled. Ввести непорожню назву: enabled.
3. Для кожного ресурсу окремо очистити й відновити суму та назву, перевіряючи disabled/enabled після кожної зміни.
4. Додати скріншот валідних рядків; перевірити відсутність документів і два вільні надходження.

Очікується: обидва ресурси потребують своїх суми та назви; нуль допустимий; документ не створено, обидва надходження вільні.

### TC-CD-REQ-UI-004 — Збереження та повторне відкриття обов'язкових значень (AC-05)

Автотест: `CommercialDocumentRequiredFieldsUiTest#saveAndReopenRequiredFieldsOnly`. **1 виконання.**

1. Зберегти облік. Заповнити номер, PDF, вибрати A, ввести total=0 і Назва з UI; запам'ятати дату DatePicker, необов'язкові поля лишити порожніми.
2. Натиснути Зберегти, перехопити фактичний POST та прочитати документ через API.
3. Перевірити HTTP 200, номер, дату, NEW, один файл, total=0, назву, null необов'язкових полів; B лишається вільним і його облік незмінний.
4. Відкрити документ кнопкою Редагувати. Перевірити номер, дату, total=0, Назва з UI, порожній коментар та enabled Зберегти. Додати скріншоти до й після збереження.

Очікується: документ збережений; повторна форма відтворює введені значення та дозволяє збереження з наявним файлом; сусід B незмінний.

## Автоматизація та запуск

Java-класи: `com.erp.tests.functional.relocation.CommercialDocumentRequiredFieldsApiTest`
та `com.erp.tests.ui.CommercialDocumentRequiredFieldsUiTest`.
Page Object — `CommercialDocumentPage`, дані — `CommercialDocumentFixture`.
Кожен кейс має однойменний `@TestCaseId`, API/UI automation ID і ACTIVE-статус у TCM.
Класи зареєстровані в `commercial-document-required-fields`, `relocations`, `regression`;
UI-клас також у `ui`. Скріншоти ключових і фінальних UI-станів доступні в Allure.

```powershell
$env:JAVA_HOME='C:\Users\gigam\.jdks\corretto-21.0.9'
$env:PATH="$env:JAVA_HOME\bin;$env:PATH"
$env:PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD='1'
mvn test -Denv=dev -Dsuite=commercial-document-required-fields -Duse.database=false -Dssh.enabled=false -Dframework.browser.channel=chrome -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
```

Параметр `tcm.enabled=false` вимикає публікацію результатів конкретного запуску.
Для публікації зі suite використовується чинна конфігурація TCM; для TCM scope потрібен
DB ID фічі саме цільового середовища. DB ID production та local TCM не взаємозамінні.

## Межі покриття

Перевірено створення під ADMIN; окремої RBAC-матриці немає. Зміни полів чинного
документа й блокування документів у додатку 24 не входять до цих восьми кейсів.
API перевіряє відсутній та порожній файл; UI перевіряє наявність вибраного файлу.
Граничні довжини, від'ємні суми, точність суми та перевірка типів вкладень цим набором
не заявляються. SUT `tk` і `tk-ui` не змінюється.
