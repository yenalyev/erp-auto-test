# CPMA-895: підказка про локацію при редагуванні та клонуванні техкарт

## Зміна поведінки

Виправлення «Недоступне редагування і клонування техкарт при виборі Цукрарні в
селекторі сайдбару» додає пояснення, чому дію неможливо виконати в поточному контексті.
Воно **не дозволяє редагувати або клонувати техкарту дочірньої локації з Цукрарні**.
Користувач має вибрати відповідну локацію в селекторі сайдбару та повторити дію.

При натисканні «Редагувати» або «Клонувати» для такої техкарти запит завантаження
карти в контексті Цукрарні завершується помилкою. UI показує спливне повідомлення
і повертає користувача до списку `/technological-maps`, замість залишати незаповнену форму.
Повідомлення містить пояснення та підказку:

> Для вибраної Технологічної карти виберіть одну з наступних локацій: {назви локацій}

Назви беруться з локацій вибраної техкарти у списку; декілька назв розділяються комами.
У реалізації CPMA-895 це `toast.error` після натискання дії, а не tooltip при наведенні
чи вимкнена кнопка. За відсутності назв локацій (наприклад, при відкритті прямого URL)
показується помилка завантаження без цієї підказки.

## Критерії приймання

1. Після вибору Цукрарні **через селектор сайдбару** у списку видно техкарту дочірньої локації.
2. Натискання «Редагувати» для неї показує повідомлення з пропозицією вибрати
   відповідну локацію та її назвою. UI повертається до списку; Цукрарня залишається вибраною.
3. Натискання «Клонувати» має таку саму поведінку.
4. Невдала спроба не змінює оригінал, не створює копію чи нову версію та не надсилає
   запитів зміни техкарт (`POST`, `PUT`, `PATCH`, `DELETE`).
5. Після вибору вказаної дочірньої локації через сайдбар редагування відкриває
   заповнену форму. Зміна норми вхідного ресурсу й збереження створюють нову версію
   тієї самої групи зі збереженням прив'язки до локації.
6. Після такого самого переходу клонування відкриває заповнену форму копії.
   Збереження з новою назвою створює окремі `id` і `groupId`, зберігає склад ресурсів
   та прив'язку до локації, не змінюючи оригінал.

Для сценаріїв потрібні відповідні права та режим `EDIT_ALLOWED`. Виправлення
не скасовує перевірок прав і режиму редагування. Переглянута реалізація CPMA-895
охоплює редагування та клонування; поведінка інших дій не розширюється цим документом.

## Автоматизоване покриття

Клас `TechnologicalMapWorkspaceActionsUiTest`, чотири сценарії:

- `TC-UI-MFG-WORKSPACE-HINT` / «Редагувати» — помилка завантаження, підказка з назвою
  локації, повернення до списку, відсутність записів і змін оригіналу.
- `TC-UI-MFG-WORKSPACE-HINT` / «Клонувати» — ті самі перевірки для спроби клонування.
- `TC-UI-MFG-WORKSPACE-EDIT` — отримати підказку в Цукрарні, вибрати вказану локацію,
  повторити редагування й перевірити збережену версію через API.
- `TC-UI-MFG-WORKSPACE-CLONE` — отримати підказку в Цукрарні, вибрати вказану локацію,
  повторити клонування й перевірити копію та незмінність оригіналу через API.

Використовується `ADMIN`, ізольована дочірня виробнича локація та нові техкарти.
Корінь знаходиться через API за назвою активної локації «Цукрарня» після обрізання
крайових пробілів; тест вимагає єдиного збігу. Вибір локацій виконується через сайдбар,
без залежності від ключів `localStorage`. Початковий режим редагування кореня відновлюється після класу,
створені техкарти й дочірня локація прибираються.

Клас включений у `technological-maps`, `ui`, `regression`. Окремий запуск на dev:

```powershell
mvn test -Denv=dev -Dtest=TechnologicalMapWorkspaceActionsUiTest -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
```

Ролі без прав, `READ_ONLY`, архівні техкарти, «Всі локації», кілька локацій у підказці
та відкриття прямого URL не покриті цими чотирма сценаріями.

Команда вище з додатковим `-o`: **4 тести, 0 помилок, 0 пропусків; BUILD SUCCESS**.
