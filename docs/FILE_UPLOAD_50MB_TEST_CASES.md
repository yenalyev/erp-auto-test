# Тест-кейси: завантаження файлів до 50MB

Очікуваний текст помилки нижче підтверджено відповіддю розгорнутого dev 26.09.2026. Локальний checkout backend `tk` містить старіший текст без `50MB`.

## Спільні передумови

- У тестовому середовищі `MULTIPART_MAX_SIZE` не перевизначено: backend використовує `50MB` для `max-file-size` і `max-request-size`.
- Є користувач із правом редагувати проєктне виробництво та існуючий запис із відомими `id` і `storageId`.
- Підготовлено два PDF-файли допустимого формату: малий (наприклад, 1 МБ) і більший за 50MB (наприклад, 51 МіБ). Великому файлу не має заважати окремий ліміт proxy; інакше перевірятиметься відповідь proxy, а не backend.
- API-маршрут: `PUT /api/v1/project-production/{id}/file?storageId={storageId}`, multipart-поле `file`. У формі редагування проєктного виробництва файл надсилається через цей маршрут.

## TC-UPLOAD-50-01 — Успішне завантаження допустимого файла

**Кроки**

1. Надіслати авторизований multipart-запит із малим PDF у полі `file`.
2. Відкрити запис проєктного виробництва та завантажити прикріплений файл назад.

**Очікуваний результат**

- API повертає успішну відповідь; файл є у списку вкладень запису.
- Завантажений назад файл збігається з вихідним за вмістом.
- Повідомлення про перевищення розміру немає.

## TC-UPLOAD-50-02 — Повідомлення backend про перевищення ліміту

**Кроки**

1. Зафіксувати поточний список вкладень запису.
2. Надіслати авторизований multipart-запит із PDF розміром 51 МіБ у полі `file`.
3. Повторно відкрити список вкладень.

**Очікуваний результат**

- API повертає **HTTP 400 Bad Request**.
- `errors[0].messages[0]` дорівнює **«Розмір файлу перевищує допустимий 50MB.»**.
- Нового файла у списку вкладень немає; попередні вкладення не змінилися.

## TC-UPLOAD-50-03 — Відображення повідомлення користувачу

**Кроки**

1. Відкрити форму редагування проєктного виробництва.
2. Додати PDF розміром 51 МіБ через блок файлів.

**Очікуваний результат**

- Файл не додається до збережених вкладень.
- UI показує повідомлення backend **«Розмір файлу перевищує допустимий 50MB.»** та не показує повідомлення про успішне завантаження.

## TC-UPLOAD-50-04 — Успішне завантаження фото ресурсу

**Кроки**

1. Створити тестовий ресурс і надіслати невелике PNG-фото в multipart-полі `file` на `POST /api/v1/resources/{id}/image`.
2. Отримати ресурс і його фото через API.

**Очікуваний результат**

- Завантаження успішне; у ресурсу заповнено `imagePath`.
- `GET /api/v1/resources/{id}/image` повертає HTTP 200 і непорожнє зображення.

## TC-UPLOAD-50-05 — Повідомлення про перевищення ліміту для фото ресурсу

**Кроки**

1. Створити тестовий ресурс без фото.
2. Надіслати PNG-файл розміром 51 МіБ на `POST /api/v1/resources/{id}/image`.
3. Повторно отримати ресурс і його фото.

**Очікуваний результат**

- API повертає HTTP 400 та `errors[0].messages[0] = "Розмір файлу перевищує допустимий 50MB."`.
- `imagePath` залишається порожнім; `GET` фото повертає HTTP 404.

Для фото ресурсу форма UI має власний поріг 5 МБ. Тому серверний ліміт 50MB у TC-UPLOAD-50-05 перевіряється прямим API-запитом.

## TC-UPLOAD-50-06 — Десять файлів по 5 МіБ в одному запиті

**Кроки**

1. Підготувати 10 PNG-файлів розміром рівно 5 МіБ кожен.
2. Надіслати один multipart-запит `POST /api/v1/project-production`: валідна JSON-частина `request` і 10 частин `files`.

**Очікуваний результат**

- Загальний розмір запиту перевищує 50MB через multipart-обгортку, хоча кожен файл окремо має лише 5 МіБ.
- API повертає HTTP 400 та `errors[0].messages[0] = "Розмір файлу перевищує допустимий 50MB."`.

Маршрут фото ресурсу приймає тільки один `file`, тому перевірка суми 10 файлів виконується на маршруті проєктного виробництва, який приймає масив `files`.

Текст «Перевищено максимальний розмір <size> на завантажень» не є очікуванням цих кейсів: dev його не повертає.

Автоматизований запуск: `mvn test -Denv=dev -Dsuite=file-upload-50mb -Dtcm.enabled=false -Dgoogle.sheets.enabled=false -Dapi.timeout=180`.

Останній прогін на dev 26.09.2026: **6 пройшли, 0 помилок, 0 пропусків**. Звіт: `target/surefire-reports/TEST-TestSuite.xml`. Для великих запитів автотести використовують HTTP-клієнт Playwright: RestAssured у цьому середовищі обривав передавання до читання ранньої відповіді HTTP 400.
