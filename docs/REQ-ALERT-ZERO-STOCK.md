# Залишки: нульовий ресурс зі сповіщенням

## Вимога

На сторінці «Залишки» ресурс з кількістю `0` має відображатися, якщо для цього ресурсу **на поточній локації** налаштовано сповіщення по залишках. Правило діє також при вимкненому тоглі «Показувати нульові залишки». Значення `0`, статус «відсутній» і налаштований поріг мають лишатися видимими.

Нульовий ресурс без сповіщення при вимкненому тоглі прихований. При ввімкненому тоглі обидва нульові ресурси відображаються. Після видалення сповіщення нульовий ресурс знову підпадає під звичайний фільтр тогла. Ресурс із додатним залишком відображається незалежно від тогла.

Умова перевіряється для фактичного залишку `0` як із наявним `StorageItem`, так і для ресурсу, який має сповіщення, але не мав надходжень (якщо система створює для нього нульовий рядок). Видимість визначається сповіщенням для вибраної локації, а не налаштуванням іншого складу.

## Межі

Ця вимога стосується таблиці на `/inventory` та джерела даних, з якого вона завантажується (`GET /api/v1/storages/inventory` з `parentStorageId` і `showZeroStock`). Поведінку Excel-експорту й кнопки «Скопіювати» задача не визначає; їхній наявний контракт описано в [REQ-WMS-007-stock-export-copy.md](REQ-WMS-007-stock-export-copy.md).

## Критерії приймання

1. Тогл вимкнений: нульовий ресурс зі сповіщенням є у таблиці з кількістю `0` та статусом «відсутній»; нульового ресурсу без сповіщення немає.
2. Тогл увімкнений: обидва нульові ресурси є у таблиці.
3. Сповіщення видалено, тогл вимкнений: колишній нульовий ресурс зі сповіщенням зникає після оновлення таблиці.
4. `showZeroStock=false` у hierarchy API повертає нульовий ресурс зі сповіщенням і не повертає нульовий без сповіщення; `true` повертає обидва.
