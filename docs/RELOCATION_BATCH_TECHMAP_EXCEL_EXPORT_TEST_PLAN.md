# Переміщення — Excel-експорт партій і техкарт

Стан покриття: початковий аудит коду автотестів станом на 30.09.2026. Основний API-контракт у репозиторії — `GET /api/v1/relocations/export` (`RELOCATION_GET_EXPORT`). Реалізовані кейси й результати dev-прогону наведено в [окремому звіті](audits/2026-09-30/relocation-batch-techmap-excel-export-dev-test-report.md).

## Очікувана поведінка

- У файлі є окремі колонки **«Партія»** і **«Тех карта»**. Потрібно зберегти наявні поля, зокрема назву ресурсу, кількість, одиницю виміру та № накладної. Порядок нових колонок за прикладом: після одиниці виміру, перед № накладної. Точне написання заголовка «Тех карта» слід затвердити з продуктом: у чинному попапі «Залишки» використано «Техкарта».
- Для кожної партії, яка фактично входить до позиції переміщення, є окремий рядок із **кількістю саме цієї партії**. Наприклад, 5 + 2 + 8 дають три рядки, а не три рядки по 15. Сума кількостей рядків дорівнює кількості позиції переміщення; рядки інших переміщень або партій не додаються.
- «Тех карта» належить саме експортованій партії та вказує карту, за якою її виготовили. Для партії без виробництва очікується порожнє значення або `-` — точне представлення потрібно узгодити. Попап «Залишки» показує `-` для `techmap = null`, але це ще не доводить такий самий формат Excel.
- Та сама семантика діє для експорту з вкладок **«Видано»** і **«Отримано»** сторінки **«Видати/Отримати»** (`/relocations`), з урахуванням вибраної локації та періоду. Саме ці вкладки користувач уточнив як «Історію переміщень».

## Що вже перевіряють автотести

**Часткове, суміжне покриття:**

- `RelocationExtendedTest.testExportRelocations` / `TC-REL-006` викликає `RELOCATION_GET_EXPORT` з `senderIds`, перевіряє `200`, `octet-stream` і ненульову довжину. Він не відкриває XLSX і не перевіряє жодної клітинки.
- `RelocationBatchAccountingTest.accountingRowsKeepJournalInventoryAndExportsConsistent` / `TC-REL-ACC-019` створює отримання з двома бухгалтерськими рядками того самого ресурсу, читає журнал і залишок, а для експорту з `receiverIds` перевіряє лише `200` та ненульову довжину. Назва тесту не означає, що вміст Excel порівняно з журналом.
- `RelocationExtendedTest` / `TC-REL-B01…B07` перевіряє списання, передачу, редагування та зарахування партій. `TC-REL-B03` створює два рядки з різними партіями **різних ресурсів**. Це корисні передумови для нових кейсів, але в них немає перевірки експорту і немає сценарію «один ресурс, три партії».
- `InventoryBatchTechMapApiTest` / `TC-WMS-011-001` перевіряє `techmap{id,name}` для вироблених партій, `null` для зовнішньої партії й правило останнього виробництва за однакового номера. `InventoryBatchTechMapUiTest` / `TC-WMS-011-002…005` перевіряє колонку та `-` у попапі «Залишки». Це підтверджує джерело й UI-представлення зв'язку партія ↔ техкарта, **але не його перенесення в Excel переміщень**.
- `XlsxWorkbookReader` уже читає аркуші, рядки й числові колонки; його можна використати для предметних перевірок XLSX. `ResourceViewerExportApiTest` і `ResourceViewerUiTest` перевіряють інший endpoint (`/api/v1/resources-viewer/export`) та інший екран. Вони не є покриттям цієї фічі.

**На момент початкового аудиту прямого покриття нових вимог не було.** Воно додане в `RelocationBatchTechMapExportTest` і `RelocationBatchTechMapExportUiTest`; dev-прогін API виявив помилку кількості в партійних рядках. Наявність endpoint і перевірка ненульових байтів у старих тестах не доводили ні колонки, ні розбиття рядків, ні значення техкарти, ні роботу обох вкладок.

## Нові тест-кейси

Пріоритет **P0** — приймання фічі; **P1** — регресія та крайові умови. `001–006` автоматизовані; `007–011` лишаються планом. Кожний API-кейс читає XLSX як workbook і звіряє рядки за унікальними даними тесту, а не шукає текст у ZIP. Кількості порівнюються як числа.

1. **TC-REL-XLS-001 · P0 · API · Структура файлу.** Експорт одного контрольного переміщення. Перевірити валідний XLSX, рівно одну колонку «Партія» й одну «Тех карта», їхній порядок відносно «Одиниця виміру» та «№ накладної», збереження наявних заголовків і значень. Числовий тип клітинки «Кількість» додати як окрему перевірку формату після стабілізації основної фічі.
2. **TC-REL-XLS-002 · P0 · API · Один ресурс, три партії.** Підготувати партії 5, 2, 8 одного ресурсу, перші дві від техкарти A, третю від B; явно створити переміщення 15 із цими партіями та унікальним № накладної. У файлі для цього переміщення рівно три рядки з парами `(партія, кількість, техкарта)` = `(A1,5,A)`, `(A2,2,A)`, `(B1,8,B)`. У всіх трьох рядках збережені назва, одиниця й № накладної; сума = 15. Не покладатися на порядок рядків, якщо він не визначений вимогою.
3. **TC-REL-XLS-003 · P0 · API · Різні ресурси та ізоляція.** Одне переміщення з двома ресурсами: вироблений продукт має три партії, другий ресурс — одну. Поруч існує інше переміщення того самого продукту. Перевірити чотири очікувані рядки цільового переміщення та відсутність змішування номерів партій між ресурсами.
4. **TC-REL-XLS-004 · P0 · API · Партія без техкарти.** Створити зовнішнє отримання з невиробленою партією поруч із виробленими партіями цього ресурсу. Експорт не падає; номер і кількість зовнішньої партії правильні; її техкарта порожня або позначена `-` і не підтягує карту виробленої партії.
5. **TC-REL-XLS-005 · P0 · UI · «Отримано».** На `/relocations` з унікальним зовнішнім отриманням виконати експорт кнопкою вкладки, дочекатися завантаження та перевірити в XLSX нові заголовки, тестову партію і її кількість 4.
6. **TC-REL-XLS-006 · P0 · UI · «Видано».** На `/relocations` видати 2 одиниці з отриманої партії, відкрити вкладку «Видано», експортувати XLSX і перевірити нові заголовки, ту саму партію та кількість 2. Зафіксувати запити обох вкладок і відповідність вибраної локації та періоду файлу. Предметну перевірку трьох партій і двох техкарт виконує API-кейс `002`.
7. **TC-REL-XLS-007 · P1 · API/UI · Стани й напрямки.** Перевірити видачу «В дорозі», завершену видачу «Видано» та «Отримано» (у межах того, що експортується відповідною вкладкою). Кожна сторона бачить власні дозволені переміщення, а партійний склад, кількість і техкарта не губляться після приймання. Включити зовнішнє отримання від постачальника як окремий тип операції.
8. **TC-REL-XLS-008 · P1 · API · Фільтри й пагінація.** Додати сторонні переміщення/ресурси та кілька сторінок журналу. Експорт із фільтрами локації, періоду та ресурсу містить усі й лише відфільтровані переміщення, кожне розгорнуте за партіями один раз. Порівняти набір ID/накладних з API журналу з урахуванням того, чи експорт має охоплювати всі сторінки.
9. **TC-REL-XLS-009 · P1 · API · Історична техкарта.** Після виготовлення й переміщення деактивувати або перейменувати техкарту; для двох техкарт із тим самим номером партії окремо перевірити правило вибору. Очікувану семантику експорту (назва на час виробництва чи актуальна назва; правило для неоднозначного номера) слід затвердити до написання асерту. Не можна визначати техкарту лише за текстом номера без ідентичності партії/виробництва.
10. **TC-REL-XLS-010 · P1 · API · Межі даних.** Одна партія, дробова кількість і партія, для якої номер відсутній у legacy-записі, якщо такий запис можливий. Перевірити коректний підсумок, відсутність порожнього дублюючого рядка та узгоджений формат невідомої партії. Довгу назву техкарти й кирилицю перевірити без втрати символів.
11. **TC-REL-XLS-011 · P1 · API · Доступ.** Для ролі з доступом лише до своєї локації експортувати її переміщення; стороння локація та її партії/техкарти не потрапляють до файлу. Цей кейс потрібен, якщо endpoint приймає ширші `senderIds`/`receiverIds`, ніж дозволяє UI.

## Порядок автоматизації

1. `001–004` реалізовані як API-контракт для `RELOCATION_GET_EXPORT`. Фікстура створює унікальні ресурси, партії, дві техкарти та переміщення з явними UUID партій.
2. `005–006` реалізовані як UI-кейси із читанням завантаженого XLSX з вкладок «Отримано» та «Видано» сторінки `/relocations`.
3. Додати `007–011` після погодження наведених нижче контрактних питань. Реалізовані тести внесені до `relocations`, `regression` та `ui`.

## Питання до продукту/розробки перед точними асертами

- Заголовок у файлі: **«Тех карта»** за цією вимогою чи **«Техкарта»** як у попапі? Який точний порядок усіх колонок і чи в усіх аркушах однакова структура?
- Яке Excel-значення для партії без виробництва та для legacy-переміщення без збереженого номера партії: порожня клітинка, `-` чи інший маркер?
- Чи експорт відображає історичну назву техкарти на момент виробництва, чи поточну назву? Якщо однаковий номер партії має кілька виробництв, чи правило «останнє виробництво» з попапа застосовується й тут?
- Чи має експорт повертати всі відфільтровані записи незалежно від пагінації таблиці, і як відображати повернення/скасування та часткову доставку?

## Межа початкового аудиту

Початковий висновок «немає прямого покриття» стосувався стану репозиторію до додавання тестів. Поточні результати dev-прогону наведено в окремому звіті. Наявні локальні незбережені зміни в інших файлах збережено.
