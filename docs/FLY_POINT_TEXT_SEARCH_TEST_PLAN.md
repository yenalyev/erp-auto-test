# Пошук точки вильоту за текстом — план перевірки

## Обсяг

Текстовий пошук у селекторі точки вильоту на двох формах:

- **«Видача на екіпаж»** (`/relocation/create-output-crew`);
- **«Отримання з точки вильоту»** (`/relocation/create-input-crew`).

Пошук працює всередині відкритого ієрархічного списку точок. Введений текст фільтрує вже завантажені варіанти за назвою; вибір точки залишається звичайною дією форми. Пошук не створює переміщення і не змінює залишки.

## Критерії перевірки

1. На обох формах у відкритому селекторі є поле `Пошук...`.
2. Частина назви залишає відповідну точку в списку і приховує точку, яка не збігається. Регістр літер не впливає на збіг.
3. Якщо збігів немає, список показує `Нічого не знайдено`.
4. Очищення поля знову показує всі доступні варіанти.
5. Після вибору результату назва точки відображається у полі форми.
6. Ієрархія зберігає батьківський вузол для знайденої дочірньої точки; збіг за назвою батьківського вузла залишає його дочірні точки.

## Дані та середовище

Для автоматизованих UI-сценаріїв потрібні дві точки з різними назвами в одному підрозділі. Тести створюють базовий сценарій `attachedScenario`, а відповідь `GET /api/v1/storages/names/crew-units` підміняють локальним деревом із реальною точкою цього сценарію та другим контрольним варіантом. Це робить перевірку клієнтського фільтра незалежною від поточних прав тестового користувача на dev. API-права на перегляд точок і фактичну операцію видачі чи отримання ці два тести не перевіряють.

## Покриття

| Сценарій | TestCaseId | Автотест |
|---|---|---|
| Видача на екіпаж | `TC-UI-CREW-029` | `CrewIssuanceUITest.testFlyPointTextSearchInCrewIssuance` |
| Отримання з точки вильоту | `TC-UI-CREW-RET-004` | `CrewReturnUITest.searchFlyPointByTextInCrewReturn` |

Обидва автотести перевіряють наявність поля, частковий збіг, відсутність збігу, очищення та вибір. Перевірки різного регістру й фільтрації за назвою батьківського вузла залишені для окремого розширення покриття.

Детальні кроки: [FLY_POINT_TEXT_SEARCH_TEST_CASES.md](FLY_POINT_TEXT_SEARCH_TEST_CASES.md).

## Запуск

```powershell
mvn -q '-Denv=dev' '-Dtest=CrewIssuanceUITest#testFlyPointTextSearchInCrewIssuance,CrewReturnUITest#searchFlyPointByTextInCrewReturn' '-Dtcm.enabled=false' '-Dgoogle.sheets.enabled=false' test
```

Інтеграції TCM і Google Sheets вимкнені лише для локального запуску. Результат перевірки — два пройдені UI-тести; якщо підготовка `attachedScenario` недоступна, помилку слід розглядати окремо від роботи текстового фільтра.
