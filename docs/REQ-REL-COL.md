# REQ-REL-COL — Експорт даних → Переміщення: колонки

## Контракт

Екран `/export-analytics`, тип «Переміщення», кнопка «Експорт в Excel».
Запит `GET /api/v1/export-analytics/export-relocation?start=YYYY-MM-DD&end=YYYY-MM-DD`.
Актуальний UI додатково передає `include_batches=false`; API за замовчуванням також агрегує партії.
На dev аркуш `Переміщення`, відправник має підпис «Відправник» (поле «Видав» у вимозі).
Цей експорт має один рядок на позицію ресурсу переміщення;
партії всередині позиції не створюють додаткових рядків. Детальний Excel журналу
`/api/v1/relocations/export` має іншу деталізацію і не є предметом цих перевірок.

- **AC-01:** Група відправника розташована відразу після Відправник (Видав у вимозі); Отримувач → Група отримувача → Тип отримувача йдуть поспіль. Старі поля збережені; кожен заголовок унікальний. На dev усі 20 колонок: ID; Надіслано; Отримано; Відправник; Група відправника; Отримувач; Група отримувача; Тип отримувача; Категорія; Назва; Кількість; Одиниця виміру; Накладна; Статус; Примітки; Постачальник; Тип БЧ; Тип Носія; Завод; Вага. Стара колонка Тип отримувача з групою перейменована, нова містить kind.
- **AC-02:** Тип отримувача відповідає kind саме отримувача: LOCATION → Локація, FLY_POINT → Точка вильоту, CREW → Екіпаж. Тип і група не підміняють одне одного.
- **AC-03:** Група отримувача визначається ієрархією саме отримувача. Погоджені 22.10.2026 точні значення: ПМ без Цукрарня, СБС без ПМ, Цукрарня, Інші. Правило перевіряється для всіх трьох kind.
- **AC-04:** Група відправника визначається ієрархією саме відправника. Погоджені 22.10.2026 точні значення: ПМ без Цукрарня, СБС без ПМ, Цукрарня, Інші. Відправник і отримувач різних груп не обмінюються значеннями.
- **AC-05:** Excel відповідає повним вкладкам Видано й Отримано за той самий період: ті самі позиції, кількості, назви, категорії, статуси. Кілька партій ресурсу не множать рядки; два різні переміщення з однаковими видимими полями залишаються двома записами. Повторний експорт стабільний.
- **AC-06:** Період у UI передається як start/end із include_batches=false для агрегації позицій; включний поточний день містить контрольні переміщення, наступний день їх не містить. Реальний UI завантажує читабельний XLSX з тим самим контрактом.

## Дані й незалежне очікування

`RelocationExportColumnsFixture` створює лише власні локації та два унікальні ресурси.
Одна позиція містить дві партії 1.25 + 2.5 = 3.75, друга — 4.75.
Базовий набір: три kind та повторна передача на першу локацію, 4 переміщення / 8 позицій.
Матриця: 4 групи × 3 kind, відправник завжди іншої групи, 12 переміщень / 24 позиції.
Матриця читає PostgreSQL (`storage`, `business_unit_filter`, `cukrarnia_storage`) через
`RemainderExportParents`; SQL нічого не змінює. Налаштування груп залишаються спільними.
Без JDBC два групові кейси явно SKIP, це не вважається підтвердженням груп.

Oracle для дублів: сторінки API, які живлять вкладки «Видано» та «Отримано», читаються
до кінця з size=2; порівнюються ID переміщень між перспективами й очікуваними ID.
Потім позиції розгортаються в multiset (ID переміщення, відправник, отримувач, ресурс, кількість),
тож зайві рядки, пропуски та видалення легітимного однакового запису дають FAIL.
UI додатково перевіряє видимі кількості та 4/2 записи на власних робочих локаціях.
XLSX і скриншоти додаються до Allure. Dev забороняє видалення завершеної історії.
Cleanup обнуляє та видаляє власні рядки залишків, архівує ресурси й локації;
завершені переміщення залишаються в історії, їхні ID додаються до Allure.
Помилки cleanup не приховуються.

## Тест-кейси

### TC-REL-COL-API-001 — Назви та точний порядок колонок [AC-01]
1. Експортувати поточний день як ADMIN.
2. Відкрити аркуш Переміщення і порівняти всі заголовки.
Очікування: Всі 20 актуальних колонок збережені й унікальні; нові групи та kind розташовані у погодженому порядку.

### TC-REL-COL-API-002 — Kind отримувача в кожному рядку [AC-02]
1. Створити завершені передачі на LOCATION, FLY_POINT і CREW.
2. Експортувати день і знайти позиції за власними відправниками, отримувачами й ресурсами.
Очікування: Тип отримувача дорівнює Локація, Точка вильоту або Екіпаж саме для відповідної локації.

### TC-REL-COL-API-003 — Групи отримувача для матриці 4 × 3 [AC-03]
1. Прочитати поточні корені груп через read-only JDBC; створити по три kind у кожній групі.
2. Передати два ресурси з іншої групи й перевірити Група отримувача в кожній позиції Excel.
Очікування: Всі 24 позиції мають точні ПМ без Цукрарня, СБС без ПМ, Цукрарня або Інші за ієрархією отримувача.

### TC-REL-COL-API-004 — Група відправника незалежна від отримувача [AC-04]
1. Використати матрицю різних груп відправника й отримувача.
2. Перевірити Група відправника для кожного ресурсу кожної передачі.
Очікування: Всі 24 позиції мають групу відправника: ПМ без Цукрарня, СБС без ПМ, Цукрарня або Інші.

### TC-REL-COL-API-005 — Регресія дублів і звірка обох вкладок [AC-05]
1. Створити чотири завершені передачі, включно з двома однаковими за отримувачем і кількостями.
2. Прочитати всі сторінки Видано й Отримано з size=2 та порівняти ID і позиції.
3. Двічі експортувати той самий період; порівняти multisets позицій і кількості.
Очікування: Обидва Excel містять рівно 8 позицій; дві партії дають одну позицію 3.75; легітимні однакові передачі збережені, кількості й категорії відповідають журналу.

### TC-REL-COL-API-006 — Включний період та виключення сусіднього дня [AC-06]
1. Експортувати start=end=сьогодні для чотирьох контрольних передач.
2. Експортувати start=end=завтра.
Очікування: Сьогодні є всі 8 позицій, завтра жодної контрольної позиції; порядок колонок збережений.

### TC-REL-COL-UI-001 — Реальний download із Експорт даних [AC-06]
1. Як ADMIN відкрити Експорт даних, вибрати Переміщення й поточний день.
2. Натиснути Експорт в Excel; перевірити GET, точні start/end, include_batches=false та файл .xlsx.
3. Прочитати завантажений файл і порівняти заголовки, kind та позиції з обома журналами.
Очікування: Реальний XLSX містить правильні 20 колонок, три kind та рівно 8 контрольних позицій.

### TC-REL-COL-UI-002 — Звірка видимих Видано й Отримано з Excel [AC-05]
1. Відкрити Видано за сьогодні, вибрати власного відправника через Від кого: звірити 4 записи й кількості 3.75/4.75.
2. Відкрити Отримано, вибрати власного LOCATION отримувача через Кому: звірити 2 окремі записи з кількостями 3.75/4.75.
3. Завантажити глобальний Excel за сьогодні й порівняти позиції з повними API-списками обох вкладок.
Очікування: Кількості та записи в обох UI-вкладках збігаються з Excel, два однакові переміщення не зливаються.
