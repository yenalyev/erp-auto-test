# REQ-ALERT — сповіщення про поріг залишків

## Призначення

На `/alerts/{storageId}` користувач із доступом до локації переглядає та
зберігає пороги залишків ресурсів. На `/inventory?storageId={storageId}`
ресурс із налаштованим порогом має відображати свій стан і мінімум. Це окрема
функція від персональних підписок у `REQ-NOTIF`.

## Автоматизоване покриття

- `TC-ALERT-005` (`AlertOwnerSaveApiTest`) — динамічно створений керівник
  локації створює та оновлює власний поріг через `POST /api/v1/alerts` і
  `PUT /api/v1/alerts/{id}`; відповіді мають бути успішними, без `403`.
- `TC-UI-ALERT-004` (`AlertOwnerSaveUiTest`) — той самий тип динамічного
  користувача натискає «Зберегти» на `/alerts/{storageId}`; запит має
  завершитися успішно, а повідомлення про помилку не з'являється.
- `TC-ALERT-004` (`AlertStorageTypeApiTest`) — для `STORAGE`, `UNIT`,
  `PRODUCTION`, `CREW` і `FLY_POINT` API повертає збережений поріг, стан
  нульового залишку та порядок рядків за пріоритетом алерту.
- `TC-UI-ALERT-003` (`AlertStorageTypeUiTest`) — для тих самих типів UI
  показує ресурс, бейдж, мінімум і налаштований поріг на сторінці алертів.

Тести створюють локації, ресурси та користувачів під час запуску й очищають
їх після нього. Для перевірки нульового залишку фікстур спочатку створює
рядок ресурсу із запасом, а потім обнуляє його. UI-тест вмикає «Показувати
нульові залишки» і чекає, доки обидва тестові ресурси з'являться в таблиці.
Для `CREW` і `FLY_POINT` тестовий комірник має доступ до дочірньої локації
та її батьківської `UNIT`, яка є його робочим простором.

## Відомий дефект: `/alerts/{id}` для `CREW` і `FLY_POINT`

**Кроки:** створити `UNIT` із дочірньою `CREW` або `FLY_POINT`, налаштувати
для дочірньої локації поріг ресурсу та відкрити
`/alerts/{childStorageId}` користувачем із доступом до обох локацій.

**Фактично:** URL містить ID дочірньої локації, але заголовок і список
сповіщень належать батьківській `UNIT`. Налаштований ресурс відсутній.
Водночас `GET /api/v1/alerts/storage/{childStorageId}` повертає поріг, а
`/inventory?storageId={childStorageId}` відображає його біля ресурсу.

**Очікувано:** `/alerts/{childStorageId}` показує назву, ресурси та пороги
саме дочірньої локації. Перевірки `TC-UI-ALERT-003` для обох типів
залишаються активними й завершуються помилкою до виправлення сторінки.
