# REQ-REL-SUPPLIER — фільтр «Постачальник» на «Видати/Отримати»

## Призначення та контракт

У спільній панелі вкладок **В дорозі, Видано, Отримано, Втрачено** додано мультиселектор
«Постачальник». Він використовує **актуальну властивість ресурсу** з назвою `Постачальник`.
Це окремий критерій від «Від кого»: зовнішній постачальник як локація-відправник не визначає
значення властивості ресурсу.

Поле доступне в режимі «Ресурси», коли в `category_property_options` налаштовані значення
для «Постачальник». Опції надходять із AppConfig, є пошук і вибір кількох значень.
Початковий вибір порожній, placeholder — «Усі». Пошук опцій не змінює саму вибірку вантажу.

API використовує `suppliers=МОУ&suppliers=Інші` (UI також може серіалізувати масив як `suppliers[]`):

- `GET /api/v1/relocations` — список та метадані пагінації;
- `GET /api/v1/relocations/totals` — підсумки повної вибірки;
- `GET /api/v1/relocations/export` — Excel повної вибірки.

Значення одного поля поєднуються як OR; інші критерії — AND, причому постачальник,
категорія й виріб мають збігатися **для тієї самої позиції**. Список і Excel показують лише
відповідні позиції змішаного вантажу. Ресурс без цієї властивості не відповідає непорожньому
фільтру. Невідоме значення дає порожню вибірку. Без `suppliers` ресурс без властивості доступний.
Наявність кількох позицій у переміщенні не повинна дублювати переміщення.

Стани вкладок: CREATED/CANCELLED; FINISHED/AUTO_FINISHED/RETURNED для історії; LOST.
`fromIds`, `toIds`, `startDate`, `endDate`, `category`, `productIds` зберігають чинну семантику.
Дата — дата відправки. Для обладнання UI не передає `suppliers`; після повернення до ресурсів
вибір відновлюється. При повному перевідкритті сторінки вибір постачальників не зберігається.

## Критерії приймання

- **AC-01.** У ресурсному режимі кожної вкладки є «Постачальник» з опціями AppConfig, пошуком і порожнім початковим вибором. Пошук підтримує позитивний та негативний результат без дублів опцій.
- **AC-02.** Один постачальник відбирає точні позиції за властивістю ресурсу, кілька — OR. Ресурси іншого постачальника й без властивості виключені; невідоме значення дає порожню вибірку. Локація-відправник не підміняє властивість ресурсу.
- **AC-03.** Постачальник AND категорія AND виріб застосовуються до тієї самої позиції; напрямки, дата й стани обмежують результат. Порожній перетин не показує переміщення або сторонні позиції.
- **AC-04.** Метадані пагінації рахують лише відповідні переміщення, сторінки не дублюються. Підсумки охоплюють усі сторінки й лише відповідні позиції, без ресурсу без властивості.
- **AC-05.** Справжній Excel містить повний відфільтрований вантаж з правильними кількостями й актуальними станами вкладки, незалежно від page/size. Порожній результат не містить сторонніх даних.
- **AC-06.** Видалення одного chip залишає інші вибрані значення. Видалення останнього прибирає suppliers зі списку, підсумків і експорту та відновлює ресурси без властивості. Перевідкриття сторінки очищає вибір.
- **AC-07.** Для обладнання поле приховане, suppliers відсутній у списку, підсумках і експорті. Повернення до ресурсів відновлює й застосовує попередній вибір; обладнання фільтрується незалежно.
- **AC-08.** Після зміни властивості ресурсу повторні список, підсумки та Excel використовують нове значення також для наявної історії; видалення властивості виключає ресурс із непорожнього фільтра. Сусідні ресурси незмінні.

## Дані, ізоляція та очищення

`RelocationSupplierFiltersFixture` використовує власні локації, дві категорії та три ресурси
наявної `RelocationFiltersFixture`: A1=2 од., категорія A, постачальник МОУ;
A2=3 од., категорія A, постачальник Інші; B1=5 од., категорія B, властивість відсутня.
Змішані переміщення створюються для CREATED, CANCELLED, FINISHED, RETURNED, LOST.
Є sibling-одержувач та інша дата як негативні контролі. Зовнішнє AUTO_FINISHED-надходження
від одного відправника містить усі три ресурси по 100 од. UI також готує дві моделі обладнання.

Зміна й видалення властивості виконується тільки на власному ресурсі, відновлення — `finally`.
GET ресурсу підтверджує фактично збережену властивість до перевірки журналу.
Cleanup успадковано: власні інциденти видаляються, активні передачі завершуються/повертаються,
власні залишки видаляються версійованою інвентаризацією, обладнання переводиться у RETIRED,
ресурси й локації архівуються, власні категорії видаляються.
Незмінна завершена історія та архівні сутності залишаються згідно з lifecycle ERP.
