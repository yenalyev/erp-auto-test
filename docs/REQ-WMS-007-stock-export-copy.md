# REQ-WMS-007 — Експорт залишків (з/без нулів) і копіювання в таблицю

Документація інкременту для QA / продукту / автотестів.  
TCM feature: **REQ-WMS-007** (модуль WMS).  
SSOT у репозиторії: цей файл.  
SUT: backend `tk`, frontend `tk-ui`. Автотести: `erp-auto-test`.

Базовий перегляд залишків (доступ, фільтри, «Всі локації», партії) лишається в існуючих AC-01…AC-08. Тут лише **два режими Excel** і **формат «Скопіювати»**.

---

## 1. Огляд

На `/inventory` потрібні два способи винести залишки для аналізу:

1. **Excel — без нульових рядків** (операційний зріз: лише те, що реально лежить).
2. **Excel — з нульовими рядками** (повна картина складу: вичерпані `StorageItem` теж у файлі).

Окремо: кнопка **«Скопіювати»** вставляє дані в Excel / Google Sheets так, щоб **кількість сортувалась як число**. Одиниця виміру (`шт`, `кг`, …) йде в **наступну колонку**, не в ту саму комірку (`12 шт` — заборонено).

### 1.1. UX (факт SUT)

Не окреме меню на кнопці експорту. Режим нулів — тогл **«Показувати нульові залишки»** (`showZeroStock`, за замовчуванням вимкнений):

- фільтрує таблицю;
- той самий прапорець іде в `GET /api/v1/export-analytics/inventory`.

«Нуль» = валовий `StorageItem.amount == 0`, не вільний залишок (`amount − booked`).  
Ресурс без `StorageItem` (ніколи не лежав на складі) у «експорті з нулями» **не з’являється**.

### 1.2. Терміни

| Термін | Значення |
|--------|----------|
| Нульовий рядок | `StorageItem` з `amount = 0` на конкретній локації |
| Вільний залишок | `amount − bookedAmount` (колонка «Всього» / буфер Copy) |
| Валовий залишок | `amount` (колонка Excel «Загальна кількість Залишок») |
| TSV | рядки буфера, колонки розділені `\t` |

## 2. API / UI контракт

### 2.1. Excel

| Метод | Path | Параметр |
|-------|------|----------|
| GET | `/api/v1/export-analytics/inventory` | `parentStorageId` — локація / ієрархія |
| GET | `/api/v1/export-analytics/inventory` | `locations=` — «Всі локації» / мультиселект |
| | | `showZeroStock` default `false` |
| | | також `searchTerm`, `categories`, `tags` |

Аркуш **«Залишок»**, колонки:

1. Назва складу  
2. Назва Виробу Залишок  
3. Загальна кількість Залишок (**число**)  
4. Заброньований Залишок (**число**)  
5. Одиниця Виміру  
6. Категорія  

Один рядок файлу = ресурс **на одній локації**. Без нулів рядок з `amount = 0` відсутній; з нулями — присутній з кількістю `0`.

Експорт забирає **всі сторінки** вибірки, не лише поточну сторінку UI.

Фреймворк: `EXPORT_INVENTORY_HIERARCHY_GET`, `InventoryFixture.exportRemaindersHierarchy` / `exportRemaindersByLocations`.

### 2.2. Таблиця та Copy

Тогл і Copy — `InventoryPage.tsx` (`showZeroStock`, `handleCopyTable`).

Буфер (після фіксу):

```text
<Назва>\t<Кількість>\t<Од. вимір.>
```

| Поле | Правило |
|------|---------|
| Кількість | лише число (вільний залишок по видимих локаціях), без `шт`/`кг` |
| Од. вимір. | `resource.unit.shortName` в **окремій** колонці |
| Склад / бронь / локації | Copy **не** дублює Excel; агрегат «Всього» |
| Пагінація | поточна сторінка `multiItems` |
| Порожня таблиця | кнопка disabled |

На екрані комірка може лишатися `12 шт` — вимога лише до **переносу кнопкою**.

## 3. Acceptance Criteria

### AC-09 — Excel: два режими нулів

Користувач з `inventory-list::read` отримує XLSX:

- без `showZeroStock` / `false` — немає рядків з `amount = 0`; ненульові на місці;
- `showZeroStock=true` — вичерпані `StorageItem` є з кількістю `0`;
- фільтри (пошук / категорія / теги / локації) застосовуються в **обох** режимах;
- кількість і бронь — числові комірки; одиниця — окрема колонка;
- чужі склади не витікають (RBAC як у TC-WMS-007-019).

UI: тогл вимкнений → файл без нулів; увімкнений → файл з нулями. Стан тогла на момент кліку.

### AC-10 — Copy: кількість і одиниця в різних колонках

Після «Скопіювати»:

- кожен рядок — мінімум 3 TSV-поля: назва, число, одиниця;
- заборонено `12 шт` (і будь-яка ОВ) в полі кількості;
- після вставки в таблицю сортування по кількості — числове (`2.5`, `12`, `100`);
- тогл нулів і пошук звужують буфер так само, як таблицю;
- фідбек «Скопійовано».
