# Аналітика → Для плану: категорія «Боєприпас» за замовчуванням

Вимога від 16.10.2026 належить до `REQ-PLAN-ANL`, AC-03. Під час відкриття `/analytics/plan`, зокрема через сайдбар, користувач одразу бачить вибрану категорію **Боєприпас**. Ресурс вручну вибирати не потрібно: таблиця та підсумки завантажуються автоматично за попередній повний календарний місяць.

ID категорії визначається за точною назвою з актуального довідника категорій. Тести не фіксують ID, кількість ресурсів або суму показників. Початковий запит `GET /api/v1/analytics/plan/rows` передає тільки ID цієї категорії в `categoryIds`, без `resourceIds`, з `fromDate` та `toDate` початкового періоду.

Користувач може прибрати категорію або замінити її іншою. Після очищення всіх категорій і ресурсів показано порожній стан; зміна періоду не вибирає «Боєприпас» повторно. Постачальник без категорій і ресурсів не запускає rows. Reload і повторне відкриття сторінки відновлюють початкову категорію; постачальник при цьому очищується. Період у межах відкритої сторінки не змінює поточний вибір категорій.

Excel одразу експортує вибірку «Боєприпас» за поточним періодом: усі сторінки, п'ять показників та окремі підсумки за одиницями. Після явного очищення вибору кнопка прихована.

Початковий вибір є поведінкою сторінки. Прямий rows API без `resourceIds/categoryIds` залишається порожнім, а прямий export API без вибору повертає весь каталог відповідно до погодженого контракту `REQ-PLAN-ANL-EXCEL` AC-04. Аналітика у візарді глобального плану й далі запитується для явно вибраного виробу.

## Автоматичне покриття

- `TC-PLAN-ANL-UI-001`: вхід через сайдбар із початковою категорією, місяць/3 місяці, ручний вибір ресурсу після очищення.
- `TC-PLAN-ANL-UI-008` (новий): реальний довідник, автоматичний rows, точний ID категорії, відсутність resourceIds, дати й категорії повернених рядків.
- `TC-PLAN-ANL-UI-009` (новий): очищення, зміна періоду без повторного дефолту, вибір іншої категорії, відновлення після reload/reopen.
- `TC-PLAN-ANL-UI-003/004/007`: перед незалежним вибором ресурсів явно прибирається початкова категорія.
- `TC-PLAN-ANL-UI-005`: постачальник очищується при reload/reopen, категорія відновлюється й rows завантажується.
- `TC-PLAN-ANL-UI-006`: після очищення категорії постачальник не запускає rows; після вибору ресурсу він застосовується.
- `TC-PLAN-ANL-XLSX-UI-001/002`: порожній стан та довільна категорія готуються через явне очищення дефолту.
- `TC-PLAN-ANL-XLSX-UI-003` (новий): завантажений початковий Excel порівнюється з повною вибіркою rows, видимими рядками та підсумками.
- `TC-PLAN-ANL-001`: API-контракт без фільтрів залишається окремою перевіркою.

Класи вже входять у `ui` та `regression`; нові методи запускаються разом із ними.

```powershell
mvn test -Denv=dev "-Dtest=PlanAnalyticsUiTest,PlanAnalyticsExcelExportUiTest" -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
```

Синхронізація TCM dev/prod оновлює документацію, критерії та кейси. Публікація в TCM prod не означає виконання на ERP production. Результати конкретного запуску фіксуються окремо у звіті перевірки.

## Перевірка на ERP dev 16.10.2026

Усі три нові сценарії пройшли на реальному backend. Початковий прогін двох UI-класів: 10 PASS із 11 методів; після виправлення підготовки стану тесту постачальника окремий повтор дав 1 PASS. Актуальний підсумок — 11 успішних методів, що відповідають 12 TCM-кейсам з урахуванням двох ID одного методу. Повний прогін після цього повтору не виконувався.

Склад вибірки, п'ять показників і підсумки початкового Excel звірено з усіма сторінками rows. Кількості ресурсів та ID категорії залежать від середовища. Докази й обмеження публікації прогонів наведені у [звіті перевірки](audits/2026-10-16/plan-analytics-default-category-dev-report.md).
