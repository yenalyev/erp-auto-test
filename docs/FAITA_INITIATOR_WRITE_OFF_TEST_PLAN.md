# Тест-план: ініціатори FAITA без списання

## Мета і критерій випуску

Підтвердити, що кожен зіставлений ініціатор іншого постачальника отримує `COMPLETED` без зміни залишку точки, а `ПМ Цукрарня` зберігає звичайне списання. Перед випуском потрібні перевірки імпорту FAITA, автоматичного процесу, API, залишків та відображення в журналі.

## Дані й метод

Ізольована точка вильоту й екіпаж; два окремі ERP-ресурси з властивістю `Постачальник` = `Інший постачальник` / `ПМ Цукрарня`; два FLIGHT-зіставлення `i-...`; унікальні `sourceId`. Порівнювати фактичні залишки до й після, статус конкретного запису та кількість завершених записів. Для наскрізної перевірки подію потрібно подавати через FAITA dev `/log`, запускати `/syncTeams`, потім чекати плановий auto-complete або викликати його тестовим тригером. Прямий INSERT готового write-off не перевіряє імпорт.

## Запуск автоматизованої частини

```powershell
mvn test '-Denv=dev' '-Dsuite=faita-initiators' '-Duse.database=true' '-Dauth.browser.disabled=true' '-Dtcm.enabled=false' '-Dgoogle.sheets.enabled=false'
```

`TC-001/002/003` створюють `PENDING` запис у БД і викликають `PUT /write-off/complete`. Це перевіряє правило сервісу завершення та облік залишку, але не запуск job і не імпорт з FAITA. На dev синхронізаційний cron у `tk/application-dev.yaml` вимкнений (`-`); для наскрізного прогону необхідний явний тригер `/syncTeams` і відомий спосіб запустити auto-complete. `auth.browser.disabled=true` перемикає runner на HTTP OAuth, бо Playwright-вхід на dev у поточному середовищі зависає. Нуль пропущених тестів є умовою зарахування прогону.
