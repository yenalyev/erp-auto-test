# Сортування ресурсів за датою зміни

Вимога `REQ-RES-SORT`, батьківська вимога `REQ-RES`.
Регресія дефекту «500 помилка — Ресурси — сортування по Змінено».

## Поведінка

У довіднику **Ресурси** натискання заголовка **Змінено** впорядковує ресурси
за датою останньої зміни. Перший клік показує давніші зміни першими, другий —
новіші першими, третій повертає початкове сортування за назвою.
Таблиця залишається доступною без серверної помилки.

Сортування працює у загальному каталозі та на конкретній локації з обмеженим
доступом до ресурсів. Активний пошук і пагінація застосовуються разом із
сортуванням. Порожня вибірка повертає порожній список без помилки.
Дата зміни враховує редагування ресурсу, а не лише його створення.

## Критерії приймання

- **AC-01.** Загальний каталог повертає HTTP 200 для обох напрямків
  сортування за датою зміни; порядок відповідає `updatedAt` кожного ресурсу.
- **AC-02.** Каталог обмеженої локації підтримує те саме сортування разом із
  пошуком та пагінацією. Сторінки утворюють правильну послідовність без
  пропусків і дублів для ресурсів із різними датами. Порожній результат має
  HTTP 200, порожній `content` і `totalElements=0`.
- **AC-03.** Кліки «Змінено» перемикають ASC, DESC та початковий порядок;
  видимі назви й дати відповідають серверним даним. Запити не повертають 5xx.

## Контракт API та фікс

`GET /api/v1/resources?sort=updated_at,ASC` і `sort=updated_at,DESC`.
Параметри `name`, `isActive`, `storageId`, `page`, `size` зберігають свою дію.
Відповідь містить `content` та метадані `page`; дата ресурсу — `updatedAt`
у форматі ISO 8601. UI відображає її як `dd.MM.yyyy HH:mm` у часовому поясі браузера.

`ResourceSort` зіставляє зовнішнє поле `updated_at` з `updatedAt`.
Native-запит `ResourceRepository.getPageByFiltersAndAccess` містить
`r.updated_at as updatedAt`, щоб сортування за цим псевдонімом працювало
також для обмеженого каталогу. Звичайний каталог використовує JPA-запит.

Однакові часові мітки не визначають взаємного порядку ресурсів;
контрольні дані мають різні мітки.

## Тест-кейси та автоматизація

Усі кейси: ACTIVE, HIGH, CRITICAL, REGRESSION; роль адміністратора.
Автоматизація використовує однойменні `@TestCaseId`.

Передумови: dev доступний; є одиниця виміру, категорія й батьківська локація.
Фікстура створює три власні ресурси у порядку C, B, A, змінює примітку C
після створення A та перевіряє різні `updatedAt`. Очікуваний порядок дат —
B, A, C. Для обмеженого каталогу створює локацію `REGIONS`, регіон `RESOURCES`
та надає йому лише ці три ресурси. Залишки й переміщення не потрібні.

### TC-RES-SORT-API-001

**Мета:** загальний каталог, AC-01.

1. Виконати GET із `name=<унікальний маркер>`, `isActive=true`, `page=0`,
   `size=10`, `sort=updated_at,ASC`, без `storageId`.
   Очікується HTTP 200, JSON, рівно три ресурси B, A, C із початковими ID
   та часовими мітками; `page.totalElements=3`.
2. Повторити з `sort=updated_at,DESC`.
   Очікується HTTP 200 і точний зворотний порядок C, A, B.

Автотест: `ResourceModifiedSortApiTest.sortsGlobalCatalogByModificationTime`.

### TC-RES-SORT-API-002

**Мета:** обмежений каталог і native SQL, AC-02.

1. Для створеної локації з `name=<маркер>` та `isActive=true` послідовно
   прочитати сторінки 0, 1, 2 із `size=1`, `sort=updated_at,ASC`.
   Кожна відповідь — HTTP 200, один ресурс, `totalElements=3`, `totalPages=3`.
   Об'єднані ID та дати точно відповідають B, A, C.
2. Повторити із DESC; очікується C, A, B без пропусків або повторів.
3. Для кожного напрямку шукати `<маркер>-missing`.
   Очікується HTTP 200, `content=[]`, `totalElements=0`.
4. Прибрати `sort`, знову шукати маркер, `size=10`.
   Очікується HTTP 200 та початковий порядок за назвою.

Автотест: `ResourceModifiedSortApiTest.sortsRestrictedCatalogAcrossPagesAndFilters`.

### TC-RES-SORT-UI-001

**Мета:** відтворення дій користувача, AC-03.

1. Увійти адміністратором, обрати підготовлену обмежену локацію,
   відкрити `/resources` і знайти три ресурси за маркером.
2. Натиснути «Змінено». Очікується запит `sort=updated_at,ASC`, HTTP 200,
   порядок B, A, C; видимі дати відповідають API та часовому поясу браузера.
3. Натиснути ще раз. Очікується `sort=updated_at,DESC`, HTTP 200,
   порядок C, A, B та правильні дати.
4. Натиснути втретє. Очікується запит без `sort`, HTTP 200 та порядок за назвою.
   Упродовж сценарію жоден GET списку ресурсів не повертає 5xx.

Автотест: `ResourceModifiedSortUiTest.modifiedHeaderSortsBothDirectionsAndResets`.
Allure зберігає фактичні JSON-відповіді та скріншоти ASC, DESC і скидання.

## Запуск та очищення

```powershell
mvn test -Denv=dev -Dsuite=resource-modified-sort -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
```

API-клас входить також до `functional` і `regression`, UI-клас — до `ui`
та `regression`. Після класу фікстура видаляє власний регіон, архівує власну
локацію й деактивує три власні ресурси. Помилка очищення провалює конфігурацію.
