## Інвентаризація ресурсу зі сповіщенням по залишках

Налаштований для ресурсу й локації поріг зберігається після проведення інвентаризації (`PUT /api/v1/storages/{id}/inventory`). Поточна кількість визначає `weight` у відповіді залишків; саму конфігурацію сповіщення інвентаризація не змінює.

- Якщо ресурс із додатним залишком вилучено з повного snapshot інвентаризації, його залишок стає `0`. Поріг залишається, `weight=100`, а нульовий рядок видимий у hierarchy API при `showZeroStock=false`.
- Якщо кількість змінено з `4` на `25` при порозі `10`, `weight` змінюється з `60` на `40`, а `alertLimit` та запис у `GET /api/v1/alerts/storage/{id}` залишаються рівними `10`.
- Якщо ресурс має сповіщення, але ще не мав залишку, додавання `4` через інвентаризацію змінює `weight` зі `100` на `60`; поріг `10` зберігається.

Критерій `AC-07`; автоматизовані API-кейси: `TC-ALERT-007` (вилучення), `TC-ALERT-008` (зміна кількості), `TC-ALERT-009` (додавання). Dev ERP, 03.10.2026: 3 passed, 0 failed, 0 skipped. Публікація документації в production TCM не означає прогін на production ERP.
