## Інвентаризація ресурсу зі сповіщенням по залишках

При зміні або додаванні кількості через інвентаризацію (`PUT /api/v1/storages/{id}/inventory`) налаштований для ресурсу й локації поріг зберігається, а поточна кількість визначає `weight`. Якщо користувач вилучає вже нульовий ресурс із повного snapshot, запит має завершитися без HTTP 500, а бекенд зберігає нульовий inventory-рядок, необхідний для активного сповіщення.

- Якщо ресурс має збережений `StorageItem` з `amount=0` і налаштований поріг, вилучення ресурсу з повного snapshot інвентаризації не повертає HTTP 500. Повторний GET повертає ресурс із `amount=0` і тим самим `alertLimit`.
- Якщо кількість змінено з `4` на `25` при порозі `10`, `weight` змінюється з `60` на `40`, а `alertLimit` та запис у `GET /api/v1/alerts/storage/{id}` залишаються рівними `10`.
- Якщо ресурс має сповіщення, але ще не мав залишку, додавання `4` через інвентаризацію змінює `weight` зі `100` на `60`; поріг `10` зберігається.

Критерій `AC-07`; автоматизовані кейси: `TC-ALERT-007` (API: вилучення нульового залишку зі snapshot), `TC-UI-ALERT-008` (та сама дія через UI), `TC-ALERT-008` (зміна кількості), `TC-ALERT-009` (додавання). Оновлені `TC-ALERT-007` і `TC-UI-ALERT-008` успішно пройшли на dev 05.10.2026. Публікація документації в production TCM не означає прогін на production ERP.
