# REQ-WMS-011 — Техкарти в попапі партій ресурсу

Специфікація фічі для продукту, QA і автотестів.
TCM feature: **REQ-WMS-011** (модуль WMS).
SSOT у репозиторії: цей файл.
SUT: backend `tk`, frontend `tk-ui`. Автотести: `erp-auto-test`.

---

## 1. Feature

На сторінці `/inventory` користувач клікає по залишку ресурсу й відкриває попап
**«Партії ресурсу»**. Попап показує, за якою технологічною картою виготовлена кожна
партія, і дозволяє локально відфільтрувати рядки за однією або кількома техкартами.

Фільтр діє лише всередині відкритого попапа. Він не змінює основну таблицю залишків,
не виконує нового серверного пошуку і не зберігається після закриття.

### 1.1. Бізнес-правила

1. Колонка **«Техкарта»** розташована одразу після **«Номер партії»**.
2. Довга назва техкарти переноситься всередині комірки й не розширює попап за межі layout.
3. Якщо техкарти немає, у рядку відображається `-`.
4. Якщо одна партія пов'язана з двома або більше виробництвами за різними техкартами,
   відображається техкарта останнього за часом створення виробництва.
5. Над таблицею відображаються клікабельні інфочіпи:
   `<назва техкарти> (<залишок> <одиниця вимірювання ресурсу>)`.
6. UI групує техкарти за відображуваною назвою, а не за `id`. Декілька техкарт із
   різними `id`, але однаковою назвою, утворюють один чіп.
7. Залишок у чіпі — сума `amount` усіх видимих ненульових партій техкарт із цією
   назвою на локації/локаціях, з яких сформовано відкритий попап.
8. Партії без техкарти утворюють окрему групу й чіп `- (<залишок>)`.
9. Якщо у всіх партій одна назва техкарти (навіть коли `id` відрізняються), чіпи не показуються.
10. Якщо всі партії без техкарти, чіпи не показуються.
11. Якщо груп більше однієї, показуються всі групи, включно з `-`.
12. Клік по чіпу вмикає фільтр і візуально виділяє чіп; повторний клік вимикає його.
13. Кілька активних чіпів працюють як **OR**: рядок показується, якщо його група серед
    обраних.
14. Коли активних чіпів немає, показуються всі партії.
15. Закриття попапа очищує вибір. Повторне відкриття завжди починається без фільтра.

## 2. Контракт даних

UI завантажує партії через:

```text
GET /api/v1/storage-items/batches?storageId={storageId}&resourceId={resourceId}
```

Релевантна частина елемента відповіді:

```json
{
  "id": 123,
  "amount": 5,
  "batchNumber": "LOT-001",
  "isProduced": true,
  "techmap": { "id": 17, "name": "Техкарта виробу" },
  "storage": { "id": 10, "name": "Склад" }
}
```

`techmap` nullable. За відсутності зв'язку API повертає `null`, а UI перетворює його на
відображення `-` та ключ фільтра `none`.

Для неоднозначної партії backend обирає техкарту останнього за часом створення
виробництва. Новіше виробництво з тим самим номером партії замінює попередню техкарту
у відповіді попапа.

## 3. Acceptance Criteria

### AC-01 — Колонка та перенос назви

- у заголовку таблиці порядок: `Локація` → `Номер партії` → `Техкарта`;
- значення техкарти відповідає партії;
- довга назва має дозволений перенос (`white-space: normal` або еквівалентний layout).

### AC-02 — Відсутня та неоднозначна техкарта

- `techmap = null` відображається як `-`;
- для двох або більше техкарт тієї самої партії API повертає карту останнього виробництва;
- зовнішня партія без виробничого процесу не отримує техкарту іншої партії/ресурсу.

### AC-03 — Склад і видимість інфочіпів

- дві чи більше різні групи за назвою → по одному чіпу на групу;
- одна назва техкарти в усіх партіях → жодного чіпа, навіть якщо `id` техкарт різні;
- усі партії без техкарти → жодного чіпа;
- суміш з техкартою і без неї → є звичайний чіп `-`.

### AC-04 — Текст та сума чіпа

- формат: `<назва> (<сума amount> <одиниця>)`, для null — `- (<сума amount> <одиниця>)`;
- сума агрегує всі партії групи, зокрема партії техкарт із різними `id` та однаковою назвою;
- після суми відображається одиниця вимірювання відкритого ресурсу (`шт`, `кг`, `л` тощо);
- формат числа та скорочення одиниці узгоджені з відображенням залишку ресурсу на `/inventory`.

### AC-05 — Один чіп і повторний клік

- перший клік залишає в таблиці лише партії групи;
- активний чіп має виділений стан;
- повторний клік знімає стан; якщо інших активних чіпів немає, повертаються всі рядки.

### AC-06 — Мультивибір OR

- можна активувати кілька чіпів;
- таблиця містить union партій активних груп;
- партії неактивних груп відсутні;
- деактивація одного чіпа не скидає решту.

### AC-07 — Життєвий цикл фільтра

- закриття попапа очищує всі активні чіпи;
- повторне відкриття показує всі партії;
- стан не переноситься на інший ресурс і не зберігається після навігації.

### AC-08 — Однакові назви різних техкарт

- ключ UI-групи — відображувана назва техкарти, а не її `id`;
- техкарти з різними `id` та однаковою назвою дають рівно один чіп;
- сума чіпа включає партії всіх таких техкарт;
- клік по чіпу показує партії всіх `id`, об'єднаних цією назвою;
- якщо це єдина назва серед усіх партій, чіпи не відображаються.

## 4. Тест-кейси

| ID | AC | Шар | Передумови та перевірки |
|----|----|-----|-------------------------|
| TC-WMS-011-001 | AC-02 | API | Дві техкарти одного output; окремі партії A/B, зовнішня партія та спільний номер. Перевірити `techmap{id,name}`, `null` і вибір техкарти останнього виробництва для спільної партії. |
| TC-WMS-011-002 | AC-01, AC-02, AC-03, AC-04 | UI | Попап із довгою назвою і партією без карти. Перевірити порядок колонок, перенос, `-`, два чіпи, суми та одиницю вимірювання. |
| TC-WMS-011-003 | AC-03–AC-07 | UI | Група A містить дві техкарти з різними `id`, але однаковою назвою; також є B і `-`. Перевірити один агрегований чіп A, суму, фільтрацію обох `id`, active state, OR, повторні кліки, звичайну роботу `-`, закриття й reset. |
| TC-WMS-011-004 | AC-03 | UI | Окремо відповіді «усі партії мають одну назву техкарти, але різні `id`» та «всі без техкарти»: чіпів немає, значення в колонці коректні. |
| TC-WMS-011-005 | AC-08 | UI | Дві техкарти з різними `id` та однаковою назвою плюс третя з іншою назвою. Перевірити один чіп спільної назви, суму залишків і фільтрацію партій обох `id`. |

### 4.1. Негативні та граничні перевірки, включені в матрицю

- null `techmap` не спричиняє помилку рендера;
- довга назва не обрізається логікою фільтра;
- декілька партій техкарт з однаковою назвою, включно з різними `id`, агрегуються в один чіп;
- зняття останнього активного чіпа повертає повний список;
- чіп `-` має ті самі правила active/toggle/OR, що й іменована техкарта;
- пізніше виробництво з тим самим номером партії замінює техкарту попереднього виробництва.

## 6. Поза scope

- серверна пагінація всередині попапа;
- збереження вибраних чіпів між відкриттями;
- AND-семантика мультивибору;
- редагування техкарти або партії з попапа.
