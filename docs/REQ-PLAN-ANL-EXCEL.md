# Експорт аналітики для плану в Excel

На сторінці **Аналітика → Для плану** (`/analytics/plan`) кнопка **Експорт в Excel** завантажує поточну відфільтровану вибірку. Файл містить підсумки та всі ресурси з усіх сторінок таблиці.

## Вимоги

- **AC-01.** Перший аркуш — `Підсумки`. Рядки: `Вироблено`, `Відвантажено`, `Використано`, `Залишок усього`, `Залишок (Цукрарня)`. Перша колонка має заголовок `В загальному`, далі окрема колонка для кожної одиниці виміру. Значення дорівнюють підсумкам UI за всією вибіркою; різні одиниці не додаються між собою.
- **AC-02.** Другий аркуш — `Ресурси`. Колонки: `Ресурс`, `Категорія`, `Од.`, `Вироблено`, `Відвантажено`, `Використано`, `Залишок усього`, `Залишок (Цукрарня)`. Експортуються всі відфільтровані рядки, включно з тими, яких немає на поточній сторінці. Дублі й сторонні рядки неприпустимі. Кількості — числові комірки Excel, включно з нулями та дробами.
- **AC-03.** Експорт застосовує ті самі період, ресурси, категорії, постачальників і заводи, що UI. Після зміни фільтра файл відповідає новому стану. Вибір кількох значень одного фільтра та перетин різних фільтрів мають ту саму семантику, що таблиця. Фільтр `Завод` залишає ресурси з точним значенням відповідної властивості; інші заводи й ресурси без цієї властивості виключаються.
- **AC-04.** Прямий API-експорт без `resourceIds` і `categoryIds` повертає весь каталог за переданим періодом. Таку поведінку погоджено користувачем 15.10.2026. Кількість ресурсів визначається поточними даними й не фіксується значенням 1929.

Під час відкриття UI автоматично вибирає категорію «Боєприпас»; експорт одразу використовує її ID та початковий період. Після явного очищення всіх категорій і ресурсів UI показує порожній стан і приховує кнопку експорту; прямий API-запит без вибору експортує весь каталог. За порожнього результату застосованих фільтрів аркуш ресурсів містить заголовки, підсумки — назви п'яти показників без числових колонок одиниць. Див. [контракт початкової категорії](REQ-PLAN-ANL-DEFAULT-CATEGORY.md).

## API

`GET /api/v1/analytics/plan/export` повертає XLSX із `Content-Disposition: attachment`. Клієнт передає `fromDate`, `toDate`, необов'язкові `resourceIds`, `categoryIds`, повторювані `supplier` і `factory`. Поточні `page`, `size` і сортування таблиці не входять у клієнтський запит експорту. Порядок рядків Excel не є критерієм відповідності: порівнюються склад вибірки та значення.

Для експорту з вибором еталон даних — `GET /api/v1/analytics/plan/rows` з ідентичними бізнес-фільтрами. Для прямого експорту без вибору еталон формується через rows із повним переліком категорій із `GET /api/v1/resources/categories`, оскільки rows без вибору навмисно порожній. В обох випадках збираються всі сторінки та контролюється `page.totalElements`.

## Автоматичне покриття

`PlanAnalyticsExcelExportApiTest`:

- `TC-PLAN-ANL-XLSX-API-001`: назви й порядок аркушів, усі рядки, п'ять показників, підсумки за різними одиницями, незалежність експорту від `page=1&size=1`.
- `TC-PLAN-ANL-XLSX-API-002`: окремий ресурс, кілька ресурсів, категорія, ресурс разом із категорією, один і кілька постачальників, порожня вибірка, завод разом із постачальниками, інший період. Кожен варіант порівнюється з повним результатом rows API.
- `TC-PLAN-ANL-XLSX-API-003`: прямий експорт без вибору містить весь актуальний каталог і його підсумки; UI rows без вибору залишається порожнім. Файл порівнюється з усіма сторінками rows за повним довідником категорій.
- `TC-PLAN-ANL-XLSX-API-004`: позитивний `Завод` із непорожнім результатом. Значення обирається з того самого `category_property_options[Завод]`, що UI. Еталон визначається незалежно за `properties[name=Завод]` повного каталогу ресурсів: перевіряються всі відповідні ресурси, виключення інших, п'ять показників і суми за одиницями. Тест не може пройти на порожній вибірці або коли обраний завод не виключає жодного ресурсу. XLSX та опис вибірки зберігаються в Allure.

`PlanAnalyticsExcelExportUiTest`:

- `TC-PLAN-ANL-XLSX-UI-001`: порожній стан без кнопки експорту після явного очищення початкової категорії «Боєприпас».
- `TC-PLAN-ANL-XLSX-UI-003`: справжній експорт початкової категорії «Боєприпас», ідентичні фільтри rows/export, усі сторінки й точні підсумки.
- `TC-PLAN-ANL-XLSX-UI-002`: справжнє завантаження з UI без підміни backend; експорт із другої сторінки по 25 рядків; повторний експорт після вибору постачальників, зміни періоду й очищення постачальників; рівність бізнес-фільтрів запитів rows та export, видимих рядків і карток підсумків UI та значень комірок файлу.

`PlanAnalyticsExportContractTest` перевіряє саме порівняння XLSX на локальних прикладах: дроби, нулі, різні одиниці та відхилення файлів із пропущеним/зайвим рядком, помилковим підсумком, текстовою кількістю, переставленими аркушами, неправильною категорією або кількістю.

API/UI класи включені в `regression`, а також у `functional` та `ui` відповідно. Локальні перевірки входять у `framework`.

## Запуск

```powershell
mvn test -Denv=dev "-Dtest=PlanAnalyticsExcelExportApiTest,PlanAnalyticsExcelExportUiTest" -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
mvn test -Dsuite=framework -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
# Окремо позитивний Завод:
mvn test -Denv=dev "-Dtest=PlanAnalyticsExcelExportApiTest#factoryExportIncludesMatchingResourcesAndExcludesOthers" -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
```

За наявності локального кешу залежностей можна додати `-o`. Для встановленого Chrome додайте `-Dframework.browser.channel=chrome`; щоб Playwright не намагався завантажити свій Chromium, задайте `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`. Дані ERP у нових тестах лише читаються. Для інтеграційного прогону потрібні доступ до dev, браузерна сесія ADMIN, категорія з понад 25 рядками та щонайменше дві одиниці виміру. Перевірки відсутніх передумов завершуються явною помилкою, без прихованого SKIP.

Порівняння UI/файлу використовує відповідь rows і весь набір сторінок; видимі комірки й картки також звіряються з rows із точністю відображення UI до п'яти десяткових знаків. Позитивний `Завод` перевіряється на API з незалежним еталоном властивостей ресурсів і підсумків; негативний перетин із постачальниками також збережений. Для позитивного сценарію потрібен налаштований завод, що має дані в аналітиці, та ресурси поза його вибіркою. Дані не створюються і не змінюються; відсутність передумов є явною помилкою, а не SKIP.

## Узгоджена поведінка без вибору

Експорт усього каталогу прямим запитом без вибору є правильною поведінкою. Раніше зафіксовані 1929 ресурсів — приклад обсягу каталогу на момент перевірки, а не нормативна кількість і не дефект. `TC-PLAN-ANL-XLSX-API-003` перевіряє повноту даних і підсумків за цим контрактом. У UI кнопка без вибору залишається прихованою. Реалізація backend/frontend у цьому репозиторії не змінюється.

Актуальні результати dev-прогону наведено у [звіті за 15.10.2026](audits/2026-10-15/plan-analytics-excel-export-dev-test-report.md).

## Перевірка на dev 15.10.2026

Середовище ERP: `https://dev.cukerochka.sbs`, роль ADMIN. Підтверджено 12 API-сценаріїв: 11 наявних пройшли в повному прогоні, позитивний `Завод` — у фінальному окремому повторі після виправлення сортування підготовки даних на `name,ASC`. Попередній успішний UI-прогін — 2/2; під час додавання позитивного заводу UI повторно не запускався. Framework — 81/81 на Java 21.

Для позитивного заводу `завод` незалежний еталон підтвердив 443 включені й 1486 виключених ресурсів. Прямий експорт без вибору містив 1929 ресурсів. UI-завантаження містили 79 ресурсів з другої сторінки категорії «Метизи», 3 після зміни постачальників і періоду та 79 після очищення постачальників. Ці кількості описують конкретний прогін і не є константами тестів.

Синхронізація цієї вимоги у TCM dev і TCM prod публікує той самий контракт та докази перевірки ERP dev. Це не означає виконання тестів на ERP production. Автоматизація: 4 API-кейси (9 варіантів у API-002, разом 12 сценаріїв) і 2 UI-кейси; усі мають `@TestCaseId` та включені у відповідні suite.
