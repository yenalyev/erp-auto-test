# FAITA: списання ініціаторів із точок вильоту

## Правило

Для ініціатора з «Журналу з Файти» система визначає спосіб проведення за постачальником зіставлених ресурсів.

- Якщо всі зіставлені ресурси мають зазначеного постачальника, відмінного від `ПМ Цукрарня`, запис завершується без списання з точки вильоту. Нульовий залишок не перешкоджає завершенню.
- Якщо хоча б один зіставлений ресурс має постачальника `ПМ Цукрарня`, діє звичайне списання з точки за кількістю події. Це правило діє і для суміші постачальників.
- Якщо властивість «Постачальник» відсутня або порожня хоча б в одного зіставленого ресурсу, також діє звичайне списання.
- Якщо зіставлення немає, автоматичне завершення не допускається. Звичайні ресурси FAITA й додаткові ресурси не отримують виняток за постачальником.
- Повторна обробка завершеного запису не повинна змінювати залишок або створювати повторне списання.

Технічний контракт поточного backend: `PENDING → COMPLETED`; поле `source=FLIGHT`, `sourceId` і кількість запису зберігаються. Окремого API-статусу «Проведено автоматично» наразі немає. Поточний UI підписує `COMPLETED` як «Проведено»; потрібне продуктове рішення, чи вимога передбачає зміну підпису/ознаку способу проведення.

## Відомий розрив і межі перевірки

12.10.2026 на dev ERP тест `TC-FAITA-INIT-011` підтвердив звичайне списання за суміші постачальників. `TC-FAITA-INIT-010` виявив дефект: ресурс із порожнім постачальником завершився без зменшення залишку, хоча за погодженим правилом має списуватися. Код продукту не змінювався. Поведінку prod ERP не перевіряли.

Технічна причина: поточний `InventoryWriteOffService` пропускає списання, коли в ресурсу є непорожній список властивостей, але немає пари `Постачальник=ПМ Цукрарня`; порожнє значення постачальника помилково потрапляє до винятку. UI поки не розрізняє автоматичне та ручне завершення.

## Перевірка

Тест-план, кейси та обмеження автоматизації: [FAITA_INITIATOR_WRITE_OFF_TEST_PLAN.md](FAITA_INITIATOR_WRITE_OFF_TEST_PLAN.md).

## Критерії приймання

1. Зіставлений ініціатор, у якого всі ресурси мають зазначеного постачальника, відмінного від `ПМ Цукрарня`, завершується без списання з точки вильоту за нульового і додатного залишку.
2. Якщо серед зіставлених ресурсів є постачальник `ПМ Цукрарня`, застосовується звичайне списання, навіть коли інші ресурси мають іншого постачальника. Нестача не спричиняє часткового списання.
3. За відсутнього або порожнього постачальника застосовується звичайне списання. Незіставлені ініціатори, боєприпаси й додаткові ресурси не отримують винятку за постачальником.
4. Повторна синхронізація або обробка не створює другий логічний запис чи повторне списання; запис і зміни залишку належать правильній точці вильоту.
5. «Журнал з Файти» показує правильний ресурс, точку й погоджений підпис автоматичного завершення.

## Покриття та результат на dev ERP

30.09.2026 цільовий suite `faita-initiators` завершився **3 passed, 0 failed, 0 skipped**. `TC-FAITA-INIT-001/003` підтвердили завершення без списання за нульового та додатного залишку; `TC-FAITA-INIT-002` підтвердив звичайне списання для `ПМ Цукрарня`. Тести створюють `PENDING` запис журналу в БД і викликають API завершення. Вони не перевіряють імпорт FAITA, плановий auto-complete чи UI-підпис.
