# FAITA: списання ініціаторів із точок вильоту

## Правило

Для запису «Журналу з Файти» з ініціатором (`externalResourceId` починається з `i-`) система перевіряє зіставлені ресурси ERP та їхню властивість `Постачальник`.

- Якщо ресурс зіставлений і його постачальник відрізняється від точного значення `ПМ Цукрарня`, запис переходить у `COMPLETED` без списання з точки вильоту. Нульовий залишок не перешкоджає завершенню.
- Якщо постачальник `ПМ Цукрарня`, діє звичайне списання з точки за кількістю FAITA.
- Якщо зіставлення немає, автоматичне завершення не допускається. Звичайні ресурси FAITA й додаткові ресурси не отримують виняток за постачальником.
- Повторна обробка завершеного запису не повинна змінювати залишок або створювати повторне списання.

Технічний контракт поточного backend: `PENDING → COMPLETED`; поле `source=FLIGHT`, `sourceId` і кількість запису зберігаються. Окремого API-статусу «Проведено автоматично» наразі немає. Поточний UI підписує `COMPLETED` як «Проведено»; потрібне продуктове рішення, чи вимога передбачає зміну підпису/ознаку способу проведення.

## Межі правила та питання

Зіставлення з кількома ERP-ресурсами: вимога каже «постачальник прив'язаного ресурса» в однині. Для суміші постачальників безпечне очікування — не пропускати списання; критерій потрібно затвердити. Для відсутньої або порожньої властивості `Постачальник` поведінку також потрібно затвердити. Ці варіанти не можна вважати доведеними поточними тестами.

Backend `InventoryWriteOffService` зараз застосовує виняток до будь-якого `i-` запису із непорожніми властивостями ресурсів, якщо серед них немає пари `Постачальник=ПМ Цукрарня`. Це охоплює ресурс із іншими властивостями, але без властивості постачальника. UI не розрізняє автоматичне та ручне завершення.

## Критерії приймання

1. Зіставлений FAITA-ініціатор (`i-...`), ERP-ресурс якого має `Постачальник` з іншим значенням, ніж `ПМ Цукрарня`, переходить у завершений статус без списання з точки вильоту за нульового і додатного залишку.
2. Для зіставленого ініціатора з `Постачальник=ПМ Цукрарня` застосовується звичайне списання: залишок точки зменшується рівно на кількість події; нестача не спричиняє часткового дебету.
3. Виняток діє лише для ініціаторів з коректним зіставленням. Незіставлений ініціатор, боєприпаси та додаткові ресурси обробляються за власними правилами. Порожній постачальник і кілька зіставлень різних постачальників потребують погодженого контракту.
4. Повторна синхронізація або обробка не створює другий логічний запис чи повторне списання; запис і зміни залишку належать правильній точці вильоту.
5. «Журнал з Файти» показує правильний ресурс, точку й погоджений підпис автоматичного завершення.

## Покриття та результат на dev ERP

Тести створюють `PENDING` запис журналу в БД і викликають API завершення. Вони не перевіряють імпорт FAITA, плановий auto-complete чи UI-підпис.
