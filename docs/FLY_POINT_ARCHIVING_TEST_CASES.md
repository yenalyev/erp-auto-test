# Тест-кейси: архівація точки вильоту

## Узгоджений контракт

- Кнопка «Архівувати» розташована на картці точки в списку `/fly-points` і відкриває `/fly-points/close/{id}`. Після успішного переміщення ресурсів або надзвичайної події користувач повертається на цю сторінку для повторної перевірки умов.
- Якщо одночасно є активні екіпажі й залишки, поточний UI спершу показує екіпажі. Архівна точка не має активних екіпажів і додатного фізичного залишку. Активний резерв треба вручну зняти до переміщення/списання; він входить у фізичну кількість, тому двічі не підсумовується. Вантаж у дорозі сам по собі архівацію не блокує.
- У попередженні про залишки потрібні назва ресурсу, одиниця, кількість і партія. Бронь зберігає ресурс і кількість, але не партію: не призначати їй вигадану партію.
- Комірник має **лише** «Керівник локації» та «Екіпажі: перегляд» у межах свого батальйону; адміністратор має той самий функціональний потік. Тестові фікстури не додають комірнику спеціальних дозволів.

## Передумови

Ізольований батальйон A з активними точками P1/P2 та екіпажами, створеними тестом; окремий батальйон B для перевірки доступу. Для матеріальних сценаріїв — унікальний ресурс R із партіями B1/B2. Після кожного сценарію перевіряти стан через API, а в cleanup змінювати лише створені тестом дані.

## P0

### TC-FPA-001 — Адміністратор архівує порожню точку

**Кроки:** відкрити `/fly-points` → натиснути «Архівувати» на P1 без екіпажів/залишку → підтвердити. **Очікування:** відкрито `/fly-points/close/{id}`; після підтвердження P1 `active=false`, відсутня в «Активні», присутня у «Всі» з неактивним станом. **Авто:** `FlyPointArchivingUiTest.adminArchivesEmptyPointFromListCard`.

### TC-FPA-002 — Комірник архівує порожню точку без додаткових прав

**Кроки:** увійти користувачем лише з двома узгодженими ролями, обрати свій батальйон, архівувати P1. **Очікування:** кнопка видима, дія дозволена, `active=false`. Комірник іншого батальйону й користувач без права дії не мають доступу. **Авто:** `FlyPointArchivingUiTest.standardKeeperCanArchiveEmptyPoint`.

### TC-FPA-003 — Активний екіпаж блокує архівацію

**Кроки:** додати активний C1 до P1, відкрити архівацію; окремо викликати `DELETE /api/v1/storages/{P1}`. **Очікування:** попередження про екіпажі, кнопки «Скасувати»/«Перемістити», фінальне підтвердження відсутнє; сервер повертає 4xx, P1 активна. **Авто:** `FlyPointArchivingUiTest.activeCrewBlocksUiAndDirectApiArchive`.

### TC-FPA-004 — Переміщення екіпажу й архівація точки

**Кроки:** для C1 на P1 обрати P2 того самого батальйону → «Перемістити» → «Готово» → архівувати P1. **Очікування:** C1 має parent=P2; P1, архівна точка і точка іншого батальйону не є допустимими цілями; P1 стає неактивною після підтвердження. **Авто:** `FlyPointArchivingUiTest.adminMovesCrewThenArchivesPoint`.

### TC-FPA-005 — Залишок і вміст попередження

**Кроки:** створити на P1 ресурс R, партію B1 та додатну кількість; відкрити архівацію і викликати прямий DELETE. **Очікування:** назва, одиниця, кількість, партія; кнопки переміщення й події; 4xx від API без зміни P1. **Авто:** `FlyPointArchivingUiTest.stockWarningShowsRequiredFieldsAndBlocksDirectArchive`.

### TC-FPA-006 — Переходи для залишку

**Кроки:** з попередження P1 послідовно відкрити «Перемістити залишки» й «Створити надзвичайну подію». **Очікування:** форми `/relocation/create-output-fly-point` і `/inventory/create-incident/{P1}`, у параметрі `returnTo` — `/fly-points/close/{P1}`. Після успішного збереження кожної форми користувач повертається туди ж. **Авто:** `FlyPointArchivingUiTest.stockActionsOpenFormsWithArchiveReturnRoute` (маршрути), окремі наскрізні сабміти додати після стабілізації базового потоку.

### TC-FPA-007 — Вантаж у дорозі не блокує

**Кроки:** видати весь запас P1 на P2, лишити операцію `CREATED` і фізичний залишок P1=0; архівувати P1. **Очікування:** список блокерів порожній, архівація успішна. **Авто:** `FlyPointArchivingUiTest.inTransitWithoutPhysicalStockDoesNotBlockArchive`.

### TC-FPA-008 — Резерв знято вручну до архівації

**Кроки:** з N на P1 зарезервувати M для замовлення; перевірити, що M входить у фізичний N і недоступний до переміщення/події; користувач із правом керувати замовленням вручну знімає бронь; комірник переміщує/списує N і завершує архівацію. **Очікування:** після зняття броні доступно N; комірнику не видають `order.manage`; сумарний фізичний залишок не подвоюється.

### TC-FPA-009 — Заборона архівації екіпажу з даними

**Кроки:** спробувати архівувати C1 із залишком, який модель прикріпленого екіпажу обліковує на точці; окремо C2 з активною операцією. **Очікування:** обидві дії відхилені, причина показана, екіпажі й P1 активні; прямий API не обходить перевірку. **Авто:** `FlyPointArchivingUiTest.attachedCrewWithPointStockCannotBeArchived` (перша частина й прямий API; активну операцію та повідомлення в UI ще не автоматизовано).

### TC-FPA-010 — Екіпажі й залишок одночасно

**Кроки:** на P1 створити C1 і фізичний залишок; пройти послідовно два блокери. **Очікування:** спершу екіпаж, потім залишок; обробка лише одного не дозволяє підтвердження; після обох P1 архівується один раз. **Авто:** `FlyPointArchivingUiTest.crewThenStockAreSequentialBlockers` (черговість і заборона перед обробкою другого; завершення переміщення залишку ще не автоматизовано).

## P1

### TC-FPA-011 — Скасування й неуспішні дії

**Кроки:** скасувати на сторінці архівації, екіпажів, переміщення й події; окремо підмінити відповідь збереження на 4xx/5xx. **Очікування:** без успішного сабміту дані не змінюються; повідомлення про помилку й контекст форми збережені. **Авто:** `FlyPointArchivingUiTest.cancelArchiveKeepsPointActive` (скасування на сторінці архівації; решта дій ще не автоматизована).

### TC-FPA-012 — Права й ізоляція

**Кроки:** для комірника іншого батальйону та користувача без ролі напряму відкрити P1 і надіслати запити архівації, переміщення/архівації C1, створення події. **Очікування:** відмова без розкриття чужих даних; адміністратор має всі дії.

### TC-FPA-013 — Конкурентна зміна перед підтвердженням

**Кроки:** відкрити фінальне підтвердження P1; інший запит додає екіпаж або залишок; натиснути «Архівувати». **Очікування:** сервер повторно перевіряє блокери, P1 не архівується, UI показує актуальний стан. Подвійний клік не створює двох операцій. **Авто:** `FlyPointArchivingUiTest.concurrentCrewCreationPreventsFinalArchive` (додавання екіпажу після відкриття; залишок і подвійний клік ще не автоматизовані).

### TC-FPA-014 — Після архівації

**Кроки:** перевірити P1 у списку, фільтрах і селекторах нової видачі/призначення екіпажу. **Очікування:** точка зникла з активних дій, історія доступна за наявними правилами; розархівація повертає її до активних без втрати історії.

## Примітки для автоматизації

Автоматизовано 11 методів: `TC-FPA-001…007`, `009`, `010`, `011`, `013`. Для `006`, `009`, `010`, `011`, `013` покрито частину кроків, прямо зазначену біля кейсу. `008`, `012` та решта `014` лишаються до автоматизації; успішний прогін частини кроків не означає виконання всього кейсу.
