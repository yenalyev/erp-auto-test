# Дата в журналі «Отримано»

TCM feature: **REQ-EDIT_REL-009** (модуль `EDIT_REL`, батьківська вимога `REQ-EDIT_REL`). Синхронізація документації, критеріїв приймання й кейсів: `scripts/sync_tcm_received_date.py`.

## Очікувана поведінка

У журналі «Видати/Отримати» колонки «Надіслано» й «Отримано» показують різні бізнес-дати. «Надіслано» походить із дати видачі `date`. «Отримано» походить із дати фактичного отримання `receivedAt`, відображеної за київським календарем. Створення або прийняття переміщення не повинно замінювати обрану дату отримання поточною датою.

1. У формі «Отримано» обрана в полі «Дата» дата стає датою в колонці «Отримано». Це працює і для дати в минулому.
2. Коли через форму «Видача» ресурс передають зовнішньому отримувачу й переміщення одразу завершується (`AUTO_FINISHED`), колонка «Отримано» показує обрану в формі дату видачі.
3. Для внутрішнього переміщення кнопка «Прийняти» відкриває діалог з полем «Дата прийому» (`type=date`, як у формі «Отримано»). За замовчуванням стоїть сьогоднішня дата. Найраніший дозволений день — дата «Надіслано» включно, найпізніший — сьогодні включно. Підтвердження поза цими межами недоступне. Після підтвердження «Отримано» показує обрану дату, а «Надіслано» не змінюється.

Для перевірок `receivedAt` переводиться в часову зону `Europe/Kyiv` перед порівнянням календарної дати. Час доби не є частиною цієї вимоги.

## Автоматизовані сценарії

- `TC-REL-RECEIVED-DATE-001` — API отримання від зовнішнього постачальника датою в минулому; відповідь і журнал «Отримано» містять цю дату.
- `TC-REL-RECEIVED-DATE-002` — API видача зовнішньому отримувачу датою в минулому; `AUTO_FINISHED` і журнал отримувача містять цю дату в `receivedAt`.
- `TC-REL-RECEIVED-DATE-003` — API прийняття внутрішнього переміщення з датою між надсиланням і сьогодні; `date` лишається датою надсилання, `receivedAt` і журнал відповідають даті прийому.
- `TC-UI-REL-RECEIVED-DATE-001` — діалог «Прийняти»: тип поля, початкове значення, обидві включні межі, блокування дат поза межами та збереження обраної дати після підтвердження.
- `TC-UI-REL-RECEIVED-DATE-002` — отримання через UI-форму із вчорашньою датою; API-журнал отримувача підтверджує цю дату.
- `TC-UI-REL-RECEIVED-DATE-003` — видача назовні через UI-форму із вчорашньою датою; API-журнал зовнішнього отримувача підтверджує цю дату.
- Чинний `TC-REL-DATE-017` у `RelocationOneDayLimitTest` — давнє переміщення можна прийняти з окремою датою прийому в дозволеному інтервалі.

Спільні фікстури `RelocationFixture` й `EquipmentFixture` передають сьогоднішню дату для звичайного переходу `FINISHED`; `RelocationFixture.resolve(..., receivedDate)` дозволяє сценаріям задати дату явно. Для скасування та повернення поле не передається.

Тести: `RelocationReceivedDateTest`, `RelocationReceivedDateUiTest`. Вони включені до `relocations`, `functional`/`ui` і `regression` suite. Цільовий запуск без слухачів зовнішньої звітності: `mvn test -Denv=dev -Dsuite=received-date`.

## Критерії приймання в TCM

- `AC-01` — при зовнішньому отриманні дата з форми записується в «Отримано», зокрема якщо вона раніша за сьогодні.
- `AC-02` — при видачі зовнішньому отримувачу дата з форми видачі записується в «Отримано» для `AUTO_FINISHED`.
- `AC-03` — у діалозі «Прийняти» внутрішнє переміщення має поле дати як у формі «Отримано»: від «Надіслано» до сьогодні включно; обрана дата зберігається в «Отримано», дата «Надіслано» не змінюється.

Шість нових автоматизованих кейсів із розділу вище прив’язані до цих AC за відповідним сценарієм. Оновлений `TC-REL-DATE-017` синхронізується окремо під `REQ-EDIT_REL / AC-08`: старе переміщення можна прийняти, якщо вибрана дата прийому лежить у дозволеному інтервалі. Разом синхронізуються **7 автоматизованих кейсів**. TCM-синхронізація описує вимоги й покриття; вона не публікує результати виконання тестів.
