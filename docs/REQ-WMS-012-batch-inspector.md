# REQ-WMS-012 — Batch Inspector

Специфікація фічі для продукту, backend, frontend і QA.
Функціональний контур: партії ресурсів, виробництво та складські переміщення.
SSOT у репозиторії: цей файл.

Статус: **автотести додано; контракт перевірено на dev 2026-09-25**.

Фактична реалізація dev використовує сторінку `/batch-inspector?name={batchNumber}`
та `GET /api/v1/batches/inspect?name={batchNumber}`. UUID залишається стабільною
ідентичністю партії у відповіді та суміжних контрактах. Відмінності від погоджених
правил доступу й відображення документа наведені у розділі 8.

---

## 1. Мета

Admin повинен мати змогу знайти партію за її чинною назвою `batchNumber` на окремій
сторінці та переглянути її походження, рух і фактичні залишки по складах. У всіх
пов'язаних API-контрактах логічна партія ідентифікується стабільним UUID.

Нова сторінка доступна за маршрутом:

```text
/batch-inspector?name={batchNumber}
```

Batch Inspector показує:

- назву партії;
- дату виробництва або діапазон дат;
- технологічну карту;
- хронологію руху партії по складах;
- поточні фактичні залишки по складах.

## 2. Терміни та зафіксовані рішення

### 2.1. Логічна партія

Логічна партія — набір залишків і складських операцій одного ресурсу зі спільним
походженням. Залишки цієї партії можуть одночасно бути на кількох складах після
часткового переміщення, але всі вони належать одному UUID.

У межах цієї вимоги **«назва партії» — це чинне значення `batchNumber`**. Окреме
редаговане поле `batchName` не створюється. Наявний пошук за назвою партії продовжує
працювати за `batchNumber`; результати пошуку та рядки партій використовують UUID
лише для переходу на сторінку inspector.

### 2.2. UUID партії

1. UUID генерується backend один раз під час створення логічної партії.
2. UUID є обов'язковим, глобально унікальним і незмінним; у чинних DTO поле має
   назву `batchUuid`, а у відповіді inspector — `id`.
3. UUID в API передається як канонічний рядок і для клієнта є opaque identifier:
   клієнт не повинен визначати за ним дату, тип або інші властивості партії.
4. Часткове або повне переміщення, повернення та розподіл залишку між складами не
   створюють новий UUID.
5. Для нових партій `batchNumber` глобально унікальний між ресурсами. Legacy-дані
   можуть містити колізії назв; inspector повертає масив результатів і не об'єднує
   записи з різними UUID.
6. UUID не можна повторно використати після видалення або повного списання партії.
7. Числові `id` можуть тимчасово залишатися внутрішніми технічними ключами, але не
   використовуються в новому URL і не є публічною ідентичністю партії.

### 2.3. Міграція наявних даних

- для кожної наявної логічної партії UUID створюється backfill-міграцією;
- усі складські фрагменти, виробничі записи та позиції переміщень цієї партії мають
  посилатися на один UUID;
- міграція використовує чинну доменну тотожність партії, а не випадковий
  `storage_item_batch.id` окремого складу;
- повторний запуск міграції не змінює вже призначені UUID;
- після міграції суміжні API-відповіді повертають `batchUuid`, а inspector — `id`.

## 3. Функціональні правила Batch Inspector

### 3.1. Заголовок партії

У верхньому блоці сторінки відображаються:

- **Назва партії** — `batchNumber`; для відсутнього legacy-значення — `—`;
- **Ресурс** — назва ресурсу партії;
- **Дата виробництва**;
- **Технологічна карта**.

UUID може бути показаний як другорядне значення з можливістю копіювання, але він не
замінює зрозумілу користувачу назву партії.

### 3.2. Дата виробництва

Дата визначається за проведеними виробничими записами, що належать UUID партії:

- один запис або кілька записів за одну календарну дату — одна дата;
- записи за різні дати — діапазон від мінімальної до максимальної дати включно;
- для зовнішньої партії без виробничого запису — `—`;
- скасовані або видалені з повним rollback виробничі записи не враховуються.

UI використовує локалізований формат дат, але не змінює межі діапазону, отримані від
API.

### 3.3. Технологічна карта

- для виробничої партії відображається назва технологічної карти та, якщо доступна,
  її зафіксована версія;
- значення береться зі snapshot/версії, використаної для виробництва, а не з
  поточної редакції довідника;
- для зовнішньої партії без виробництва відображається `—`;
- усі валідні виробничі записи одного UUID повинні мати одну техкарту й версію;
- якщо legacy-дані порушують цю інваріанту, API не обирає мовчки «останню» карту:
  сторінка показує попередження **«Дані партії неузгоджені»**.

Batch Inspector є read-only: перехід до картки техкарти можливий окремим посиланням,
але редагування техкарти зі сторінки партії не виконується.

### 3.4. Поточні фактичні залишки

Перед історією руху відображається окремий блок **«Поточні залишки»**. Він показує
фактичний залишок партії на кожному складі на момент завантаження сторінки:

- назву складу;
- актуальну кількість;
- одиницю вимірювання ресурсу.

До блоку входять склади з додатним фактичним залишком цього UUID. Залишки різних
UUID з однаковою назвою партії не агрегуються. Сума рядків блоку дорівнює загальному
поточному залишку логічної партії. Якщо партію повністю витрачено або списано, UI
показує **«Партія відсутня на складах»**.

### 3.5. Рух партії по складах

Рух відображається хронологічною таблицею від найстарішої операції до найновішої.
Для кожної проведеної операції показуються:

- дата й час операції;
- тип операції;
- склад-відправник або зовнішнє джерело;
- склад-одержувач або зовнішній напрямок;
- кількість і одиниця вимірювання;
- номер документа/накладної, якщо він є.

Номер документа є інтерактивним, якщо для руху доступна накладна:

- `canGenerateInvoice=true` — номер відображається як кнопка завантаження
  згенерованої накладної;
- `hasExternalInvoicePhoto=true` — номер відкриває або завантажує прикріплене фото;
- якщо жоден артефакт недоступний, номер залишається звичайним текстом;
- дія не веде на картку виробництва або переміщення.

До історії входять лише операції, що фактично змінили облік партії: виробниче або
зовнішнє оприбуткування, завершене внутрішнє переміщення, повернення та списання.
Чернетки, скасовані операції й невдалі запити не додаються до руху.

Часткове переміщення створює рядок лише на переміщену кількість і зберігає той самий
UUID у залишку відправника та в залишку одержувача. Історія не повинна змішувати
операції іншої партії з такою самою назвою.

Якщо проведених операцій немає, UI показує порожній стан **«Рух партії відсутній»**,
а не порожню таблицю або помилку.

### 3.6. Навігація

- для Admin у sidebar доступний пункт **«Інспектор партії»**;
- пошук виконується за точною назвою партії (`batchNumber`);
- стан пошуку відтворюється у query-параметрі `name`;
- пряме відкриття URL і перезавантаження сторінки працюють без попереднього переходу;
- браузерна кнопка «Назад» повертає користувача до попереднього екрана без зміни
  даних партії.

## 4. Контракт API

### 4.1. Пошук та деталі партії

```text
GET /api/v1/batches/inspect?name={batchNumber}
```

Відповідь — масив, оскільки legacy-дані можуть містити колізії назв:

```json
[
  {
    "id": "018f8494-954b-7a4d-8b79-2f65b58ab001",
    "name": "LOT-001",
    "resource": { "id": 42, "name": "Корпус виробу" },
    "legacy": false,
    "createdAt": "2026-09-20T08:00:00Z",
    "productions": [
      {
        "id": 71,
        "date": "2026-09-20",
        "storage": { "id": 10, "name": "Склад виробництва" },
        "techMap": { "id": 17, "name": "Техкарта корпусу" },
        "product": { "id": 42, "name": "Корпус виробу" },
        "amount": 10,
        "unit": "шт"
      }
    ],
    "ingredients": [],
    "movements": [
      {
        "relocationId": 501,
        "dateTime": "2026-09-22T10:15:30Z",
        "sender": { "id": 10, "name": "Склад виробництва" },
        "recipient": { "id": 24, "name": "Центральний склад" },
        "state": "FINISHED",
        "invoiceNumber": "REL-2026-00125",
        "canGenerateInvoice": true,
        "hasExternalInvoicePhoto": false,
        "resource": { "id": 42, "name": "Корпус виробу" },
        "amount": 5,
        "unit": "шт"
      }
    ],
    "stock": [
      {
        "storage": { "id": 24, "name": "Центральний склад" },
        "resource": { "id": 42, "name": "Корпус виробу" },
        "amount": 5,
        "unit": "шт"
      }
    ]
  }
]
```

Правила полів:

- `id` — UUID логічної партії;
- `productions`, `ingredients`, `movements` і `stock` завжди є масивами;
- дата або діапазон виробництва та технологічна карта обчислюються UI з
  `productions`;
- для зовнішньої партії `productions=[]` та `ingredients=[]`;
- `stock` містить актуальні фактичні залишки партії по складах;
- невідома назва повертає `200 OK` і `[]`;
- `movements` відсортований за `dateTime ASC`.

### 4.2. UUID у суміжних контрактах

Контракти залишків і переміщень повертають `batchUuid`:

```json
{
  "id": 123,
  "batchUuid": "018f8494-954b-7a4d-8b79-2f65b58ab001",
  "amount": 5,
  "batchNumber": "LOT-001"
}
```

Під час відправлення конкретної партії клієнт також передає її `batchUuid`. Це
виключає неоднозначність назви та гарантує незмінну ідентичність після часткового
переміщення.

### 4.3. Доступ і помилки

- endpoint призначений лише для глобального Admin;
- не-Admin — `403 Forbidden` без деталей партії;
- анонімний запит — `401 Unauthorized`;
- невідома назва для Admin — `200 OK` та порожній масив;
- тимчасова помилка backend відображається окремим error state з retry.

## 5. Доступ

Batch Inspector доступний **тільки глобальному Admin**.

- Admin бачить повні основні дані, фактичні залишки та весь маршрут партії;
- для всіх інших авторизованих ролей пункт sidebar та інші entry points приховані;
- прямий API-запит або пряме відкриття `/batch-inspector` не-Admin користувачем має
  завершуватися `403 Forbidden`;
- backend є остаточною точкою перевірки доступу; прихованого пункту в UI недостатньо;
- анонімний API-запит повертає `401 Unauthorized`;
- відповідь `403` не повинна містити назву партії, ресурс, склади, залишки або рухи.

Фіча не створює нової ролі чи permission: доступ визначається глобальною роллю
Admin.

## 6. Acceptance Criteria

### AC-01 — Стабільна UUID-ідентичність

- кожна логічна партія має непорожній унікальний UUID;
- UUID незмінний у виробництві, залишках і переміщеннях;
- часткове переміщення не створює нову партію;
- новий `batchNumber` не можна повторно використати для іншого ресурсу;
- legacy-партії з однаковою назвою, але різними UUID, не змішуються.

### AC-02 — Відкриття сторінки

- маршрут `/batch-inspector?name={batchNumber}` підтримує пряме відкриття та reload;
- пошук знаходить партію за `batchNumber`;
- кожний результат містить UUID `id`, який збігається з `batchUuid` у залишках і
  переміщеннях.

### AC-03 — Основні дані

- показані назва партії та ресурс;
- відображені значення належать запитаному UUID;
- nullable legacy-назва відображається як `—` без помилки рендера.

### AC-04 — Дата або діапазон виробництва

- одна виробнича дата показується як одна дата;
- різні дати показуються як `min — max`;
- зовнішня партія без виробництва показує `—`;
- скасовані записи не розширюють діапазон.

### AC-05 — Технологічна карта

- валідна виробнича партія показує snapshot назви й версії техкарти;
- зовнішня партія показує `—`;
- конфліктні legacy-дані дають видиме попередження, а не довільно обрану карту.

### AC-06 — Хронологія руху

- проведені рухи показані в детермінованому хронологічному порядку;
- кожний рядок містить напрямок, кількість, одиницю й дату/час;
- часткові переміщення відображають фактичну кількість;
- чернетки та скасовані операції відсутні;
- доступний документ відображається інтерактивною кнопкою, а недоступний — текстом.

### AC-07 — Порожній стан і помилки

- `movements=[]` дає повідомлення «Рух партії відсутній»;
- невідоме ім'я дає `[]` і повідомлення «Партію … не знайдено»;
- `403` і тимчасова серверна помилка мають окремі UI-стани;
- сторінка не показує дані попередньо відкритої партії після помилки нового запиту.

### AC-08 — Контроль доступу

- неавторизований запит відхиляється;
- будь-яка авторизована роль, крім глобального Admin, не бачить entry point і
  отримує `403` через прямий API або прямий URL;
- Admin отримує повний контракт без фільтрації маршруту.

### AC-09 — Backfill

- усі наявні партії отримали UUID;
- пов'язані записи однієї legacy-партії мають однаковий UUID;
- повторна міграція не змінює UUID і не створює дублікати.

### AC-10 — Поточні фактичні залишки

- сторінка показує окремий рядок для кожного складу з додатним залишком UUID;
- кількості й одиниця відповідають фактичному складському обліку на момент запиту;
- сума рядків дорівнює загальному залишку партії;
- після часткового переміщення залишок коректно розподілений між складами;
- повністю витрачена партія показує «Партія відсутня на складах»;
- залишки іншого UUID з тим самим `batchNumber` не потрапляють до блоку.

- QR/barcode, друк етикетки та публічний доступ за UUID;
- export історії;

- зміна правил проведення виробництва або переміщень.

## 10. Підтверджені продуктові рішення

1. Окреме поле `batchName` не додається: назвою є чинний пошуковий `batchNumber`.
2. Batch Inspector та повний маршрут партії доступні тільки глобальному Admin.
3. Номер документа інтерактивний, коли доступне генерування накладної або її фото;
   без доступного артефакту він відображається звичайним текстом.
4. Поточні фактичні залишки партії по складах показуються окремим блоком над
   історією рухів.
