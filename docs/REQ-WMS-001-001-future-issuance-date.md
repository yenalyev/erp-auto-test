# REQ-WMS-001-001 — Заборона видачі майбутньою датою

TCM: дочірня вимога `REQ-WMS-001` («Операція Видати»). Статус у dev TCM — `IN_PROGRESS`.

## Правило

При створенні видачі та при зміні її дати під час редагування дата не може бути пізніше поточної календарної дати системи. Верхня межа однакова для бізнес-власника, комірника й адміністратора. Це стосується видачі ресурсів та обладнання, зокрема форм видачі на локацію, екіпаж і між точками вильоту.

Сервер має повернути HTTP 400 з помилкою поля `date`. Невдалий запит не створює переміщення і не змінює дату, вміст, статус чи залишки існуючої видачі. UI також має не дозволяти вибрати та надіслати майбутню дату, але серверна перевірка потрібна для прямих API-запитів.

Це **верхня** межа. Вимога `REQ-EDIT_REL / AC-08` (CPMA-796) задає **нижню** межу для неадміністратора: дата не раніше вчорашньої. Адміністратор звільнений від нижньої межі, але не від верхньої.

Дата прийому під час «Прийняти» — окреме поле: її межі від дати «Надіслано» до сьогодні описані в [тест-плані дати отримання](RECEIVED_DATE_TEST_PLAN.md). Одноденне вікно для редагування видачі не забороняє приймати давнє переміщення.

## Критерії та автотести

| AC dev TCM | Перевірка | Наявні API-тести |
|------------|-----------|------------------|
| AC-01 | Створення видачі завтрашньою датою відхилене для неадміністратора й адміністратора; правило окремо перевірене для комірника при `FP1 → FP2`; залишок незмінний | `TC-REL-DATE-010`, `011`, `022` |
| AC-02 | Зміна дати існуючої видачі на завтра відхилена для неадміністратора й адміністратора; правило окремо перевірене для комірника при `FP1 → FP2`; запис та залишок незмінні | `TC-REL-DATE-012`, `013`, `023` |
| AC-03 | Форми видачі блокують майбутню дату | Окремого UI-автотесту наразі немає |

Усі шість API-сценаріїв знаходяться в `RelocationOneDayLimitTest`. Окремого UI-автотесту для AC-03 ще немає.

## Стан реалізації на 15.09.2026

На `dev` серверна перевірка майбутньої дати працює для звичайних переміщень і для `FP1 → FP2`: запуск `RelocationOneDayLimitTest` 15.09.2026 пройшов `39/39`, включно з `TC-REL-DATE-010…013`, `022` і `023`. Відхилені API-запити повернули помилку поля `date`, а тести підтвердили незмінність записів і залишків. У `tk-ui` форми видачі також встановлюють HTML `max` для поля дати; окремий UI-автотест AC-03 залишається непокритим.

Запуск: `mvn test -Denv=dev -Dtest=RelocationOneDayLimitTest`.
