Після уточнення порядку дій `RelocationUsedBatchEditTest` повторно запущено на dev: **5 PASS, 0 FAIL, 0 ERROR, 0 SKIP** за Surefire (72,06 с). У кожному кейсі виконано `POST /defects`, потім `GET /defects/{id}` із перевіркою UUID і кількості, і тільки після цього `PUT /relocations/{id}/receive` для того самого отримання.

Після уточнення правила сумарного списання додано `TC-REL-USED-006` (два браки 2 + 3, редагування 10 → 4 відхилено) і `TC-REL-USED-007` (два браки 2 + 3, редагування 10 → 5 дозволено). Повний повторний прогін: **7 PASS, 0 FAIL, 0 ERROR, 0 SKIP** за Surefire (86,11 с). Обидва записи браку створено і перевірено через `GET` перед `PUT`; після редагування перевірено їх незмінність і залишок партії.

На окремий запит повторно запущено лише `TC-REL-USED-006` та `TC-REL-USED-007` на dev: **2 PASS, 0 FAIL, 0 ERROR, 0 SKIP** за Surefire (63,04 с, включно з підготовкою і прибиранням тестового середовища).

Після уточнення сценарію браку від постачальника додано `TC-REL-USED-008`: зовнішнє отримання 10 од. (`isProduced=false`, одна партія), брак типу `RELOCATION` 8 од. з `relocationId` цього отримання, спроба редагування до 4 од. Окремий прогін кейсу: **1 PASS**; `PUT` відхилено з `4xx`, отримання залишилось 10, брак 8, залишок партії 2. Повний прогін `001…008`: **8 PASS, 0 FAIL, 0 ERROR, 0 SKIP** за Surefire (88,72 с). Сім кейсів `STORAGE` збережені.

Перший UI-прогін `TC-UI-REL-004` завершився тайм-аутом у `RelocationPage.waitForJournalDataSettled`: HTML-таблиця вже була видима, проте Page Object чекав контейнерний `data-slot` і напис «Завантаження...» залишався змонтованим. Після зміни очікування кейс пройшов. Цей кейс редагує отримання через API і робить скриншот журналу; він не перевіряє саме збереження через UI-форму.

30.09.2026 додано прямий UI-кейс `TC-UI-REL-USED-008` для ролі адміністратора. Після отримання 10 і `RELOCATION`-браку від постачальника 8 форма дозволяє ввести 4, кнопка «Підтвердити» активна й надсилає `PUT`. Сервер повертає `400`, у формі з'являється повідомлення про недостатній залишок ресурсу. Повторне читання підтвердило отримання 10, брак 8, загальний залишок ресурсу 2 і залишок партії 2. Перший прогін додаткової перевірки банера встигав прочитати стан «Обробка…» відразу після HTTP-відповіді; після очікування появи повідомлення кейс пройшов. Цей висновок стосується **однієї партії** й недостатнього загального залишку.

Після уточнення користувача про **інші партії** підготовлено два зовнішні отримання того самого ресурсу по 10 од. у різні партії. Брак 8 створено за першим отриманням; перед редагуванням його партія мала 2 од., друга — 10 од., загальний залишок 12 од. Для `TC-REL-USED-009` брак типу `RELOCATION` вказував `relocationId` першого отримання. Для `TC-REL-USED-010` брак типу `STORAGE` явно містив `batchUuid` першої партії. В обох випадках адмінський `PUT` першого отримання 10 → 4 **повернув 200**; повторне читання показало отримання 4, брак 8, залишки партій 0 і 6, загальний залишок 6. UI-кейс `TC-UI-REL-USED-009` відтворив ті самі дані після натискання «Підтвердити». Кожен із трьох нових регресійних тестів навмисно **FAIL**, бо перевіряє потрібну відмову `4xx` і незмінність стану. Це підтверджений дефект dev; попередні `008` і `TC-UI-REL-USED-008` з однією партією перевіряли лише ситуацію з недостатнім загальним залишком.

## Звірка TCM

- Фіча `REQ-EDIT_REL-010`, критерії `AC-01…04`, десять API-кейсів і два UI-кейси синхронізовані в dev і prod TCM. Read-back 30.09.2026 підтвердив **12 кейсів**, відповідність документації джерелу, чотири кроки кожного нового кейсу й відповідні `apiAutomationIds` або `uiAutomationIds`. Кейси `009…010` позначають відомий дефект dev і залишають очікувану заборону як критерій приймання.
- ID `REQ-EDIT_REL-009` уже належить даті отримання. Після виявлення колізії нові кейси перенесено до `010`; існуючий документ і три AC фічі `009` у dev відновлено та звірено з незміненим prod TCM. Прод-фіча `009` не змінювалася.
- Перевірено чинні `TC-DEF-029`, `TC-UI-DEF-029`, `TC-REL-050`, `TC-REL-054`, `TC-REL-B04` у dev/prod TCM: вони активні й мають відповідні посилання на автоматизацію. Нові кейси не дублюють їхні дії.
