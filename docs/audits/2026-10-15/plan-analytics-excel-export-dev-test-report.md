# Перевірка експорту аналітики для плану в Excel

Оновлення 15.10.2026 на dev `https://dev.cukerochka.sbs`, роль ADMIN: **позитивний фільтр «Завод» — PASS**. Excel містить 443 відповідні ресурси та виключає 1486 інших; значення й підсумки збігаються з незалежним еталоном властивостей ресурсів.

За актуальними прогонами підтверджено **12 API-сценаріїв** і **framework 81/81 на Java 21**. Попередній успішний UI-прогін 2/2 збережено; у цьому оновленні UI повторно не запускався. Авторизація ADMIN на dev пройшла.

Експорт без вибору ресурсу/категорії прийнято користувачем як правильну поведінку: прямий API-запит повертає повну аналітичну вибірку каталогу за періодом. Це більше не класифікується як дефект.

## Результати повторного прогону

- **Попередній UI-прогін: 2 PASS, 0 FAIL, 0 SKIP.** Порожній стан без кнопки експорту; справжні завантаження Excel після вибору категорії, переходу на другу сторінку, вибору двох постачальників, зміни періоду й очищення постачальників.
- **API: 12 підтверджених PASS, без SKIP.** 11 наявних сценаріїв пройшли в повному прогоні цього оновлення; новий позитивний `Завод` пройшов у фінальному окремому повторі. Покрито порядок аркушів `Підсумки`, `Ресурси`; всі рядки поза поточною сторінкою; назви, категорії, одиниці й п'ять числових показників; підсумки за одиницями; фільтри ресурсів, категорій, постачальників, позитивний завод і негативний перетин із заводом; зміну періоду; повний каталог без вибору.
- **Framework на Java 21: 81 PASS, 0 FAIL, 0 SKIP.** Включно з 8 перевірками порівняння XLSX та `RegressionSuiteCompletenessTest`.

UI-запити export містили ті самі бізнес-фільтри, що rows, без `page`, `size` і `sort`. Видимі клітинки й картки підсумків звірено з відповіддю rows; кожний Excel — з повним набором сторінок і підсумками API. Підміни rows/export не використовувалися.

## Підтверджені UI-завантаження

1. **Категорія «Метизи», вересень 2026, друга сторінка по 25 рядків:** Excel містить усі **79 ресурсів**, включно з рядками інших сторінок.
2. **Два постачальники та період липень–вересень 2026:** Excel містить **3 ресурси**, які відповідають новим фільтрам; числові значення й підсумки збігаються з API.
3. **Після очищення постачальників:** Excel знову містить **79 ресурсів** за поточним періодом; старий фільтр постачальників відсутній у запиті.

Це виміряні обсяги конкретного прогону, а не фіксовані очікування автотесту.

## Позитивний фільтр Завод

`TC-PLAN-ANL-XLSX-API-004` / `factoryExportIncludesMatchingResourcesAndExcludesOthers` перевірено на реальних даних dev за вересень 2026:

1. Значення `завод` обране з `category_property_options[Завод]` — того самого джерела, що використовує UI.
2. Повний каталог ресурсів прочитано сторінками по 500 рядків із дозволеним сортуванням `name,ASC`. Еталон визначено за точним значенням `properties[name=Завод]`, незалежно від реалізації фільтра аналітики.
3. Очікувана вибірка містить **443 ресурси**. **1486** інших ресурсів аналітики з іншими значеннями або без відповідної властивості виключені. Позитивна вибірка та набір виключень обов'язково непорожні.
4. Rows API повернув точний очікуваний набір ID; експорт містив усі 443 рядки, назви, категорії, одиниці та п'ять числових показників.
5. Підсумки незалежно обчислено з очікуваних рядків через `BigDecimal` окремо за одиницями виміру й порівняно з аркушем `Підсумки`. Перевірено числові типи комірок.

Кількості 443 і 1486 — результат цього прогону. Тест не фіксує назву заводу чи кількість рядків і не може пройти лише через однаково неправильну фільтрацію rows та export. Дані ERP не змінюються.

## Узгоджена поведінка експорту без вибору

`TC-PLAN-ANL-XLSX-API-003` тепер перевіряє таку поведінку:

1. `GET /server/api/v1/analytics/plan/rows?fromDate=2026-09-01&toDate=2026-09-30&page=0&size=20` без `resourceIds` і `categoryIds` повертає порожні `content` і `totals` — UI ще не має вибору.
2. `GET /server/api/v1/analytics/plan/export?fromDate=2026-09-01&toDate=2026-09-30` повертає повний каталог аналітики за періодом.
3. Еталон для файлу формується з усіх сторінок rows із повним переліком категорій із `GET /api/v1/resources/categories`.
4. Порівнюються всі ресурси, п'ять числових показників і підсумки за одиницями.

У цьому прогоні повний експорт містив **1929 ресурсів**. Автотест не прив'язаний до цього числа: очікувані рядки й підсумки отримує з актуальних даних. У UI кнопка без вибору ресурсу/категорії залишається прихованою.

## Оновлення тестів і документації

- Додано `TC-PLAN-ANL-XLSX-API-004`: позитивний завод, контроль виключень, незалежний еталон властивостей і сум за одиницями. XLSX та опис вибірки додаються до Allure.
- `exportWithoutSelectionContainsWholeCatalog` замінив помилкове очікування порожнього експорту; `@TestCaseId` залишився `TC-PLAN-ANL-XLSX-API-003`.
- Еталон повного каталогу використовує весь довідник категорій, а не категорії лише першої сторінки ресурсів.
- `PlanAnalyticsPage.selectCategory` очікує появи вибраної категорії та закриває список кліком поза ним. Це усуває передчасний перехід до пагінації та втрату вибору в Page Object.
- [Вимоги й покриття](../../REQ-PLAN-ANL-EXCEL.md) містять AC-04 для погодженого експорту без вибору.

Backend/frontend у межах цієї роботи не редагувалися. Інтеграційні перевірки лише читають дані ERP. Позитивний завод і негативний перетин із постачальниками покрито API-тестами.

## Синхронізація TCM dev і prod 15.10.2026

У проєкті 1 [TCM dev](http://localhost:18100) та [TCM prod](http://tcm.lab) створено дочірню вимогу `REQ-PLAN-ANL-EXCEL` під `REQ-PLAN-ANL`, 4 критерії приймання та 6 кейсів. Вимога й кейси мають статус `ACTIVE`; усі 6 кейсів мають `automation=true`, точний `@TestCaseId`, Java-клас/метод та відповідні suite. Після запису повторно прочитано й перевірено документацію, критерії, назви, передумови, тестові дані, кроки, очікування, теги та API/UI-прив'язки.

- `AC-01` → `TC-PLAN-ANL-XLSX-API-001`: підсумки за одиницями та структура файлу.
- `AC-02` → `TC-PLAN-ANL-XLSX-UI-002`: усі сторінки ресурсів у справжніх UI-завантаженнях; API-001 додатково перевіряє повний файл.
- `AC-03` → `TC-PLAN-ANL-XLSX-API-002`, `API-004`: фільтри та позитивний «Завод» із незалежним еталоном; UI-002 додатково перевіряє зміну й очищення фільтрів.
- `AC-04` → `TC-PLAN-ANL-XLSX-API-003`, `UI-001`: повний прямий експорт без вибору та прихована кнопка UI.

DB ID вимоги — 152 в обох TCM. DB ID кейсів у порядку API-001…004, UI-001…002: dev — 1804…1809; prod — 1811…1816. Бізнес-ID однакові; всі критерії мають принаймні один прив'язаний кейс.

Опубліковано актуальну документацію з результатом позитивного заводу: 443 відповідні ресурси та 1486 виключень; експорт без вибору з 1929 ресурсами зафіксовано як погоджену правильну поведінку. Значення залишаються доказами конкретного прогону, а не константами тестів.

Прогони ERP, описані в цьому звіті, виконано на dev. Синхронізація в TCM prod переносить контракт і докази dev-перевірки; нового прогону на ERP production та нових записів execution results не створювали.

Повторювана локальна синхронізація: `scripts/sync_tcm_plan_analytics_excel_export.py` через AI API; production синхронізовано через MCP `tcm-ai-prod`. Машинні докази перевірки збережено в gitignored [dev JSON](../../../logs/plan-excel-evidence/tcm-dev-sync.json) та [prod JSON](../../../logs/plan-excel-evidence/tcm-prod-sync.json).
