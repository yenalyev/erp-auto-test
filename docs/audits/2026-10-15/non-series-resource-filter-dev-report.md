## Очищення даних

Усі власні виробництва й отримання фінального прогону видалено, залишки
обох локацій кожної фікстури перевірені як нульові, локації архівовано.
Ресурси фінального прогону `4530–4535` залишилися в каталозі: ERP повертає
400 при спробі деактивації через наявність нульових `storage_item` навіть
на архівній локації. Таке саме обмеження стосується ресурсів попереднього
повного прогону. API видалення цих нульових рядків не надається.
Фікстура явно журналює це обмеження; інші помилки cleanup провалюють
конфігурацію. Чужі дані не очищуються за назвами або префіксами.
