# Несерійне виробництво — результати перевірки Excel на dev

Дата: 15.10.2026, Europe/Kyiv. Середовище: `https://dev.cukerochka.sbs`.
Фіча: [REQ-NSP-EXCEL](../../REQ-NSP-EXCEL.md).

## Результат

Фінальний повний прогін: **11/11 PASS — 7 API та 4 UI; FAIL 0, SKIP 0**.
Локальний `framework`: **85/85 PASS; FAIL 0, SKIP 0**, включно з чотирма перевірками
нового Excel-верифікатора та перевіркою повноти `regression.xml`.

У перевірених сценаріях активні фільтри застосовуються до Excel. Назва, матеріал,
статус і період працюють окремо та через AND. Зміна й очищення фільтрів оновлюють файл.
Порожня вибірка дає файл із заголовками. Друга сторінка журналу з одним видимим рядком
експортує всі **26 виробів**, загальний об’єм **49 од.**; сусідня локація виключена.
У API також перевірено дві локації разом і незалежність файлу від `page=1&size=1`.

Після посилення `TC-NSP-XLSX-API-007` окремий повтор також завершився **1/1 PASS**:
повні виробничі записи обох локацій до й після експорту однакові. Лог:
[перевірка незмінності записів](../../../logs/nsp-excel-isolation-dev.log),
[Surefire](../../../logs/nsp-excel-build/surefire-reports/TEST-com.erp.tests.functional.non_series_production.NonSeriesExcelExportApiTest.xml).

- `TC-NSP-XLSX-API-006`: два порожні результати, зміна й вилучення пошуку — PASS.
- `TC-NSP-XLSX-API-007`: усі сторінки, дві локації, незмінність залишків і об’ємів — PASS.
- `TC-NSP-XLSX-UI-001`: чотири завантаження за окремими UI-фільтрами — PASS.
- `TC-NSP-XLSX-UI-002`: три завантаження за комбінованими, зміненими й очищеними умовами — PASS.
- `TC-NSP-XLSX-UI-003`: завантаження з порожнього журналу — PASS.
- `TC-NSP-XLSX-UI-004`: завантаження з другої сторінки — PASS.

UI-перевірки звіряють точні параметри запиту експорту з очікуваними фільтрами,
видимі вироби та загальний об’єм. Для кожного файлу перевіряються всі поля виробів,
усі витрачені матеріали, їх кількість і одиниці. Об’єднані комірки не створюють дублів.
Загалом фінальний прогін завантажив 32 Excel-файли: 23 через API та 9 через UI.

## Історія запуску

Початкова спроба в sandbox завершилася DNS-помилкою входу `ERR_NAME_NOT_RESOLVED`;
11 тестів не дійшли до перевірок фічі. У повторі з мережевим доступом виконано всі
11 тестів: 10 PASS, один failure підготовки сценарію пагінації. Повторне відкриття
журналу відновлювало типовий період; тест тепер явно очищає його перед перевіркою
експорту всіх сторінок. Після цього повний повтор завершився 11/11 PASS.

Локальний framework у sandbox був зупинений після зависання; повтор поза sandbox
завершився 85/85 PASS. Це окремі від бізнес-перевірок інфраструктурні спроби.
Java: Amazon Corretto 21.0.9; браузер: встановлений Chrome через Playwright.

у [production TCM](http://tcm.lab) та [локальному TCM](http://localhost:18100), проєкт 1.
Усі кейси мають `automation=true`, точні API/UI automation ID та Java-клас і метод.
Після запису документація, критерії та кейси прочитані повторно.

Документацію фічі в обох TCM доповнено підсумками 11/11 PASS, framework 85/85,
окремого повтору перевірки незмінності записів, посиланням на dev run 195 та станом
імпорту результатів у prod. У `TC-NSP-XLSX-API-007` уточнено кроки й очікування
порівняння повних виробничих записів; текст документації звірено з файлом у репозиторії.

  production змінюється через MCP `tcm-ai-prod`, local — через AI API порту 18100.

Фактичні результати повного dev-прогону імпортовані до **локального TCM, run 195**:
`COMPLETED`, 11 PASS, matched=11, unmatched=[], outOfScope=[]. Після імпорту run

Production runner API повертає HTTP 401 з доступними налаштованими autotest credentials.
Документація й усі 11 кейсів у prod збережені та перевірені, але їх `executionStatus`
залишився `NOT_RUN`. Результати dev підтверджені Surefire, Allure та локальним run 195.

## Дані та межі перевірки

Фікстура створює власні локації, ресурси, отримання та виробничі записи. Cleanup
видаляє власні виробництва й отримання, перевіряє нульові залишки й архівує локації.
ERP відхиляє деактивацію деяких ресурсів через нульові складські рядки на архівованих
локаціях; такі ресурси фікстура залишає з повідомленням у логах.

Продуктових дефектів експорту в цих сценаріях не виявлено. Продуктивність великих
файлів та нова RBAC-матриця не перевірялися. Backend `tk` і frontend `tk-ui` не змінювалися.
