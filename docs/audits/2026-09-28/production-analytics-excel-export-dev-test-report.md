## Падіння за попередньою версією контракту

1. `TC-ANL-UI-022` (`excelExportForwardsLocationAndProductTopFilters`): при виборі
   двох виробів з двох локацій workbook містить обидва готові вироби, але не
   містить їхніх контрольних ресурсів на аркуші «Виготовлення - Витрати».
2. `TC-ANL-UI-023` (`excelExportForwardsCombinedCategoryAndProductFilters`): при
   перетині локації, категорії та виробу workbook містить готовий виріб, але
   не містить його контрольного ресурсу витрат.

В обох випадках export endpoint повернув валідний XLSX. На момент цього
прогону тест очікував витрат за фільтром «Вироби»; згодом користувач уточнив
окрему фільтрацію матеріалів, а тести оновлено й повторно запущено.

### Локалізація падінь за кодом

- `TC-ANL-UI-022` падає на `ProductionAnalyticsUiTest.java:1074`, після
  прямого API-запиту з `resourceIds=[P1, P2]`. Попередні кроки цього тесту:
  UI-експорт із `P1`, скидання фільтра й перевірка `L1`/`L2` — пройшли.
- `TC-ANL-UI-023` падає на `ProductionAnalyticsUiTest.java:1109`, після
  прямого API-запиту з `categoryIds=[C1]`, `resourceIds=[P1]` і `storageIds=[L1]`.
  Попередня перевірка того, що UI передав ці ID в export URL, пройшла.
- У backend `ProductionAnalyticExportFacade` передає один
  `ProductionAnalyticExportFilter` до `getOutput` і `getInput` кожного типу.
  SQL `getOutput` порівнює `categoryIds/resourceIds` з готовим виробом, а
  SQL `getInput` — зі спожитим матеріалом. Тому ID виробу залишає рядок
  виробу, але відкидає його витрати, якщо ID матеріалу інший.
- У frontend snapshot `9be990c`, оглянутому після прогону, таб «Витрати» має
  окремі фільтри матеріалів, але `handleExport` брав `categoryIds/resourceIds`
  зі стану виробів. У новішому frontend `e883fc1` він уже бере ID активного
  таба й додає `kind`, `tags`, `resourceName`; backend `9e6f2278` цих трьох
  нових параметрів не має. Точний frontend build DEV під час прогону не
  зафіксовано. Обидва падіння відбулися на прямих API-запитах, тому зміна
  frontend сама по собі їх не усуває.

На момент прогону тести перевіряли попередню версію `AC-EXCEL-04`: вибраний
виріб мав включати пов'язані витрати. Код `getInput` фільтрував за самим
матеріалом. Пізніше користувач уточнив контракт на користь окремого фільтра
матеріалів; оновлені assertions перевіряють саме його результат.

`getInput` використовує також UI-таб «Витрати», де фільтрація за спожитим
матеріалом є очікуваною. Якщо вибрати варіант із пов'язаними витратами виробу,
міняти спільний SQL `getInput` без окремого export-контексту не можна: це
зламає фільтри таблиці «Витрати». Потрібні окремі параметри або окремий шлях
вибірки для експорту.

### Додаткова розбіжність поточних checkout-ів

Frontend `e883fc1` надсилає `kind`, `tags` і `resourceName` з активного
представлення, але backend `9e6f2278` не має цих полів у
`ProductionAnalyticExportFilter` і завжди формує п'ять аркушів з однакового
набору ID-фільтрів. Це висновок із коду, **не окремий результат DEV-прогону**.
Нові UI-параметри потребують окремої перевірки; `TC-ANL-UI-015` перевіряє
лише два стани без локальних
фільтрів і не покриває їх.

## Назви аркушів

Поточний тестовий контракт і DEV використовують назви «Виготовлення - За виробами»,
«Виготовлення - Витрати», «Розбір - За виробами», «Розбір - Витрати»,
«Несерійне виробництво - Витрати». Вони відрізняються від коротких назв у
початковому формулюванні задачі. Чинна [специфікація](../../REQ-ANL-PRODUCTION-EXCEL-EXPORT.md)
трактує короткі назви як бізнес-ярлики; якщо вони потрібні буквально як назви
вкладок Excel, контракт і продукт потребують окремого узгодження.

## Уточнення контракту після прогону

Користувач уточнив: витратні рядки XLSX мають бути **результатом окремого
фільтра матеріалів**. Вимога, що фільтр «Вироби» автоматично включає пов'язані
витрати, більше не чинна. Тому наведені вище два падіння описують застарілі
assertions; цей історичний результат не слід трактувати як доказ продуктового
дефекту. `TC-ANL-UI-022`, `023` переписані: вони перевіряють вироби на аркуші
результатів, а матеріали на аркуші витрат після вибору окремих UI-фільтрів.

### Звірка з документацією

- `AC-EXCEL-01…03`: кнопка завантажує валідний XLSX; файл має рівно п'ять

- `AC-EXCEL-04`: період, локації, вироби та **окремий фільтр матеріалів**
  застосовуються у перевірених сценаріях. `TC-ANL-UI-021…023` пройшли;
  витрати беруться за ID матеріалу, а попередній ID виробу не передається з
  вкладки «Витрати».
- `AC-EXCEL-05…07`: контрольні суми й числові типи, порожній результат,
  повнота вибірки поза пагінацією та обмеження за правами пройшли у
  `TC-ANL-UI-016…020`, `024…027`; `TC-ANL-UI-028` підтвердив retry.
- Описаний в [as-is документі](../../AS-IS-ANL-PRODUCTION-EXCEL-EXPORT.md)

  тегів або локального пошуку змінює дані XLSX. `TC-ANL-UI-015` звіряє
  два таби без активних фільтрів, а не всі їхні комбінації.
