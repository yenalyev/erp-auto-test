# Перевірка Excel-експорту «Виконання плану» на DEV

Дата перевірки: 25.09.2026
Середовище: `dev` (`https://dev.cukerochka.sbs`)
Кейс: `TC-API-PLANEXEC-002` / `exportHasRequiredColumnsAndFilteredRows`

## Погоджений контракт

Заголовок непорожнього аркуша `Поза планом`:

`Продукт | Категорія | Зроблено | Од. вимір | На складі (<поточна дата>)`

Якщо після фільтрації немає даних для `Поза планом`, аркуш має існувати й може містити лише погоджений рядок заголовків. За відсутності даних `Розбір` має існувати порожнім.

## Результат

Погоджений заголовок підтверджено фактичним DEV-файлом:

`Продукт | Категорія | Зроблено | Од. вимір | На складі (25.09.2026)`

Попередня причина падіння — очікування `Од. виміру` після `Категорія` — більше не є дефектом.

Для категорії без рядків аркуш `Поза планом` існує та містить один допустимий рядок заголовків:

`[[Продукт, Категорія, Зроблено, Од. вимір, На складі (25.09.2026)]]`

Цільовий тест усе ще падає на вимозі формувати файл із відфільтрованих рядків: аркуш `Розбір` для того самого порожнього category-filter не порожній. Крім заголовка `Продукт | Кількість`, DEV повернув сім рядків ресурсів з інших даних. Отже, category-filter до цього аркуша не застосувався.

Отже, поточний DEV-стан:

- порядок і назва колонок `Поза планом` — **PASS**;
- створення всіх трьох аркушів — **PASS**;
- header-only `Поза планом` за відсутності data rows — **PASS**;
- формування `Розбір` лише з відфільтрованих рядків і його порожність за відсутності даних — **FAIL**.

Після актуалізації assertion повторний запуск завершився рівно з одним порушенням — лише для `Розбір` (`Multiple Failures (1 failure)`).

Команда перевірки:

```text
mvn -o test -Dtest=PlanExecutionImprovementApiTest#exportHasRequiredColumnsAndFilteredRows -Denv=dev -Dsuite.artifact.sweep=false -Dgoogle.sheets.enabled=false -Dtcm.enabled=false
```

Maven: `Tests run: 1, Failures: 1, Errors: 0, Skipped: 0`.

## Уточнення контракту 26.09.2026

Власник вимоги уточнив: аркуш `Розбір` показує дані без фільтрації за категорією, пошуком і «Лише обрані». Тому сім рядків після категорійного фільтра без рядків виконання — очікувана поведінка, а не дефект. Висновок **FAIL** вище відображає старий контракт і збережений як історія запуску. Актуальний тест порівнює `Розбір` в експорті без категорійного фільтра та в експортах із двома різними категоріями; порожність цього аркуша очікується лише за відсутності даних розбору у вибраній локації та періоді.
