# Dev ERP: вхід тестового адміністратора блокує Excel-перевірки

**Дата:** 10.10.2026, 15:04–15:14 Europe/Kyiv. **Середовище:** dev ERP. **Обсяг:** перевірки залишків Excel у dev TCM.

## Прояв

Після входу тестового адміністратора автотест багаторазово перевіряє його профіль через `GET /api/v1/users/me`. Dev ERP повертає HTTP 500 із тілом `Something went wrong`. Помилка виникає під час підготовки класу тестів до відкриття книги Excel та до перевірки бізнес-очікувань. Неавторизований запит до того самого маршруту повертав HTTP 401; це не підтверджує працездатність авторизованого сеансу.

## Докази запусків

- Runner `ee94c114-8787-4ceb-92e0-64e4b714610a`, AC-02, suite `inventory`: `InventoryMultiLocationExportApiTest.arrangeMultiLocationOwnerWithStock` завершився на перевірці сеансу з HTTP 500. TC-WMS-007-028 отримав `SKIPPED`; TC-WMS-007-026 не входив до цього suite.
- Runner `8d09ba51-8335-4323-bd78-01f82fdab2b7`, AC-02, suite `regression`: той самий HTTP 500 у підготовці `InventoryMultiLocationExportApiTest` і `OrderBookingApiTest`. Обидва бізнес-тести TC-WMS-007-028 та TC-WMS-007-026 отримали `SKIPPED`.
- Попередній діагностичний запуск TC-ANL-UI-013 зупинився ще до тестів на preflight із HTTP 503. Інший запуск TC-WMS-007-024 отримав текстову відповідь `Service Unavailable` під час підготовки спільних даних.
- О 16:02–16:05 10.10.2026 окремий запуск `RelocationUITest#supplierInvoiceNumberIsPlainTextInReceivedHistory` (TC-WMS-005-001) тричі чекав поле `#username` на сторінці входу адміністратора й кожного разу отримував Playwright `TimeoutError` через 60 секунд. `baseTestClassSetup` завершився з помилкою, сам бізнес-тест пропущено. Це окремий прояв недоступності входу; поведінку номера накладної запуск не перевірив.

Причина відповіді 500/503 без серверних логів невідома. Ці результати не доводять дефект Excel-експорту чи помилку в бізнес-логіці. Прод TCM не має результатів виконання цих нових кейсів.

Для TC-WMS-005-001 після відновлення входу повторити окремий запуск `mvn -q -Denv=dev -Dtest=RelocationUITest#supplierInvoiceNumberIsPlainTextInReceivedHistory test`. До цього його бізнес-результат не визначений.

## Повторна перевірка

Коли авторизований сеанс адміністратора знову отримуватиме HTTP 200 від `users/me`, повторити AC-02 вимоги REQ-WMS-007-EXCEL у `regression` (обидва кейси), її AC-03 та AC-01 у `inventory`, а потім діагностичний TC-ANL-UI-013. Також виконати AC-01 вимоги REQ-WMS-007-EXPORT-COPY у `inventory` та AC-02 у `regression`: він охоплює новий TC-WMS-007-029 на доступну кількість після бронювання. До успішного запуску TC-WMS-007-025 і TC-WMS-007-029 залишаються у статусі `REVIEW`.
