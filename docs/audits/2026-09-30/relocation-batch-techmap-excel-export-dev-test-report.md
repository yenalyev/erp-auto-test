# Переміщення — експорт партій і техкарт: dev-прогін 30.09.2026

## Повторна перевірка після виправлення

30.09.2026 повторно запущено обидва класи на dev з тими самими параметрами, що наведені нижче. Підсумки Maven Surefire:

- `RelocationBatchTechMapExportTest` — **4 PASS / 0 FAIL**. Раніше дефектний `TC-REL-XLS-002` тепер проходить: для трьох партій у файлі кількості 5, 2, 8, сума 15; техкарти відповідають партіям.
- `RelocationBatchTechMapExportUiTest` — **2 PASS / 0 FAIL**. Експорт з вкладок «Отримано» та «Видано» завантажує XLSX і містить очікувані рядки.

Обидва процеси Maven завершилися з кодом `0`; у `target/surefire-reports/` для класів немає failures, errors або skipped. Нижче збережено результат первинного прогону до виправлення для історії дефекту.

## Реалізовано

- `RelocationBatchTechMapExportTest`: `TC-REL-XLS-001…004`. Фікстура створює ізольований продукт, дві техкарти, три вироблені партії 5/2/8, окремий ресурс із невиробленою партією та видачу з явними UUID партій. Тест читає XLSX через Apache POI й зіставляє рядки за ресурсом і номером партії.
- `RelocationBatchTechMapExportUiTest`: `TC-REL-XLS-005…006`. Під власником локації браузер завантажує Excel з вкладок **«Отримано»** та **«Видано»** сторінки `/relocations`. Перевіряються заголовки, ID переміщення, партія та кількість. Обидва UI-кейси використовують період «1 день».
- Дію завантаження додано до `RelocationPage`; класи внесено до `relocations.xml`, `ui.xml`, `regression.xml`.

## Первинний прогін до виправлення

Команда API: `mvn test -Denv=dev -Dtest=RelocationBatchTechMapExportTest -Dtcm.enabled=false -Dgoogle.sheets.enabled=false`.

- `TC-REL-XLS-001` — **PASS**: у файлі є «Партія» і «Тех карта» в очікуваному порядку.
- `TC-REL-XLS-002` — **FAIL, дефект експорту**: три партії одного ресурсу з кількостями 5, 2, 8 виведені трьома рядками, техкарти відповідають партіям, але в колонці «Кількість» кожного рядка стоїть **15**. Сума Excel-рядків — **45** замість 15. Повторено в двох повних API-прогонах.
- `TC-REL-XLS-003` — **PASS**: рядки партій двох ресурсів в одному переміщенні не змішані; для другого ресурсу кількість 3.
- `TC-REL-XLS-004` — **PASS**: невироблена партія є в експорті, техкарта для неї відсутня.

Команда UI: `mvn test -Denv=dev -Dtest=RelocationBatchTechMapExportUiTest -Dtcm.enabled=false -Dgoogle.sheets.enabled=false`.

- `TC-REL-XLS-005` — **PASS**: «Отримано» завантажує валідний XLSX із новими колонками та рядком тестового отримання: партія, кількість 4.
- `TC-REL-XLS-006` — **PASS**: «Видано» завантажує валідний XLSX із новими колонками та рядком тестової видачі: та сама партія, кількість 2.

Первинний повний API-прогін: **3 PASS / 1 FAIL**; UI-прогін: **2 PASS / 0 FAIL**. У попередніх UI-спробах експорт на dev іноді тривав понад стандартні 30 секунд Playwright, тому для цієї дії встановлено очікування 120 секунд і звужено період до одного дня. Обидва кейси після цього завершилися без помилок. Старий пробний запуск на `/history` був поза вимогою: користувач уточнив, що «Історія переміщень» означає вкладки «Видано/Отримано» на `/relocations`; його результат не враховується. Три пізніші API-запуски не дійшли до кейсів через timeout dev-авторизації Playwright (`#username`, 60 секунд); їх не враховано як результат фічі.

## Дії для розробки та QA

1. У `GET /api/v1/relocations/export` заповнювати «Кількість» із кількості конкретної партії в позиції переміщення, а не із загальної кількості позиції. Після виправлення повторити `TC-REL-XLS-002` і перевірити суму 5 + 2 + 8 = 15. Готовий [опис дефекту для Jira](relocation-batch-quantity-excel-jira-bug.md) містить кроки відтворення та команду QA.
2. Додати крайові кейси `007–011` із тестового плану після погодження формату відсутньої техкарти, правила історичної назви й legacy-записів. UI-кейси зараз перевіряють відкриття обох вкладок та їхній файл із невиробленою партією; значення техкарти для виробленої партії предметно перевіряє API-кейс `002`.

## Очищення даних

Поточна фікстура перед видаленням створеної видачі переводить її через `CANCELLED → RETURNED`, тоді видаляє виробництва, деактивує створені техкарти й ресурси та повертає режим техкарти локації до `READ_ONLY`. Перший пробний прогін до цього виправлення видалив видачу без повернення партій; API відхилив видалення виробництв `14765–14767` через недостатній залишок. Їхній продукт `13277` і техкарти `5271–5272` були деактивовані. Ці старі dev-записи потребують окремого безпечного очищення після відновлення пов'язаного запасу.

Вихідні звіти останніх прогонів: `target/surefire-reports/` (локальні файли перезаписуються наступним Maven-прогоном).
