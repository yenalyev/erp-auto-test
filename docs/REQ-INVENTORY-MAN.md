## Документація

| Розділ UI | Маршрут | Призначення |
|-----------|---------|-------------|
| Залишки | `/unit-management` | Перегляд залишків; відкриття/закриття сесії (Admin); перехід до проведення |
| Проведення інвентаризації | `/inventory/{storageId}` | Коригування кількостей ресурсів |
| Експорт залишків | `/export-analytics` → «Залишки» | Excel |
| Історія операцій | `/history` | ADDED_INV / REMOVED_INV після інвентаризації |

**Ролі:**

| Роль | Відкрити/закрити сесію | Провести інвентаризацію | Перегляд залишків |
|------|------------------------|-------------------------|-------------------|
| **Admin** | ✓ | ✓ | ✓ |
| **Owner 1** | ✗ | ✓ (на своєму BU, сесія відкрита) | ✓ |
| **Owner 2** | ✗ | ✗ на BU Owner 1 | обмежено |
| **Audit** | ✗ | ✗ | ✓ (read) |

**Обов'язково:** у шапці SPA обрана **конкретна локація** (не «Всі локації») для дій з сесією та проведенням.

### Життєвий цикл

```
Закрито → Admin «Відкрити інвентаризацію» → Відкрито
    → Owner/Admin «Провести інвентаризацію» → зміна amount → «Зберегти»
    → Admin «Закрити інвентаризацію» → Закрито
```

# A. REQ-WMS-003 — Сесія інвентаризації

## Test Case: TC-WMS-003-001 / Admin відкриває сесію інвентаризації

**HIGH · CRITICAL · ACTIVE · Admin**  
**AC:** AC-01  
> **Автоматизовано:** `TC-UI-INV-001`

### Мета

@Admin відкриває сесію інвентаризації на сторінці «Залишки».

### Preconditions

@Admin залогінений. Обрана локація Owner 1. Сесія закрита.

### Expected result (тест)

Сесія відкрита: кнопка «Закрити інвентаризацію», «Провести інвентаризацію» активна; API `open=true`.

### Steps

1. Увійти під @Admin. У шапці обрати склад Owner 1 (не «Всі локації»).  
   **Expected:** авторизація успішна; у шапці — назва локації.

2. Меню → **«Залишки»** (`/unit-management`).  
   **Expected:** заголовок «Управління запасами — {назва локації}»; таблиця залишків.

3. Знайти кнопку **«Відкрити інвентаризацію»** (іконка замка).  
   **Expected:** кнопка видима та **enabled**.

4. Натиснути **«Відкрити інвентаризацію»**.  
   **Expected:** кнопка → **«Закрити інвентаризацію»**; зелена рамка; іконка відкритого замка.

5. Перевірити **«Провести інвентаризацію»**.  
   **Expected:** кнопка **активна**; немає tooltip про адміністратора.

6. *(Опційно)* DevTools: `PUT .../inventory/status {"open":true}` → 200; `GET status` → `open:true`.  
   **Expected:** API підтверджує відкриту сесію.

7. **Cleanup:** «Закрити інвентаризацію».  
   **Expected:** сесія закрита.

# B. REQ-WMS-003 — Проведення інвентаризації

## Test Case: TC-WMS-003-006 / Owner змінює кількість ресурсу

**HIGH · CRITICAL · Owner**  
**AC:** AC-06, AC-08

### Preconditions

Сесія відкрита Admin-ом. «Ресурс-А» з залишком 10 од.

### Expected result

Залишок «Ресурс-А» = **15 од.** на «Залишках».

### Steps

1. Зафіксувати залишок «Ресурс-А» на «Залишках» (**10 од.**).  
   **Expected:** `amount_before = 10`.

2. **«Провести інвентаризацію»** → знайти «Ресурс-А».  
   **Expected:** поле кількості = 10; delta = 0.

3. Змінити кількість на **15**.  
   **Expected:** delta **+5.00** (зелений).

4. **«Зберегти»**.  
   **Expected:** успіх; повернення на «Залишки».

5. Перевірити «Ресурс-А» у таблиці.  
   **Expected:** **15 од.**

6. Cleanup: Admin закриває сесію.
