# Тест кейси: нульовий залишок зі сповіщенням

## TC-ALERT-006 — hierarchy API, вимкнені нулі

**P0, автоматизовано.** У новій локації створити ресурси A (сповіщення з порогом, `amount=0`) і B (без сповіщення, збережений `StorageItem.amount=0`). Через single-storage API перевірити передумови. Викликати hierarchy GET з `parentStorageId=<локація>`, `showZeroStock=false`, окремо для A та B. **Очікування:** A є, B немає. Повторити з `showZeroStock=true`: є обидва. Автотест: `AlertStockHighlightApiTest.alertedZeroStockIsIncludedWhenShowZeroStockIsFalse`.

## TC-UI-ALERT-005 — сторінка «Залишки», вимкнений тогл

**P0, автоматизовано.** Під Admin відкрити нову локацію з A, B і ресурсом C з додатним залишком. Вимкнути «Показувати нульові залишки», знайти ресурси за унікальним префіксом. **Очікування:** тогл вимкнений; A є, має кількість `0` і бейдж «відсутній»; B немає; C є. Увімкнути тогл — A і B є з `0`. Вимкнути тогл, видалити сповіщення A, оновити таблицю — A і B приховані, C лишився. Автотест: `AlertStockHighlightUiTest.zeroStockWithAlertRemainsVisibleWhenToggleIsOff`.

## TC-UI-ALERT-006 — сповіщення лише в іншій локації

**P1, ручний / запланований.** Для ресурсу A зробити `amount=0` у двох локаціях, сповіщення налаштувати лише в першій. При вимкненому тоглі A має бути видимим у першій локації та прихованим у другій. Вигляд «Всі локації» перевірити окремо після узгодження агрегованого правила.

## TC-UI-ALERT-007 — пошук, пагінація й зміна залишку

**P1, ручний / запланований.** Для A зі сповіщенням перевірити пошук і перехід між сторінками при вимкненому тоглі; A має бути один раз. Провести `>0 → 0 → >0` і оновити таблицю. Рядок A має лишатися видимим, кількість і бейдж мають відповідати поточному залишку.
