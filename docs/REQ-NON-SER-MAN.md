**Несерійне виробництво (REQ-NON-SER-MAN)**

---

## Документація

Для ролі **owner** (для несерійного виробництва локації owner-а):

- якщо статус задачі **«Завершено»** — право редагувати або видаляти запис несерійного виробництва лише **2 дні** після переведення в статус «Завершено»
- якщо статус задачі **«В роботі»** — право редагувати або видаляти запис несерійного виробництва **не обмежується**

---

## Acceptance Criteria

**AC-01:** @Owner @Admin можуть списувати ресурси на несерійне виробництво, якщо залишок ≥ 0

**AC-02:** @Owner може редагувати/видалити несерійне виробництво в статусі «Завершено» протягом 2-х днів з моменту завершення

**AC-03:** @Admin може редагувати/видалити несерійне виробництво в статусі «Завершено» за будь-який час

**AC-04:** @Owner @Admin можуть редагувати несерійне виробництво в статусі «В роботі» за будь-який час

**AC-05:** При видаленні несерійного виробництва — ресурси повертаються на склад

**AC-06:** @Owner @Admin можуть створити несерійне виробництво без ресурсів

**AC-07:** При переводі @Owner @Admin в статус «Завершено» — міняється лише статус; валідація залишків на складі не відбувається

## Test Case: TC-NON-SER-MAN-001 / В блок «Використана сировина» не можна ввести значення більше ніж є на складі

**HIGH · MAJOR · ACTIVE**

> **Автоматизовано:** частково — API `TC-NSP-002`; UI — **ні**

### Мета / опис

@Owner @Admin не можуть ввести в блок «Використана сировина» витрату сировини більше ніж є на складі.

### Preconditions

@Owner залогінений. Обрана локація owner-а. На складі є хоча б один ресурс із ненульовим залишком.

### Steps

1. Перейти в розділ **Несерійне виробництво** (`/non-series-production`), натиснути **«+ Новий виріб»**  
   **Expected:** редирект на сторінку «Створення виробу» `/non-series-production/create`

2. Ввести унікальну назву виробу, **Кількість** — 1 од.

3. У блоці **«Використана сировина»** додати ресурс і вказати витрату на одиницю = поточний залишок на складі **+ 1**  
   **Expected:** попередження про недостатню кількість сировини; кнопка **«Зберегти виріб»** — неактивна.

4. *(Додаткова перевірка)* Спробувати зберегти через API або DevTools, якщо кнопка активна  
   **Expected:** запис не створюється, залишок на складі не змінюється.

## Test Case: TC-NON-SER-MAN-002 / Тест валідації використаних ресурсів на несерійне виробництво

**HIGH · MAJOR · ACTIVE**

> **Автоматизовано:** частково — API `TC-NSP-002` (відхилення при 1 од. і надмірній витраті); сценарій «2 од. × max запас» — **ні**

### Мета / опис

@Owner @Admin не можуть зробити більше несерійних виробів ніж є запасів ресурсів на складі.

### Preconditions

@Owner залогінений. На складі є ресурс із відомим залишком (наприклад, N од.).

### Expected result

Залишок ресурсу на складі ≥ 0.

### Steps

1. Перейти в розділ **Несерійне виробництво** (`/non-series-production`), натиснути **«+ Новий виріб»**  
   **Expected:** редирект на сторінку «Створення виробу» `/non-series-production/create`

2. Ввести назву виробу. У блоці **«Використана сировина»** додати ресурс із витратою на одиницю = **весь поточний залишок** (N од.).

3. Поле **Кількість** — поставити **2**, натиснути **«Зберегти виріб»**  
   **Expected:** дані не зберігаються; попап з поясненням (потрібно більше ресурсів ніж є на складі). Залишок на складі не змінився.

4. Перевірити розділ **Залишки** — кількість ресурсу лишилась N од.

## Test Case: TC-NON-SER-MAN-003 / Можна створити запис про несерійне виробництво

**CRITICAL · MAJOR · ACTIVE**

> **Автоматизовано:** так — API `TC-NSP-001`, UI `TC-UI-NSP-001`

### Мета / опис

@Owner @Admin можуть створити запис про несерійне виробництво.

### Preconditions

@Owner залогінений. На складі достатньо сировини для списання.

### Expected result

Можна створити несерійне виробництво і списати на нього ресурси.

### Steps

1. Зафіксувати поточний залишок обраного ресурсу в **Залишки**.

2. Перейти в розділ **Несерійне виробництво** (`/non-series-production`), натиснути **«+ Новий виріб»**  
   **Expected:** редирект на сторінку «Створення виробу» `/non-series-production/create`

3. Ввести унікальну назву виробу, **Кількість** — 1 од., статус **«В роботі»**. Додати використану сировину (витрата на одиницю ≤ залишку на складі). Натиснути **«Зберегти виріб»**  
   **Expected:** несерійне виробництво збережене, редирект на `/non-series-production`, у журналі статус — **«В роботі»**.

4. Перевірити **Залишки** — залишок ресурсу зменшився на `витрата × кількість`.

## Test Case: TC-NON-SER-MAN-004 / Видалення несерійного виробництва в статусі: Завершено (Happy path)

**MEDIUM · MAJOR · ACTIVE**

> **Автоматизовано:** **ні**

### Мета / опис

@Owner може видалити несерійне виробництво в статусі завершено, протягом 2 днів з моменту завершення.

### Preconditions

@Owner залогінений. Запис ще не старший за 2 дні після завершення.

### Expected result

Може видалити несерійне виробництво в статусі завершено; ресурси повертаються на склад.

### Steps

1. Перейти в розділ **Несерійне виробництво** (`/non-series-production`), натиснути **«+ Новий виріб»**  
   **Expected:** відкриється форма створення несерійного виробництва.

2. Заповнити форму: назва виробу, ресурси, статус **«Завершено»**. Зберегти.  
   **Expected:** запис збережено; ресурси списано (у **Залишки** — менший залишок).

3. Зафіксувати залишок ресурсу після створення.

4. У журналі несерійного виробництва знайти запис і натиснути **«Видалити»**, підтвердити.  
   **Expected:** запис видалено; ресурси повернено на склад (залишок відновився); записи про витрати зникли з **Історії операцій**.

## Test Case: TC-NON-SER-MAN-005 / Перевести несерійне виробництво з статусу «В роботі» в статус «Завершено»

**MEDIUM · MAJOR · ACTIVE**

> **Автоматизовано:** так — UI `TC-UI-NSP-001`, `TC-UI-NSP-002`

### Мета / опис

@Owner може перевести несерійне виробництво з статусу «В роботі» в статус «Завершено» незалежно від наявних залишків.

### Preconditions

@Owner залогінений.

### Expected result

Можна перевести запис з «В роботі» в «Завершено» навіть коли залишок використаного ресурсу на складі = 0.

### Steps

1. Перейти в **Несерійне виробництво** → **«+ Новий виріб»**.

2. Створити запис: статус **«В роботі»**, кількість 1 од., у **«Використана сировина»** вказати витрату = **весь поточний залишок** обраного ресурсу. Зберегти.  
   **Expected:** запис створено; у **Залишки** залишок цього ресурсу = 0.

3. У журналі натиснути **«Редагувати»** для створеного виробу.

4. Змінити статус на **«Завершено»**, зберегти.  
   **Expected:** статус у журналі — **«Завершено»**; додаткових помилок валідації залишків немає (AC-07).

## Test Case: TC-NON-SER-MAN-006 / Створення 2 од. — коректне списання сировини

**CRITICAL · MAJOR · ACTIVE**

> **Автоматизовано:** так — API `TC-NSP-003`, UI `TC-UI-NSP-002`

### Мета / опис

@Owner може створити несерійне виробництво на 2 од. і коректно списати сировину зі складу.

### Preconditions

@Owner залогінений. На складі достатньо сировини (наприклад, ≥ 6 од. для витрати 3 од./од.).

### Expected result

Списано `витрата_на_одиницю × 2`; запис у журналі з кількістю 2 од.

### Steps

1. Зафіксувати залишок ресурсу в **Залишки**.

2. **Несерійне виробництво** → **«+ Новий виріб»**. Назва виробу, **Кількість** — **2**, статус **«В роботі»**. Додати сировину з витратою на одиницю, що дає загальне списання ≤ залишку (наприклад, 3 од./од.). Зберегти.  
   **Expected:** редирект на журнал; виріб з кількістю 2 од., статус «В роботі».

3. Перевірити **Залишки**: залишок зменшився на `витрата × 2`.

4. *(Опційно)* Відкрити запис на редагування → **«Завершено»** → зберегти.  
   **Expected:** статус «Завершено» без додаткової валідації залишків.

## Test Case: TC-NON-SER-MAN-007 / «Загальний об'єм» відповідає відфільтрованим записам

**CRITICAL · MAJOR · ACTIVE**

> **Автоматизовано:** так — API `TC-NSP-004`, UI `TC-UI-NSP-003`

### Мета / опис

Після фільтрів **«Пошук виробу»** та **«Статус»** на екрані журналу показується **«Загальний об'єм: N од»**, де N дорівнює сумі кількостей відфільтрованих записів.

### Preconditions

@Owner залогінений. У журналі є щонайменше два записи з однаковим фрагментом у назві виробу, але різним статусом (наприклад, один «В роботі» на 2 од., інший «Завершено» на 3 од.).

### Steps

1. Перейти в **Несерійне виробництво** (`/non-series-production`).

2. У фільтрі **«Пошук виробу»** ввести спільний фрагмент назви (префікс тестових записів).

3. У фільтрі **«Статус»** обрати **«В роботі»**.  
   **Expected:** у списку лише записи «В роботі»; **«Загальний об'єм»** = сума їхніх кількостей (для прикладу вище — **2 од.**).

4. Змінити статус фільтра на **«Завершено»**.  
   **Expected:** **«Загальний об'єм»** оновився (для прикладу — **3 од.**).

5. Очистити фільтр статусу.  
   **Expected:** **«Загальний об'єм»** = сума всіх записів, що відповідають пошуку (для прикладу — **5 од.**).

## Test Case: TC-NON-SER-MAN-009 / Редагування завершеного запису @Admin

## Test Case: TC-NON-SER-MAN-010 / Обмеження 2 дні для @Owner після «Завершено»

**MEDIUM · MAJOR · ACTIVE**

> **Автоматизовано:** **ні** (AC-02)

### Мета / опис

@Owner **не може** редагувати або видалити несерійне виробництво в статусі «Завершено», якщо з моменту завершення минуло більше 2 днів.

### Preconditions

@Owner залогінений. Є запис у статусі «Завершено», завершений **понад 2 дні тому** (потрібні тестові дані або зміна дати в БД).

### Steps

1. Відкрити журнал **Несерійне виробництво**, знайти старий завершений запис.

2. Перевірити наявність кнопок **«Редагувати»** / **«Видалити»**.  
   **Expected:** дії недоступні або при спробі — повідомлення про обмеження терміну.

3. Порівняти з записом «Завершено», створеним сьогодні.  
   **Expected:** для свіжого запису редагування/видалення **доступне**.
