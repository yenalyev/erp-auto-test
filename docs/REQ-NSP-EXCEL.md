# Несерійне виробництво — експорт в Excel

## Фіча

`REQ-NSP-EXCEL`, дочірня фіча `REQ-NON-SER-MAN`. Пріоритет: HIGH.

Користувач журналу «Несерійне виробництво» завантажує Excel за допомогою кнопки
«Експорт в Excel». Файл містить усю вибірку за активними фільтрами журналу:
локація, назва виробу, використаний матеріал, період і статус. Перехід між сторінками
не обмежує експорт поточною сторінкою. Після зміни або очищення фільтрів наступне
завантаження відображає актуальну вибірку.

Початкова вимога: **активні фільтри мають впливати також на результати в Excel**.
Період застосовується до дати початку виробництва; межі включні. Різні фільтри
поєднуються через AND; кілька статусів чи локацій усередині одного параметра — через OR.
Пошук назви та матеріалу підтримує підрядок і не залежить від регістру.

## Критерії приймання

- **AC-01.** Excel застосовує поточні локації, пошук назви виробу, пошук фактично використаного матеріалу, включні межі періоду за датою початку та статус. Кожен фільтр окремо обмежує склад файлу так само, як журнал; без додаткових фільтрів експортуються всі записи вибраної локації.
- **AC-02.** Одночасно активні фільтри застосовуються через AND. Файл містить усі відповідні вироби й виключає невідповідні; збіг лише в назві або описі не задовольняє фільтр використаного матеріалу.
- **AC-03.** Після зміни, часткового очищення або загального очищення фільтрів наступний експорт використовує нові умови без попередніх значень. Очищення одного поля зберігає решту фільтрів; загальне очищення зберігає вибрану локацію.
- **AC-04.** Для вибірки без збігів журнал показує нульовий об’єм, а Excel успішно завантажується й містить тільки заголовки, без сторонніх записів.
- **AC-05.** Експорт містить усі записи відфільтрованої вибірки незалежно від поточної сторінки та розміру сторінки журналу, без пропусків і дублів.
- **AC-06.** Завантажується читабельний файл «Несерійне виробництво.xlsx» з аркушем «Несерійне виробництво». Заголовки: Дата, Продукт, Локація/Організм, Об'єм, Використана сировина, Кількість, Од. вимір, Люди, Статус. Значення відповідають записам журналу; об’єм, кількість сировини й люди — числові комірки. Усі матеріали знайденого виробу зберігаються, навіть якщо частина не відповідає пошуку матеріалу; вироби без сировини також підтримуються.
- **AC-07.** Файл обмежений вибраними локаціями. Експорт не змінює виробничі записи, загальні об’єми чи складські залишки вибраної та сусідньої локацій.

## Контракт API і UI

`GET /api/v1/non-series-production/export` використовує `storageIds` та необов’язкові
`productSearch`, `resourceSearch`, `startDate`, `endDate`, `statuses`. API-список і
`/total` отримують ті самі бізнес-фільтри. UI не передає `page` і `size` в експорт.
Прямий API-виклик експорту також не повинен обрізатися переданими `page`/`size`.
Дати передаються у форматі `yyyy-MM-dd`, у файлі показуються як `dd.MM.yyyy`.

Статуси: `IN_PROGRESS` → «В роботі», `DONE` → «Завершено». UI дозволяє вибрати один
статус або «Всі статуси»; API додатково перевіряє повторювані `statuses`.

Назва й об’єм виробу можуть бути об’єднані вертикально для кількох матеріалів.
Тому кількість фізичних рядків Excel не дорівнює кількості виробів. Тест порівнює
блоки виробів, числові значення та матеріали; порядок виробів не фіксується.

Джерела контракту, прочитані без змін: `tk-ui/src/pages/non-series-production/NonSeriesProductionListPage.tsx`,
`tk/.../controller/NonSeriesProductionController.java`, `tk/.../dao/NonSeriesProductionSpecifications.java`,
`tk/.../facade/NonSeriesProductionExportFacade.java`.

## Тест-план

Рівні: API та UI з реальним backend dev. Авторизація ADMIN через наявний браузерний
механізм сесії. Підготовка — через `NonSeriesResourceFilterFixture`; кожен клас має
власні локації, ресурси й операції. Очікувані вироби визначаються з контрольних даних,
а не лише порівнянням двох відповідей сервера, що могли б мати однакову помилку.

Контрольні дані основної локації:

- Альфа: 2 од., «В роботі», сьогодні, матеріал Мідь A.
- Бета: 3 од., «Завершено», сьогодні, Мідь A + Мідь A2 + Сталь B.
- Виріб зі словом Мідь у назві та описі: 5 од., сьогодні, використовує тільки Сталь B.
- Без сировини: 7 од., сьогодні, «В роботі».
- Раніше: 11 од., десять днів тому, «В роботі», матеріал Мідь A.
- Сусідня локація: окремий виріб 13 од., той самий матеріал Мідь A.

Усього основна локація: 5 виробів, об’єм 28. Пошук Мідь: 3 вироби, об’єм 16.
Сьогодні: 4 вироби, об’єм 17. Для UI-пагінації додається 21 власний виріб без
сировини по 1 од.: 26 виробів, об’єм 49; друга сторінка при size=25 містить один виріб.
Імена мають унікальний маркер кожного прогону.

Після класу видаляються власні виробництва й отримання сировини, перевіряється нульовий
залишок, архівуються власні локації та виконується спроба деактивації ресурсів.
Наявне обмеження ERP: деактивація ресурсу може відхилятися через нульові складські рядки
на вже архівованих локаціях; фікстура записує це в лог.

Продуктивність великих файлів, нові правила RBAC, форматування ширини колонок і
експорт інших модулів не входять до цієї фічі.

## Тест-кейси

Усі наведені кейси автоматизовані через `@TestCaseId`; API-клас
`NonSeriesExcelExportApiTest`, UI-клас `NonSeriesExcelExportUiTest`.
Передумови для кожного: доступний dev, сесія ADMIN та успішно створені контрольні дані.
Помилки підготовки чи продукту не перетворюються на успішний результат або навмисний SKIP.

### TC-NSP-XLSX-API-001 — Повний файл і поля виробів

АС: AC-01, AC-06. Метод: `exportsUnfilteredSelectionAndWorkbookFields`.

1. Прочитати список основної локації без додаткових фільтрів.
2. Завантажити `/export` з тим самим `storageIds`.
3. Перевірити attachment, аркуш, дев’ять заголовків і кожне поле всіх блоків виробів.

Очікування: рівно 5 виробів, включно з виробом без сировини; усі матеріали та числові
комірки коректні; стороння локація відсутня.

### TC-NSP-XLSX-API-002 — Назва виробу

АС: AC-01. Метод: `filtersByProduct`.

1. Послідовно встановити повну назву Альфи, `альфа`, `АЛЬФА`.
2. Для кожного значення прочитати список та експортувати Excel.
3. Порівняти точний склад і поля файлу.

Очікування: кожного разу тільки Альфа, 2 од.; решта виробів виключена.

### TC-NSP-XLSX-API-003 — Статуси

АС: AC-01. Метод: `filtersByStatus`.

1. Експортувати `DONE`, потім `IN_PROGRESS`, потім обидва статуси.
2. Звірити список, точний склад файлу та текст статусу кожного виробу.

Очікування: Бета; потім Альфа + виріб Сталь + Без сировини + Раніше; потім усі п’ять.

### TC-NSP-XLSX-API-004 — Період і його межі

АС: AC-01. Метод: `filtersByInclusiveDateRange`.

1. Перевірити сьогодні–сьогодні та лише startDate=сьогодні.
2. Перевірити лише endDate=вчора та історичний день десять днів тому.
3. Перевірити весь діапазон від історичного дня до сьогодні.

Очікування: 4 сьогоднішні вироби; окремо Раніше; потім усі 5. Обидві межі включні,
вибірка визначається датою початку, а не датою завершення.

### TC-NSP-XLSX-API-005 — Матеріал і перетин усіх фільтрів

АС: AC-01, AC-02, AC-06. Метод: `intersectsAllFiltersAndKeepsAllMaterials`.

1. Експортувати за підрядком матеріалу Мідь та його верхнім регістром.
2. Додати назву Бети, DONE і сьогодні–сьогодні.
3. Звірити всі матеріали знайдених виробів.

Очікування: спочатку Альфа + Бета + Раніше; потім тільки Бета, 3 од., із трьома
матеріалами включно зі Сталлю. Збіг Мідь лише в назві/описі іншого виробу не включає його.

### TC-NSP-XLSX-API-006 — Порожній результат і нові фільтри

АС: AC-03, AC-04. Метод: `handlesNoMatchesAndChangedFilters`.

1. Експортувати неіснуючу назву та несумісний перетин матеріалу з назвою виробу Сталь.
2. Послідовно експортувати Альфу, Бету та вибірку без пошуку.

Очікування: два файли тільки із заголовками; потім відповідно Альфа, Бета й усі п’ять.
Попередні умови не впливають на наступні запити.

### TC-NSP-XLSX-API-007 — Усі сторінки та локації без мутацій

АС: AC-05, AC-07. Метод: `exportsAllPagesAndScopesLocationsWithoutMutations`.

1. Зберегти повні виробничі записи й залишки обох локацій; отримати список page=1, size=1.
2. Експортувати з page=1, size=1; окремо другу локацію; потім обидві локації разом.
3. Повторно звірити повні записи, об’єм і залишки кожної локації.

Очікування: список має 1 виріб, перший файл усі 5; друга локація тільки свій виріб;
обидві локації — 6 виробів без дублів. Повні записи, об’єми 28 і 13 та всі залишки незмінні.

### TC-NSP-XLSX-UI-001 — Кожен активний UI-фільтр

АС: AC-01, AC-06. Метод: `exportsEachActiveFilter`.

1. Відкрити основну локацію й очистити фільтри.
2. Окремо застосувати назву Альфи, DONE, сьогодні–сьогодні, матеріал Мідь;
   між перевірками очищати фільтри.
3. Для кожної умови натиснути «Експорт в Excel», звірити query, назву файлу,
   точні рядки й об’єм журналу та кожне поле Excel; зберегти скріншот в Allure.

Очікування: Альфа/2; Бета/3; чотири сьогоднішні вироби/17; Альфа+Бета+Раніше/16.
Кнопка доступна після кожного завантаження, `page`/`size` відсутні у query export.

### TC-NSP-XLSX-UI-002 — Поєднання, зміна й очищення UI-фільтрів

АС: AC-02, AC-03. Метод: `exportsCombinedChangedAndClearedFilters`.

1. Встановити матеріал Мідь, сьогодні–сьогодні, DONE та назву Бети; експортувати.
2. Очистити тільки назву, змінити статус на «В роботі»; експортувати з рештою умов.
3. Натиснути «Очистити», експортувати знову; звірити порожні поля пошуку.

Очікування: тільки Бета/3; потім тільки Альфа/2; потім усі п’ять/28. Запити й файли
відповідають поточним умовам, локація зберігається. Три скріншоти й файли в Allure.

### TC-NSP-XLSX-UI-003 — Експорт порожнього журналу

АС: AC-04. Метод: `exportsEmptySelection`.

1. Увести унікальну назву без збігів.
2. Перевірити «Записів не знайдено» та об’єм 0; зробити скріншот.
3. Завантажити Excel і перевірити його вміст.

Очікування: коректний файл тільки з дев’ятьма заголовками, без даних; кнопка знову доступна.

### TC-NSP-XLSX-UI-004 — Експорт із другої сторінки

АС: AC-05, AC-07. Метод: `exportsEveryPageFromSecondUiPage`.

1. Додати 21 власний виріб; зберегти залишки обох локацій.
2. Вибрати size=25 і перейти на другу сторінку; перевірити один видимий рядок та об’єм 49.
3. Зробити скріншот, завантажити Excel, звірити всі 26 виробів і повторно залишки.

Очікування: файл містить 26 виробів без дублів, включно з першою сторінкою, без виробу
сусідньої локації; `page`/`size` відсутні; залишки незмінні.

## Запуск і звітність

Класи включені до `non-series-production` і `regression`; API також до `functional`, UI до `ui`.
Окремий запуск фічі:

```powershell
$env:JAVA_HOME='C:\Users\gigam\.jdks\corretto-21.0.9'
$env:PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD='1'
mvn -o test -Denv=dev '-Dtest=NonSeriesExcelExportApiTest,NonSeriesExcelExportUiTest' '-Dtest.output.directory=logs/nsp-excel-build' '-Dallure.results.directory=logs/nsp-excel-allure' -Dframework.browser.channel=chrome -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
mvn -o test -Dsuite=framework '-Dtest.output.directory=logs/nsp-excel-framework' -Dtcm.enabled=false -Dgoogle.sheets.enabled=false
```

`-Dtest` обходить suite-listeners; фактичні результати такого запуску імпортуються до TCM
окремо з Surefire. Для стандартної звітності доступний `-Dsuite=non-series-production`.

експорт не змінив записи, об’єми чи залишки. Завантажено й перевірено 32 Excel-файли:
23 через API та 9 через UI. Файли й скріншоти доступні у звіті та Allure.
