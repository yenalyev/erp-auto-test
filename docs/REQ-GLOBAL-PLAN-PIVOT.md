# Глобальний план — pivot view «Ресурси»

## Призначення

Сторінка `/global-plans` має два взаємозамінні представлення тих самих глобальних планів:

- «Список» — наявний список планів із періодом, описом, output, статусом і діями;
- «Ресурси» — pivot-таблиця, у якій рядки відповідають output-ресурсам, а колонки — періодам глобальних планів.

Фіча не вводить нового backend endpoint. Обидва представлення будуються з відповіді
`GET /api/v1/global-plans`.

## Правила перемикання

- `/global-plans` без параметра `view` відкриває «Список»;
- натискання «Ресурси» встановлює `view=resources` і показує pivot;
- натискання «Список» прибирає параметр `view`;
- пряме відкриття `/global-plans?view=resources` показує pivot без проміжного ручного перемикання;
- reload зберігає режим, оскільки він визначається URL;
- одночасно активний рівно один перемикач.

## Побудова pivot

- перша колонка має заголовок «Ресурс»;
- кожен унікальний output-ресурс представлений одним рядком;
- у назві рядка показуються назва ресурсу та його поточна скорочена одиниця виміру;
- періоди формують колонки у спадному порядку: спочатку новіший рік і місяць;
- значення комірки дорівнює сумі output-кількості ресурсу в плані відповідного періоду;
- якщо ресурс відсутній у плані періоду, показується `—`, а не `0` і не порожня комірка;
- рядки ресурсів сортуються за назвою з українською locale;
- у pivot потрапляють плани незалежно від того, чи згенеровані для них location plans: джерелом є `globalPlan.output`.

## Фільтр категорій

- фільтр «Категорії» доступний лише у view «Ресурси»;
- список опцій формується з категорій output-ресурсів, які присутні в отриманих глобальних планах;
- одна вибрана категорія залишає ресурси лише цієї категорії;
- кілька категорій об'єднуються за OR;
- порожній вибір означає «Всі»;
- фільтрація не змінює набір або порядок колонок і не змінює суми.

## Стани

- під час `GET /global-plans` показується «Завантаження планів...»;
- якщо планів або output-ресурсів немає, pivot показує «Немає ресурсів для відображення»;
- помилка завантаження показує «Не вдалося завантажити глобальні плани»;
- таблиця підтримує вертикальний і горизонтальний scroll; header і колонка ресурсу залишаються sticky.

## Acceptance criteria

1. Користувач може без перезавантаження перемикатися між «Список» і «Ресурси».
2. Активний режим однозначно відображається станом перемикача та query-параметром.
3. Pivot відтворює точні output-значення для кожної пари ресурс/період.
4. Один ресурс, присутній у кількох планах, не дублює рядок.
5. Періоди впорядковані від нового до старого.
6. Відсутність ресурсу в періоді позначається `—`.
7. Category multiselect фільтрує рядки за exact category ID та OR-семантикою.
8. Deep link `?view=resources` і reload зберігають pivot view.
9. Завантаження, empty state та error state завершуються визначеним UI-станом без нескінченного spinner.

## Автоматизоване покриття

Клас `GlobalPlanPivotUiTest` створює через API дві ізольовані production-техкарти з output-ресурсами
у різних наявних категоріях та два глобальні плани у вільних майбутніх періодах. Після класу плани
видаляються, техкарти й створені ресурси деактивуються.

- `TC-GP-PIVOT-001` — default list, перемикання list → resources → list і URL;
- `TC-GP-PIVOT-002` — порядок періодів, унікальність рядків, одиниці, точні суми та `—`;
- `TC-GP-PIVOT-003` — category multiselect: одна категорія, OR двох, видалення вибору, очищення;
- `TC-GP-PIVOT-004` — прямий `?view=resources`, reload і повернення до списку.

`GlobalPlansPage.waitForLoaded()` додатково очікує завершення асинхронного завантаження планів.
Статичний PageTab або CTA не вважається достатньою ознакою готовності сторінки.

## Стабільні UI-контракти

Автотести використовують доступні feature-specific selectors:

- `global-plans-view-toggle-list`;
- `global-plans-view-toggle-resources`;
- `global-plans-resources-category-filter`;
- `global-plans-resources-row-{resourceId}`.

Іконки, Tailwind-класи, порядковий номер рядка або координати не є тестовим контрактом.

## Рекомендоване додаткове frontend-покриття

На рівні component/unit tests із контрольованим payload доцільно перевірити:

- повністю порожню відповідь;
- помилку `GET /global-plans`;
- сумування повторних output-позицій одного ресурсу в одному періоді;
- fallback для невідомого `?view=...`;
- українське locale-сортування назв;
- sticky header/first column при великій кількості рядків і періодів.

Ці сценарії не повинні очищати всі плани на спільному DEV або залежати від випадкових даних середовища.
